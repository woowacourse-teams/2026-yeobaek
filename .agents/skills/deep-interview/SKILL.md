# Deep Interview

먼저 `../../../backend/docs/지침/피드백_루프_하네스.md`와
`../../../backend/docs/지침/deep-interview_활용.md`를 끝까지 읽고 그대로 실행한다.

저장소에서 확인할 수 있는 사실을 먼저 조사한다. 목표, 범위와 제외 범위, 제약, 완료 기준,
기존 맥락과 영향 범위 중 구현 결과를 가장 크게 바꿀 불확실성 하나만 골라 질문한다.

한 라운드에 질문 하나만 묻는다. 추천은 개발자가 명시적으로 요구한 경우에만 제시한다.
개발자의 선택 이유나 구조 설명을 대신 작성·요약·윤문하지 않는다.

구현에 영향을 주는 미분류 질문이 없어질 때까지 계획이나 구현으로 넘기지 않는다. 남은
질문은 `범위 제외`, `연기`, `정책 관문 대기`, `결정 관문 대기` 중 하나로 배정한다.
인터뷰 답변을 정식 승인으로 간주하지 않고, 공식 관문이 필요한 항목은 해당 절차로 넘긴다.

이 스킬은 요구사항 명확화만 수행한다. 종료 후 프로젝트 지침에 정의된 요구사항 전달물을
남기고 직접 구현하지 않는다.
