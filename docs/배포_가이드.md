# 배포 가이드

> M8 배포 구성 결정 (2026-08-06): EC2 1대 + 같은 인스턴스의 Docker MySQL ·
> GitHub Actions → Docker Hub → EC2 pull 방식 · `ddl-auto=update`(데모 한정) · nginx + Let's Encrypt HTTPS

## 구성 개요

```
GitHub (develop push, backend/** 변경)
  └─ Actions: gradle build(게이트) → 이미지 빌드 → Docker Hub 푸시 → EC2에 SSH
       └─ EC2: docker compose pull && up -d
            ├─ yeobaek-app   (Spring Boot, 127.0.0.1:8080)
            ├─ yeobaek-mysql (볼륨 mysql-data에 데이터 영속)
            └─ nginx (호스트 설치) ── HTTPS(443) → 127.0.0.1:8080
```

- 관련 파일: `backend/Dockerfile`, `backend/deploy/docker-compose.prod.yml`, `backend/src/main/resources/application-prod.properties`, `.github/workflows/backend-deploy.yml`

## 1. GitHub 시크릿 (저장소 Settings → Secrets and variables → Actions)

| 시크릿 | 값 |
|---|---|
| `DOCKERHUB_USERNAME` | Docker Hub 계정명 (이미지: `<계정>/yeobaek-backend`) |
| `DOCKERHUB_TOKEN` | Docker Hub Access Token (Read & Write) |
| `EC2_HOST` | EC2 퍼블릭 IP 또는 도메인 |
| `EC2_USER` | SSH 사용자 (예: `ubuntu`) |
| `EC2_SSH_KEY` | SSH 개인키(PEM) 전문 |

## 2. EC2 최초 세팅 (1회)

```bash
# Docker 설치 (Ubuntu 기준)
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER   # 재로그인 필요

# 배포 디렉터리
mkdir -p ~/yeobaek
# 로컬에서 compose 파일 복사
scp -i <키> backend/deploy/docker-compose.prod.yml <user>@<host>:~/yeobaek/docker-compose.yml
```

`~/yeobaek/.env` 작성 (compose가 읽는다. 값은 팀 비밀 채널로 공유):

```
DOCKERHUB_USERNAME=<계정>
DB_PASSWORD=<강한 비밀번호>
ADMIN_TOKEN=<강한 토큰>
```

최초 기동(이후는 CI가 수행):

```bash
cd ~/yeobaek && docker compose pull && docker compose up -d
curl http://127.0.0.1:8080/api/books -H 'X-Member-Id: 1'   # 400(MEMBER_NOT_FOUND)이면 정상 기동
```

## 3. nginx + Let's Encrypt (호스트 설치, 1회)

도메인의 A 레코드를 EC2 퍼블릭 IP로 연결해 둔 상태에서:

```bash
sudo apt update && sudo apt install -y nginx certbot python3-certbot-nginx
sudo tee /etc/nginx/sites-available/yeobaek <<'EOF'
server {
    listen 80;
    server_name <도메인>;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
EOF
sudo ln -s /etc/nginx/sites-available/yeobaek /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx

# HTTPS 발급 (443 서버 블록·리다이렉트를 certbot이 자동 구성, 갱신 타이머 자동 등록)
sudo certbot --nginx -d <도메인>
```

## 4. 배포 이후

- **호스트 공유**: 발급된 `https://<도메인>`을 안드로이드 팀과 공유하고 `API.md` 0장의 Base path 항목을 갱신한다.
- **실제 책 투입**: `https://<도메인>/admin` 에서 [인제스트_가이드.md](인제스트_가이드.md) 절차로 업로드한다.
- **수동 배포(폴백)**: CI가 죽었을 때 — 로컬에서 `./gradlew bootJar && docker build -t <계정>/yeobaek-backend backend && docker push ...` 후 EC2에서 `docker compose pull && up -d`.
- **로그 확인**: `docker logs -f yeobaek-app`

## 주의

- `ddl-auto=update`는 데모 한정 결정이다. 컬럼 삭제·타입 변경은 반영되지 않으며, 데이터 안전성이 중요해지는 시점에 `none` + 수동 DDL로 전환을 재논의한다.
- MySQL 데이터는 도커 볼륨 `mysql-data`에 있다. `docker compose down -v`는 **데이터를 삭제**하므로 금지.
- 개발용 시드(`DevDataSeeder`)는 `local` 프로파일 한정이라 운영에 투입되지 않는다.
