# 로컬 백엔드 테스트 환경 구성 방법

이 문서는 백엔드 애플리케이션 실행에 익숙하지 않은 Android 개발자를 위한 안내서입니다.

아래 절차를 따르면 **JDK나 MySQL을 따로 설치하지 않고**, Docker만으로 백엔드 서버와 DB를 함께 실행할 수 있습니다. Android Studio, 에뮬레이터, Android 앱의 API 주소 설정 등 **Android 개발 환경 구성은 이 문서의 범위에 포함하지 않습니다.**

## 준비물

- 이 프로젝트를 내려받은 로컬 저장소
- 실행 중인 Docker Desktop 또는 Docker Engine
- macOS/Linux에서는 `curl` 명령도 필요합니다.

저장소의 최상위 디렉터리 `2026-yeobaek`에서 터미널을 열고 시작합니다.

Docker가 준비됐는지 다음 명령으로 확인합니다.

```text
docker info
docker compose version
```

두 명령이 모두 오류 없이 끝나면 준비가 된 것입니다. Docker 엔진 연결 오류가 나오면 Docker Desktop을 실행한 뒤 다시 시도합니다.

## 최초 한 번만 설정하기

먼저 백엔드 디렉터리로 이동합니다.

```text
cd backend
```

Docker Hub에 미리 빌드된 `develop` 백엔드 이미지의 위치를 `.env.local` 파일에 설정해야 합니다. 이 작업은 PC마다 최초 한 번만 하면 됩니다.

Windows PowerShell에서는 다음 명령을 실행합니다.

```powershell
Copy-Item .env.local.example .env.local
```

macOS/Linux에서는 다음 명령을 실행합니다.

```bash
cp .env.local.example .env.local
```

생성된 `.env.local` 파일을 열면 다음 내용이 있습니다.

```dotenv
BACKEND_IMAGE=YOUR_DOCKERHUB_USERNAME/yeobaek-backend:develop
APP_BIND_ADDRESS=127.0.0.1
```

`YOUR_DOCKERHUB_USERNAME`만 팀에서 사용하는 실제 Docker Hub 계정명으로 바꿉니다. 계정명을 모르면 백엔드 개발자에게 확인합니다. 나머지는 수정하지 않습니다.

예를 들어 팀 계정명이 `team-name`이라면 다음과 같습니다.

```dotenv
BACKEND_IMAGE=team-name/yeobaek-backend:develop
APP_BIND_ADDRESS=127.0.0.1
```

`.env.local`은 개인 PC에서만 사용하는 설정이며 Git에 올라가지 않습니다.

## 서버와 DB 시작하기

터미널의 현재 위치가 `2026-yeobaek/backend`인지 확인한 뒤, 사용하는 운영체제에 맞는 명령 하나를 실행합니다.

Windows PowerShell:

```powershell
.\local-env.ps1 up
```

macOS/Linux:

```bash
sh ./local-env.sh up
```

스크립트가 다음 작업을 자동으로 처리합니다.

1. Docker Hub에서 최신 `develop` 백엔드 이미지를 내려받습니다.
2. MySQL DB를 실행하고 준비될 때까지 기다립니다.
3. 백엔드 서버를 실행하고 실제 HTTP 응답이 올 때까지 기다립니다.

처음 실행할 때는 이미지를 내려받느라 시간이 걸릴 수 있습니다. 다음 메시지가 나오면 테스트 환경이 준비된 것입니다.

```text
백엔드 준비 완료: http://localhost:8080/v3/api-docs
```

PC 브라우저에서 아래 주소를 열어 정상 실행 여부를 다시 확인할 수 있습니다.

- API 문서 화면: <http://localhost:8080/docs>
- OpenAPI JSON: <http://localhost:8080/v3/api-docs>

## Android에서 접속하기

### Android Studio 에뮬레이터

에뮬레이터 안에서 `localhost`는 개발 PC가 아니라 **에뮬레이터 자신**을 가리킵니다. 따라서 Android 앱에서 사용할 백엔드 주소는 다음과 같습니다.

```text
http://10.0.2.2:8080
```

PC 브라우저에서는 계속 `http://localhost:8080`을 사용합니다.

### 실제 Android 기기

실제 기기에서 접속할 때는 PC와 기기를 같은 신뢰할 수 있는 Wi-Fi에 연결해야 합니다. 그다음 `.env.local`을 다음처럼 변경합니다.

```dotenv
APP_BIND_ADDRESS=0.0.0.0
```

변경 사항을 적용하려면 실행 중인 환경을 종료한 뒤 다시 시작합니다.

Windows PowerShell:

```powershell
.\local-env.ps1 down
.\local-env.ps1 up
```

macOS/Linux:

```bash
sh ./local-env.sh down
sh ./local-env.sh up
```

Android 앱에서는 `localhost` 대신 개발 PC의 같은 Wi-Fi상 IP 주소를 사용합니다.

```text
http://개발_PC의_IP_주소:8080
```

예를 들어 PC의 IP 주소가 `192.168.0.10`이면 `http://192.168.0.10:8080`입니다. PC의 LAN IP 주소는 다음 명령으로 확인할 수 있습니다.

- Windows: `ipconfig`
- macOS: `ipconfig getifaddr en0` (Wi-Fi 인터페이스가 다르면 시스템 네트워크 설정에서 확인)
- Linux: `hostname -I`

접속이 막히면 신뢰할 수 있는 개인 네트워크에서만 운영체제 방화벽의 인바운드 TCP `8080` 포트를 임시로 허용합니다. Docker 전체나 모든 네트워크 프로필을 허용하지 마세요.

`0.0.0.0` 설정은 개발용 서버를 같은 네트워크에 공개합니다. 신뢰할 수 있는 네트워크에서만 사용하고, 실제 기기 테스트가 끝나면 `APP_BIND_ADDRESS=127.0.0.1`로 되돌린 뒤 환경을 다시 시작합니다.

## 상태와 로그 확인하기

서버와 DB의 현재 상태를 확인하려면 다음 명령을 사용합니다.

Windows PowerShell:

```powershell
.\local-env.ps1 status
```

macOS/Linux:

```bash
sh ./local-env.sh status
```

서버가 준비되지 않거나 요청이 실패할 때는 로그를 확인합니다.

Windows PowerShell:

```powershell
.\local-env.ps1 logs
```

macOS/Linux:

```bash
sh ./local-env.sh logs
```

로그 화면에서 빠져나오려면 `Ctrl+C`를 누릅니다. 이 동작은 로그 보기만 끝내며 서버와 DB는 계속 실행됩니다.

## 서버와 DB 종료하기

테스트가 끝나면 반드시 아래 명령으로 서버와 DB를 함께 종료합니다.

Windows PowerShell:

```powershell
.\local-env.ps1 down
```

macOS/Linux:

```bash
sh ./local-env.sh down
```

터미널 창을 닫는 것만으로는 백그라운드의 Docker 컨테이너가 종료되지 않을 수 있으므로 `down` 명령을 사용합니다.

`down`은 테스트용 DB 데이터도 삭제합니다. 또한 백엔드는 로컬 실행 때 스키마를 새로 만들도록 설정되어 있으므로, 환경을 다시 시작하면 깨끗한 DB에서 테스트를 시작합니다. 유지해야 하는 테스트 데이터를 이 DB에 저장하지 마세요.

## 자주 발생하는 문제

### Docker를 찾을 수 없거나 Docker 엔진에 연결할 수 없음

Docker Desktop이 설치되어 있고 실행 중인지 확인합니다. Docker Desktop을 막 실행했다면 엔진 준비가 끝난 뒤 다시 `up` 명령을 실행합니다.

### `BACKEND_IMAGE가 설정되지 않았습니다`

현재 위치가 `backend`인지, `backend/.env.local` 파일이 존재하는지 확인합니다. 파일 안의 `YOUR_DOCKERHUB_USERNAME`이 실제 팀 Docker Hub 계정명으로 바뀌어 있어야 합니다.

### 이미지 pull 권한 오류

Docker Hub 계정명과 이미지 이름의 오타를 확인합니다. 이미지가 비공개라면 해당 이미지를 읽을 권한이 있는 계정으로 `docker login`한 뒤 다시 실행합니다. 권한을 모르면 백엔드 개발자에게 확인합니다.

### `8080` 포트를 이미 사용 중이라는 오류

PC에서 실행 중인 다른 백엔드 서버나 프로그램이 8080 포트를 사용하고 있습니다. 해당 프로그램을 종료한 뒤 다시 `up` 명령을 실행합니다.

### 120초 안에 백엔드가 준비되지 않음

스크립트가 화면에 출력한 app 로그를 먼저 확인합니다. 이후 `logs` 명령으로 전체 로그를 다시 볼 수 있습니다. Docker Desktop의 메모리가 부족하거나 이미지 설정이 잘못된 경우가 아닌지 확인합니다.

원인을 확인한 뒤에는 `down` 명령으로 실패한 서버와 DB를 정리하고 다시 `up`을 실행합니다. `up`이 실패했다고 해서 생성된 컨테이너가 항상 자동으로 제거되는 것은 아닙니다.

### PC 브라우저에서는 되지만 Android에서 접속할 수 없음

- 에뮬레이터에서는 `localhost`가 아니라 `10.0.2.2`를 사용했는지 확인합니다.
- 실제 기기에서는 PC와 같은 Wi-Fi인지, `APP_BIND_ADDRESS=0.0.0.0`인지 확인합니다.
- 실제 기기에서 PC의 올바른 LAN IP 주소를 사용했는지 확인합니다.
- PC 방화벽이 통신을 막고 있지 않은지 확인합니다.
- Android 앱이 개발용 HTTP 통신을 허용하도록 설정되어 있는지 Android 프로젝트 설정을 확인합니다. 이 설정 방법은 이 문서의 범위에 포함하지 않습니다.

문제가 해결되지 않으면 `status`와 `logs` 명령의 출력 내용을 백엔드 개발자에게 전달합니다.
