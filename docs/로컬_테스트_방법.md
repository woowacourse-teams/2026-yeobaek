# 로컬 백엔드 테스트 환경 구성 방법

## 준비물

- Docker가 설치되어 있어야 합니다.
- Windows에서는 PowerShell 7.2 이상이 필요합니다. `pwsh --version`으로 버전을 확인하고,
  명령을 찾을 수 없으면 [Microsoft의 PowerShell 7 설치 안내](https://learn.microsoft.com/powershell/scripting/install/install-powershell-on-windows)를 따라 설치합니다.

## 서버와 DB 시작하기

터미널에서 `2026-yeobaek/backend`로 이동한 뒤, 사용하는 운영체제에 맞는 명령 하나를 실행합니다.

Windows (PowerShell 7.2 이상):

```powershell
pwsh -NoProfile -File .\local-env.ps1 up
```

macOS/Linux:

```bash
sh ./local-env.sh up
```

처음 실행할 때는 이미지를 내려받느라 시간이 걸릴 수 있습니다. 다음 메시지가 나오면 테스트 환경이 준비된 것입니다.

```text
백엔드 준비 완료: http://localhost:8080/v3/api-docs
```

PC 브라우저에서 아래 주소를 열어 정상 실행 여부를 다시 확인할 수 있습니다.

- API 명세서: <http://localhost:8080/swagger-ui/index.html>
- OpenAPI JSON: <http://localhost:8080/v3/api-docs>

## 초기 테스트 데이터

서버를 시작하면 다음 데이터가 자동으로 생성됩니다.

- 회원: `1` 민서, `2` 지수
- 도서: `1` 운수 좋은 날
- 모임: `1` 교환독서 1기 (참여 코드 `A3F9KQ`)
- 진도: 민서 `10/30`, 지수 `20/30`
- 댓글: 본문 ID `2`에 민서와 지수의 댓글

회원 인증이 필요한 API에는 사용할 회원 ID를 `X-Member-Id` 헤더로 전달합니다.

## Android에서 접속하기

### Android Studio 에뮬레이터

에뮬레이터 안에서 `localhost`는 개발 PC가 아니라 **에뮬레이터 자신**을 가리킵니다. 따라서 Android 앱에서 사용할 백엔드 주소는 다음과 같습니다.

```text
http://10.0.2.2:8080
```

PC 브라우저에서는 계속 `http://localhost:8080`을 사용합니다.

### 실제 Android 기기

실제 기기에서 접속할 때는 PC와 기기를 같은 신뢰할 수 있는 Wi-Fi에 연결해야 합니다. 실행 중인 환경을 종료한 뒤 다음 명령으로 다시 시작합니다.

Windows (PowerShell 7.2 이상):

```powershell
pwsh -NoProfile -File .\local-env.ps1 down
$env:APP_BIND_ADDRESS='0.0.0.0'
pwsh -NoProfile -File .\local-env.ps1 up
```

macOS/Linux:

```bash
sh ./local-env.sh down
APP_BIND_ADDRESS=0.0.0.0 sh ./local-env.sh up
```

Android 앱에서는 `localhost` 대신 개발 PC의 같은 Wi-Fi상 IP 주소를 사용합니다.

```text
http://개발_PC의_IP_주소:8080
```

예를 들어 PC의 IP 주소가 `192.168.0.10`이면 `http://192.168.0.10:8080`입니다. PC의 LAN IP 주소는 다음 명령으로 확인할 수 있습니다.

- Windows: `ipconfig`
- macOS: `ipconfig getifaddr en0` (Wi-Fi 인터페이스가 다르면 시스템 네트워크 설정에서 확인)
- Linux: `hostname -I`

접속이 막히면 신뢰할 수 있는 개인 네트워크에서만 운영체제 방화벽의 인바운드 TCP `8080` 포트를 임시로 허용합니다. Docker 전체나 모든 네트워크 프로필을 허용하지 마세요.

`0.0.0.0` 설정은 개발용 서버를 같은 네트워크에 공개합니다. 신뢰할 수 있는 네트워크에서만 사용하세요. 테스트가 끝나면 `down`으로 서버를 종료합니다. PowerShell에서는 이어서 `Remove-Item Env:APP_BIND_ADDRESS`를 실행해 설정도 제거합니다.

## 상태와 로그 확인하기

서버와 DB의 현재 상태를 확인하려면 다음 명령을 사용합니다.

Windows (PowerShell 7.2 이상):

```powershell
pwsh -NoProfile -File .\local-env.ps1 status
```

macOS/Linux:

```bash
sh ./local-env.sh status
```

서버가 준비되지 않거나 요청이 실패할 때는 로그를 확인합니다.

Windows (PowerShell 7.2 이상):

```powershell
pwsh -NoProfile -File .\local-env.ps1 logs
```

macOS/Linux:

```bash
sh ./local-env.sh logs
```

로그 화면에서 빠져나오려면 `Ctrl+C`를 누릅니다. 이 동작은 로그 보기만 끝내며 서버와 DB는 계속 실행됩니다.

## 서버와 DB 종료하기

테스트가 끝나면 반드시 아래 명령으로 서버와 DB를 함께 종료합니다.

Windows (PowerShell 7.2 이상):

```powershell
pwsh -NoProfile -File .\local-env.ps1 down
```

macOS/Linux:

```bash
sh ./local-env.sh down
```

터미널 창을 닫는 것만으로는 백그라운드의 Docker 컨테이너가 종료되지 않을 수 있으므로 `down` 명령을 사용합니다.

`down`은 테스트용 DB 데이터도 삭제합니다. 또한 백엔드는 로컬 실행 때 스키마를 새로 만들도록 설정되어 있으므로, 환경을 다시 시작하면 깨끗한 DB에서 테스트를 시작합니다. 유지해야 하는 테스트 데이터를 이 DB에 저장하지 마세요.

## 자주 발생하는 문제

### Windows에서 `NativeCommandError`와 `No blkio` 경고가 발생함

Windows에 기본 포함된 Windows PowerShell 5.1(`powershell.exe`)은 Docker가 표준 오류 스트림에
출력한 경고를 `NativeCommandError`로 처리할 수 있습니다. `No blkio ... support` 경고와 함께
`local-env.ps1`이 중단되면 Docker 엔진 연결 실패로 단정하지 말고, 준비물에 안내된 PowerShell 7.2 이상을
설치한 뒤 `pwsh -NoProfile -File .\local-env.ps1 <command>` 형식으로 다시 실행합니다.

PowerShell 7.2 이상은 `pwsh`, Windows PowerShell 5.1은 `powershell.exe`로 실행되며 서로 별개의
프로그램입니다. 이 문서의 Windows 명령은 모두 PowerShell 7.2 이상을 기준으로 합니다.

### Android 앱에서 HTTP 요청이 실패함

현재 Android 앱은 운영 HTTPS 주소를 사용하며, HTTP 통신도 허용하지 않은 상태입니다. 로컬 서버를 테스트하려면 디버그 빌드의 API 주소를 에뮬레이터는 `http://10.0.2.2:8080`, 실제 기기는 `http://개발_PC의_IP_주소:8080`으로 바꾸고 해당 주소의 HTTP 통신을 허용해야 합니다. 그렇지 않으면 운영 서버로 요청되거나 `Cleartext HTTP traffic ... not permitted` 오류가 발생할 수 있습니다.

HTTP 통신은 암호화되지 않으므로 로컬 테스트에서만 사용하고 실제 계정이나 민감한 데이터를 보내지 마세요. 운영 빌드에서 HTTP를 전체 허용하면 안 됩니다.

### `8080` 포트를 이미 사용 중이라는 오류

PC에서 실행 중인 다른 백엔드 서버나 프로그램이 8080 포트를 사용하고 있습니다. 해당 프로그램을 종료한 뒤 다시 `up` 명령을 실행합니다.

### 120초 안에 백엔드가 준비되지 않음

스크립트가 화면에 출력한 app 로그를 먼저 확인합니다. 이후 `logs` 명령으로 전체 로그를 다시 볼 수 있습니다. Docker Desktop의 메모리가 부족하거나 이미지 설정이 잘못된 경우가 아닌지 확인합니다.

원인을 확인한 뒤에는 `down` 명령으로 실패한 서버와 DB를 정리하고 다시 `up`을 실행합니다. `up`이 실패했다고 해서 생성된 컨테이너가 항상 자동으로 제거되는 것은 아닙니다.

### PC 브라우저에서는 되지만 Android에서 접속할 수 없음

- 에뮬레이터에서는 `localhost`가 아니라 `10.0.2.2`를 사용했는지 확인합니다.
- 실제 기기에서는 PC와 같은 Wi-Fi인지, `APP_BIND_ADDRESS=0.0.0.0`인지 확인합니다.
- 실제 기기에서 PC의 올바른 LAN IP 주소를 사용했는지 확인합니다.
- PC 방화벽이 통신을 막고 있지 않은지 확인합니다.
- Android 앱이 개발용 HTTP 통신을 허용하도록 설정되어 있는지 Android 프로젝트 설정을 확인합니다. 이 설정 방법은 이 문서의 범위에 포함하지 않습니다.

문제가 해결되지 않으면 `status`와 `logs` 명령의 출력 내용을 백엔드 개발자에게 전달합니다.
