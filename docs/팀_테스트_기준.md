# 여백 팀 테스트 기준

- API 명세와 핵심 사용자 흐름의 대표 성공·실패를 검증한다. 저장이 계약에 포함되면 저장 결과도 확인한다.
- 검증할 수 있는 가장 좁은 수준에서 시작한다. 단위 테스트를 기본으로 하고, 구성요소 연결에서 생기는 문제는 슬라이스 또는 통합 테스트로 확인한다.
- 동작에 영향 없는 내부 구현·장식용 색상·미세 여백, 라이브러리 자체 동작, 이미 검증한 동일 계약은 검증하지 않는다.
- 실제 저장소가 결과를 좌우하면 격리된 테스트 DB를 사용한다. 외부 API는 테스트 대역으로 바꿔 성공·실패를 재현한다.
- 앱과 서버를 함께 띄우는 E2E는 새로 작성하지 않는다. 기능 변경이 잦아 두 환경을 함께 유지하는 비용이 크기 때문이다.
