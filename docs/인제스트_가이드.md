# 인제스트 가이드 — 로컬 LLM으로 규격 JSON 만들기

> 기반 문서: [`PRD.md`](PRD.md) 3.3 · 규격 상세: [`API.md`](API.md) 6장 (2026-08-06 M7 확정)
> 흐름: 퍼블릭 도메인 원문 확보 → 로컬 LLM으로 규격 JSON 생성 → 관리자 페이지(`/admin`)에서 업로드

## 1. 콘텐츠 선정 규칙

- **퍼블릭 도메인(저작권 만료) 저작물만** 사용한다 (PRD 3.3). 한국 문학은 공유마당(gongu.copyright.or.kr), 위키문헌 등에서 원문을 얻는다.
- 이미지가 포함된 저작물은 텍스트만 인제스트한다 (이미지는 데모 범위 제외 — PRD 6장).

## 2. 규격 JSON (요약)

```json
{
  "title": "운수 좋은 날",
  "publisher": "자체 제작",
  "publishedYear": 1924,
  "authors": [{ "name": "현진건", "isni": "0000 0001 2345 964X" }],
  "chapters": [
    { "title": "1장", "passages": [{ "content": "첫 문단..." }, { "content": "둘째 문단..." }] }
  ]
}
```

- 본문 순서는 **배열 등장 순서** 그대로 서버가 1..N을 부여한다. JSON에 순서 번호를 넣지 않는다.
- 제목·출판사·작가명·목차 제목은 각 1~100자. 본문 `content`는 필수(공백 불가).
- 목차 0개, 본문 0개인 목차는 거부된다. 목차가 없는 원문은 임시로 "본문" 같은 단일 목차를 만들지 말고 팀에 논의를 올린다 (PRD 6장 미해결 항목).

## 3. 작가 기입 규칙

1. **ISNI를 먼저 찾는다** — [isni.org](https://isni.org) 검색. 있으면 `{ "name", "isni" }`로 기입한다. 같은 ISNI가 서버에 이미 있으면 자동으로 재사용된다 (이름이 다르면 거부되니 등록된 이름 그대로 쓴다).
2. **ISNI가 없으면 관리자 페이지의 "작가 목록 불러오기"로 기존 등록 여부를 확인한다.**
   - 같은 작가가 이미 있다 → `{ "authorId": 12 }`로 참조한다.
   - 없다 → `{ "name": "..." }`만 기입한다 (신규 생성).
3. **작자를 알 수 없는 저작물은 이름을 `"작자 미상"`으로 기입한다** (2026-08-06 결정).

## 4. LLM 프롬프트 템플릿

로컬 LLM에 원문(또는 장 단위 분할본)과 함께 아래 지시를 준다.

```
다음 원문을 아래 JSON 규격으로 변환하라.

규칙:
1. 문단 분할: 원문의 문단(빈 줄 또는 들여쓰기로 구분되는 단위)을 그대로 하나의
   passages 원소로 만든다. 문단을 임의로 합치거나 쪼개지 않는다.
   물리적 페이지 개념은 없다.
2. 원문 텍스트를 요약·수정·현대어 교정하지 않고 그대로 담는다.
   명백한 OCR 오류(글자 깨짐)만 원문 표기에 맞게 복원한다.
3. 목차: 원문의 장 구분(1장, 二, 상편 등)을 chapters 원소로 만들고 제목을 그대로 쓴다.
   장 구분이 없는 단편은 변환을 멈추고 그 사실을 보고한다.
4. 등장 순서를 유지한다. 순서 번호는 출력하지 않는다.
5. 이미지·삽화는 제외한다.
6. 출력은 JSON 하나만. 설명 문장을 붙이지 않는다.

JSON 규격:
{ "title": ..., "publisher": ..., "publishedYear": ...,
  "authors": [{ "name": ..., "isni": ... }],
  "chapters": [{ "title": ..., "passages": [{ "content": ... }] }] }
```

- **긴 책은 장 단위로 나눠 생성한다.** LLM 컨텍스트를 넘기면 문단이 유실돼도 알아채기 어렵다. 장별로 `passages` 배열을 생성한 뒤 사람이 chapters 배열로 병합한다.
- 생성 후 **문단 수를 원문과 대조**한다. 순서·개수 검증은 서버가 못 해주는 부분이다 (배열 순서가 곧 정답으로 취급되므로).

## 5. 업로드와 에러

관리자 페이지(`/admin`)에 토큰을 입력하고 JSON을 붙여 넣어 업로드한다. 업로드는 단일 트랜잭션이라 실패 시 아무것도 저장되지 않는다 — 고치고 다시 올리면 된다.

| 에러 코드 | 원인 | 조치 |
|---|---|---|
| `UNAUTHORIZED` (401) | 토큰 누락·불일치 | 토큰 확인 |
| `INVALID_REQUEST` | 필드 검증 실패 (길이, 빈 구조, 공백 본문, ISNI 형식 등) | message 참고해 JSON 수정 |
| `AUTHOR_NOT_FOUND` | 없는 `authorId` 참조 | 작가 목록 다시 확인 |
| `AUTHOR_NAME_MISMATCH` | ISNI는 같은데 이름이 기존 등록과 다름 | 등록된 이름으로 통일 |
| `DUPLICATE_AUTHOR` | 한 업로드에 같은 작가 중복 기재 | authors 배열 정리 |
| `DUPLICATE_BOOK` | 제목·출판사·출판연도·작가 구성이 동일한 도서 존재 | 이미 올라간 책인지 확인 |
