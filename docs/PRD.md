# 여백 (Yeobaek) — 소셜 독서 서비스 PRD

> "책 한 권의 여백을 친구와 나눠보세요"

## 1. 개요

여백은 소규모 그룹이 같은 책을 각자의 속도로 읽으며, 문단 단위로 감상을 나누는 모바일 독서 모임 서비스다. 참여 코드로 가볍게 모임에 합류하고, 앱 안에서 책을 직접 읽으며(e-reader), 마음에 남은 문단에 댓글을 남겨 모임원과 교환한다.

- 프로토타입: https://gyohwan-reading-club.dryzero0.chatgpt.site/
- 대상 플랫폼: Android (Galaxy S25 기준 반응형)

## 2. 핵심 사용자 경험

1. 앱 첫 실행 시 닉네임을 입력해 회원이 된다 (별도 로그인 없음).
2. 참여 코드를 입력해 모임에 들어가거나, 새 모임을 만들면서 읽을 책을 고른다.
3. 앱 안에서 책을 문단 단위로 읽는다. 읽던 위치는 모임별로 저장되어 이어 읽을 수 있다.
4. 인상 깊은 문단에 댓글을 남기고, 같은 문단에 모임원이 남긴 댓글을 본다.
5. 홈에서 내가 마지막으로 읽던 책과 위치를 확인하고 바로 이어 읽는다.

## 3. 기능 요구사항

### 3.1 회원

- 첫 실행 시 닉네임 입력만으로 회원이 생성된다. 인증(로그인)은 없다.
- 서버가 발급한 회원 ID를 클라이언트가 기기 로컬에 저장하여 재방문을 식별한다.
- 닉네임은 표시용이며 unique 제약이 없다 (중복 허용).
- **트레이드오프(감수)**: 기기 변경·앱 삭제 시 회원 데이터(진도, 댓글)는 유실된다.

### 3.2 모임

- 회원은 모임을 생성할 수 있으며, 생성 시 읽을 책 한 권을 선택한다.
- **모임 1개 = 책 1권, 영구 고정.** 책은 교체할 수 없다. 새 책을 읽으려면 새 모임을 만든다.
- 모임마다 unique한 참여 코드가 발급되고, 코드를 입력한 회원은 모임에 참여한다.
- 하나의 회원은 여러 모임에 참여할 수 있고, 하나의 모임은 여러 회원으로 구성된다.
- 역할(모임장) 개념은 없다. 전원 동등하다.
- **MVP 제외**: 모임 삭제, 이름 변경, 코드 재발급, 강퇴, 탈퇴. 참여하면 영구 멤버다.

### 3.3 도서 · 콘텐츠

- 앱이 책 본문을 직접 호스팅하는 e-reader 방식이다.
- **콘텐츠는 퍼블릭 도메인(저작권 만료) 저작물만** 사용한다.
- 책의 구조: 도서 → 목차(평면, 계층 없음) → 본문.
- **본문의 단위는 문단**이다. 텍스트 또는 이미지를 담는다. 물리적 페이지 개념은 없다.
- 본문의 순서는 책 전체 기준 1..N으로 빈틈없이(dense) 매겨진다. 이는 인제스트 파이프라인이 보장하는 계약이다.
- 도서의 본문 개수는 인제스트 시 자동 산출하여 저장한다 (수기 입력 금지). 진도율 연산에 사용한다.
- 작가와 도서는 다대다 관계다 (공저 지원).
- **인제스트 방식**: 로컬 LLM으로 원문을 정해진 규격(JSON)으로 변환하고, 관리자 페이지에서 서버에 업로드한다. 서버는 업로드 시 순서 1..N dense와 본문 개수를 검증·산출한다. 규격 포맷과 페이지 상세는 구현 시 확정한다.

### 3.4 읽기 · 진도

- 회원의 읽기 진도는 **모임 단위**로 저장된다. 같은 책이라도 모임이 다르면 진도는 별개다.
- 진도는 **최근 열람 본문** 포인터 하나로 관리한다. "최대 도달" 개념은 두지 않는다.
- 진도율 = 최근 열람 본문의 순서 ÷ 도서의 본문 개수.
- **트레이드오프(감수)**: 앞부분을 다시 읽으면 진도율이 후퇴한다.
- 회원은 본문을 자유롭게 이동하며 읽을 수 있다 (순차 강제 없음).
- 모임별로 마지막으로 읽은 시간을 기록하며, 이를 통해 "내가 마지막에 읽던 책과 위치"를 전 모임에 걸쳐 조회한다.

### 3.5 댓글

- 회원은 본문(문단) 단위로 댓글을 남긴다.
- 댓글은 작성된 모임 내부에서만 공유된다. 같은 책을 읽는 다른 모임에서는 보이지 않는다.
- 댓글은 해당 본문 화면에서만 노출된다. 별도의 댓글 피드는 없다.
- 스포일러 필터는 없다. 앞선 본문을 열어 댓글을 보는 것은 본인의 선택이다.
- 평면 구조다 (대댓글 없음).
- 본인 댓글은 수정·삭제할 수 있다. 삭제는 하드 삭제다.

## 4. 데이터 모델

| 테이블 | 컬럼 |
|---|---|
| 회원 | PK, 닉네임 |
| 모임 | PK, 모임 이름, 도서 FK(불변), 참여 코드(unique) |
| 모임-회원 | PK, 회원 FK, 모임 FK, 최근 열람 본문 FK, 마지막으로 읽은 시간 |
| 도서 | PK, 제목, 출판사, 출판연도, 본문 개수(자동 산출) |
| 작가 | PK, 이름 |
| 작가-도서 매핑 | PK, 작가 FK, 도서 FK |
| 목차 | PK, 도서 FK, 제목, 순서 |
| 본문 | PK, 목차 FK, 순서(책 전체 기준 1..N dense), 내용(nullable), 이미지(nullable) |
| 댓글 | PK, 모임-회원 FK, 본문 FK, 내용, 작성일, 수정일 |

초안 대비 변경: `본문.페이지 번호` 삭제, `모임-회원.최대 도달 본문 FK` 삭제, `모임.참여 코드` 추가, `댓글.수정일` 추가.

## 5. MVP 범위 제외 (명시적 결정)

| 제외 항목 | 사유 |
|---|---|
| 인증(소셜 로그인 등) | 기기 로컬 회원 ID 저장으로 대체. 데이터 유실 감수 |
| 모임장/권한, 모임 관리 기능 | 전원 동등. 관리 기능 없음 |
| 모임 탈퇴 | 댓글 수명주기(FK 고아화) 문제 회피 |
| 대댓글 | 문단 단위로 이미 대화 맥락이 좁아 평면으로 충분 |
| 스포일러 필터 | 댓글 노출 경로가 본문 화면뿐이므로 불필요 |
| 최대 도달 진도 | 최근 열람 단일 포인터로 단순화 |
| 상용 도서 | 저작권. 퍼블릭 도메인만 |

## 6. 미해결 항목 (후속 논의)

- 인제스트 규격(JSON) 포맷 상세: 문단 분할 규칙, 목차 추출, 이미지 처리 (방식 자체는 3.3에서 확정 — LLM 변환 + 관리자 페이지 업로드)
- `본문.내용`·`이미지` 동시 null 허용 여부 (제약 검토)
- 프로토타입의 "둘러보기" 플로우 UX 정의 (스키마 영향 없음)
- 모임 인원 제한 여부
- 자체 제작 콘텐츠 도입 시 `출판사` 필드 처리
