# 컨트롤러 테스트 하네스

JSON `@RestController`의 웹 계층 계약을 작성·검토할 때 적용한다.
계약은 [API 명세](../../../../docs/API.md)를 기준으로 한다. 런타임 OpenAPI와 다르면
계약 변경 여부부터 확인한다. 기존 테스트의 일괄 개정은 별도 작업이다.

## 환경

- `@WebMvcTest(대상.class)`와 `MockMvc`를 사용하고 공통
  [`ControllerTest`](../../../src/test/java/yeobaek/backend/support/ControllerTest.java)를 상속한다.
- 서비스 협력 객체는 `@MockitoBean`으로 대체한다.
- 인증이 필요한 정상 요청은 `givenValidMember(memberId)`로 선행 조건을 만든다.
  컨트롤러 메서드를 직접 호출하지 않는다.

## 엔드포인트별 검증

| 시나리오 | 검증 |
|---|---|
| 정상 요청 | 메서드·경로, 바인딩된 값, 서비스 1회 호출과 정확한 인자, 응답 계약 |
| 엔드포인트 고유 웹 제약 위반 | 거부 원인과 서비스 미호출 |
| 컨트롤러가 선택하는 응답 분기 | 분기별 상태·본문·서비스 호출 |
| 선택 파라미터 등 바인딩 분기 | 각 요청이 서비스에 전달하는 값 |

- `verify(service, times(1))`로 호출 횟수와 실제 인자를 확인한다. VO·DTO는 동등성 비교나
  `ArgumentCaptor`를 사용한다. `any()` 스텁만으로 인자 검증을 대신하지 않는다.
- 바인딩·역직렬화·웹 검증에서 거부된 요청은 `verifyNoInteractions(service)`로 확인한다.
- Bean Validation은 실제 제약과 필요한 `@Valid`가 선언된 경우만 검증한다.
  선언되지 않은 제약을 서비스 예외 스텁으로 대신하지 않는다.
- 필수 숫자 입력은 누락을 구분할 수 있는 래퍼 타입으로 받고, 조건부 필수성은 DTO에서 검증한다.
- `verifyNoMoreInteractions()`는 추가 호출이 없어야 하는 것 자체가 계약일 때만 사용한다.

## 응답 계약

- 상태, JSON이면 호환되는 `Content-Type`, 계약 헤더와 모든 응답 필드를 검증한다.
- 성공 JSON은 `jsonPath`로 필드별 검증한다. 전체 문자열과 필드 순서에 결합하지 않는다.
- 중첩 객체·컬렉션의 구조, 크기와 원소 필드를 검증한다. nullable 필드는 JSON null,
  빈 컬렉션은 빈 배열을 명시적으로 검증한다.
- `204 No Content`는 상태와 빈 본문을 검증하며 JSON `Content-Type`을 요구하지 않는다.

## 공통 책임과의 경계

- 컨트롤러 클래스마다 대표 서비스 예외 하나에 대해 정확한 서비스 호출과
  `getResolvedException()`의 동일 인스턴스 전파를 검증한다. 예외별·메서드별로 반복하지 않는다.
- 공통 오류의 상태·code·정확한 message 전달은
  [`GlobalExceptionHandlerTest`](../../../src/test/java/yeobaek/backend/support/GlobalExceptionHandlerTest.java)에서 검증한다.
- 회원 헤더 인증과 인자 해석은 각각 `MemberAuthInterceptorTest`, `AuthMemberArgumentResolverTest`에서 검증한다.
- 비즈니스 유효성과 예외 메시지의 의미는 서비스·도메인 테스트에서 검증한다.
- Spring 자체의 잘못된 경로·메서드 거부와 공통 컴포넌트 실패를 엔드포인트마다 반복하지 않는다.
