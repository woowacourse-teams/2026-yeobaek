# 백엔드 PR 작성 하네스

PR 작성·제출·갱신을 맡은 작업에 적용한다. 로컬 수정이나 문서 정리만 요청받은 작업을
자동으로 푸시·PR 제출까지 확대하지 않는다.

## 브랜치와 변경 범위

- 브랜치·base·병합 조건은 [Git Flow 지침](../../../../docs/Git_Flow_지침.md)을 따른다.
- 제출 전에 현재 브랜치, 최신 원격 base와의 관계, 최종 diff를 확인한다.
  일반 작업은 `develop`, `hotfix/*`는 `main`을 base로 삼는다.
- `hotfix/*`에 아직 main에 없는 develop 변경이 섞이지 않았는지 확인한다.
- 보호 브랜치에 직접 커밋·푸시하지 않는다. 기존 작업의 히스토리를 임의로 재작성하지 않는다.
- 사용자의 다른 변경을 섞지 않는다. 범위가 섞였거나 안전하게 분리할 수 없으면 알린다.
- [커밋 전 게이트](../검증/커밋_전_게이트.md)를 통과한 변경만 제출한다.

## 본문

[본문 템플릿](../../템플릿/백엔드_PR_본문.md)을 복사해 임시 파일에서 작성한다.

- 첫 문단에 해결한 문제와 변경된 동작을 쓴다. 필요한 구현 이유와 검증 결과를 이어 쓴다.
- 설명은 대화 없이 이해할 수 있게 쓴다. 선택지 기호는 실제 내용으로 바꾸고 문어체로 통일한다.
- 구현·테스트에서 확인한 사실과 개발자의 판단을 구분한다. 개발자가 말하지 않은 이유를
  개발자의 결정으로 표현하지 않는다.
- 대안·결정 출처는 리뷰어가 선택을 이해하는 데 필요할 때만 추가한다.
  날짜·승인 이력이나 `해당 없음` 항목을 채우기 위해 본문을 늘리지 않는다.
- 독립적으로 설명할 변경이 여러 개일 때만 구현 상세를 나눈다. 요약을 항목마다 반복하지 않는다.
- 템플릿 안내 주석·빈 항목을 제출 본문에서 제거하고 템플릿 원본은 덮어쓰지 않는다.

## 생성·갱신

GitHub CLI 또는 같은 기능의 인증된 API·연결 도구를 사용한다.

1. 현재 인증 사용자와 PR author를 직접 확인한다. 백엔드 개발자는 `alstj2384`,
   `Yeji-Kim-Erica`, `kjoon418`이다. 다른 계정이면 대신 제출자로 추정하지 않고 확인한다.
2. 제출할 작업 브랜치를 푸시하고, 그 head의 열린 PR을 조회한다.
3. PR이 없으면 base·head·제목·본문을 명시해 생성한다. 하나면 실제 author를 기준으로 갱신한다.
   둘 이상이면 대상을 확인한다.
4. author를 제외한 백엔드 개발자 두 명을 reviewer로 지정한다.
5. 제목은 Conventional Commits 형식으로 쓴다. 종류는 제목으로 표현하고 label은 추가하지 않는다.
   기존 PR의 label도 비운다.
6. 원격 head·base·본문·reviewer·label을 다시 조회해 의도한 값인지 확인하고 PR URL을 보고한다.

CLI를 사용하면 본문은 임시 파일에 실제 줄바꿈으로 저장해 `--body-file`로 전달한다.
인증·권한 오류나 푸시 실패는 그대로 보고하고, 실패를 성공으로 표현하지 않는다.

## 인라인 설명

본문과 diff만으로 파악하기 어려운 선택이 있을 때만 대표 변경 줄에 짧게 설명한다.
선택을 가른 문제·제약과 이유부터 쓰고, 실제 검토한 대안이 있으면 선택을 가른 차이만 비교한다.
관련 결정을 연결할 때는 실제 PR 본문 제목으로 이동하는 링크를 쓴다.
같은 내용을 여러 줄에 반복하거나 각 구현 항목에 코멘트를 의무적으로 만들지 않는다.

기존 자동 코멘트를 갱신할 때는 다음 규칙을 지킨다.

- `<!-- yeobaek-rationale:{commentKey} -->`가 있는 코멘트만 자동 관리 대상으로 삼는다.
  marker가 없는 코멘트와 다른 사용자의 코멘트는 수정·삭제하지 않는다.
- 게시 직전에 원격 head SHA와 diff를 확인한다. 새 코멘트는 현재 diff의 정확한 path·line·side를 사용한다.
- 같은 marker·위치·본문이 있으면 재사용한다. outdated 코멘트는 이력으로 보존한다.
- 응답을 확인하지 못했으면 다시 조회하고, 이미 게시된 코멘트를 중복 전송하지 않는다.
- 위치를 옮길 때는 대체 코멘트의 존재와 동일 head를 확인한 뒤 기존 코멘트를 정리한다.
- 다른 사용자의 현재 자동 코멘트와 계획이 충돌하면 중단하고 확인한다.
