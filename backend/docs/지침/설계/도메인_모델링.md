# 도메인 모델링

도메인 상태·판단·값 객체를 새로 작성하거나 수정할 때 적용한다.

## 상태와 판단의 책임

- 의미 있는 상태 변화와 파생 상태(`updatedAt` 등)는 엔티티의 도메인 메서드에서 함께 갱신한다.
  생성 시점의 상태는 생성자가 채운다. 도메인 상태를 JPA 콜백이나 Auditing에 위임하지 않는다.
- 응답을 만들기 위해 `flush()`·`refresh()`가 필요하면 인프라가 대신 갱신하는 상태가 있는지
  확인하고 객체의 책임으로 되돌리는 방향을 검토한다.
- 판단·분기·계산은 상태를 가진 객체에 맡긴다. 여러 객체를 거치는 판단은 협력 객체에 위임하고,
  엔티티 식별자 비교도 의도를 드러내는 메서드로 표현한다.
- DTO 조립을 위한 값 조회는 허용한다. 조회 중 판단이 섞이면 그 판단을 도메인에 둔다.
- JPA 프록시로 전달된 다른 엔티티의 필드를 직접 읽으면 초기화되지 않은 값을 볼 수 있다.
  식별자 비교에는 `other.getId()`처럼 접근자를 사용한다.
  현행 예: [`Book.isSame`](../../../src/main/java/yeobaek/backend/book/domain/Book.java).

## 값 객체의 경계

- 값 자체에 형식·범위·정규화·계산 같은 제품 규칙이 있으면 VO가 규칙과 값을 함께 소유한다.
  엔티티도 해당 VO를 필드로 보관한다.
- DB 저장 한도, 전송 형식, 화면별 조회 개수만으로 도메인 규칙을 만들지 않는다.
  별도의 제품 정책이 있는지 확인한다.
- 전역 유일성이나 다른 레코드와의 관계처럼 값 하나로 판단할 수 없는 규칙은
  엔티티·서비스·저장소 등 필요한 정보를 가진 객체가 맡는다.
- 도메인 안에서는 VO 타입과 동등성 비교를 유지한다. 응답·조회 경계에서만 원시값으로 변환한다.
  이미 검증한 VO를 풀었다가 같은 VO로 재생성하지 않는다.
- 정규화·검증의 진입점은 VO에 둔다. 선택값의 부재는 nullable VO로 표현하고 빈 VO로 감추지 않는다.

## 요청과 JSON

- 기존 VO 대상 요청 필드는 DTO부터 VO로 받는다. 서비스·엔티티는 전달된 VO를 그대로 사용한다.
- Jackson 설정은 각 도메인의 `controller`에 `@JacksonMixin`으로 둔다.
  위임 생성자와 `@JsonValue`로 기존 JSON 형식을 유지하며 도메인 VO에 Jackson 의존성을 넣지 않는다.
- 필수값의 누락·null과 VO 검증 실패는 요청 경계에서 거부한다. 선택값의 부재는 null로 유지한다.
  오류 상태·코드는 [API 명세](../../../../docs/API.md)에 맞춰 회귀 검증한다.

## 중복 판단

- 여러 필드와 집합으로 구성된 중복 기준은 하나의 값 객체에서 비교한다.
  서비스는 기존 데이터 조회와 중복 오류 처리를 맡는다.
- 도서의 기준은 [`BookDeduplicationKey`](../../../src/main/java/yeobaek/backend/book/domain/vo/BookDeduplicationKey.java)다.
  작가 집합은 순서와 관계없이 비교한다. 이름은 필드 목록보다 판단 목적을 드러낸다.
