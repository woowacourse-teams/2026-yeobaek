# 패키지 구조

새 클래스·패키지를 배치할 때 적용한다. `yeobaek.backend.<도메인>` 안에서 역할별로 나누고,
해당 역할이 실제로 필요할 때만 하위 패키지를 만든다.

| 패키지 | 책임 |
|---|---|
| `controller` | 컨트롤러, 웹 인터셉터·리졸버, Jackson MixIn |
| `service` | 응용 서비스 |
| `repository` | 저장소와 쿼리 프로젝션 |
| `domain` | 엔티티, 도메인 규칙과 열거형 |
| `domain.vo` | 값의 검증·정규화·계산을 맡는 VO |
| `dto` | 요청·응답 객체 |

- VO 테스트도 같은 패키지에 둔다. `dto`는 request/response로 더 세분하지 않는다.
- 배치가 애매하면 의존하는 기술과 책임으로 정한다. 웹 의존은 `controller`, 영속성 의존은
  `repository`, 순수한 도메인 판단은 `domain`에 둔다.
- 다른 도메인의 모델을 사용하는 영역에는 자체 `domain`·`repository`를 억지로 만들지 않는다.
- `support`·`auth` 같은 공통 패키지에는 도메인 계층을 강제하지 않는다.
  성격이 섞이면 `support.analytics`, `support.storage`처럼 기술 관심사로 나눈다.
