# 백엔드 테스트 기준

[팀 테스트 기준](../../../../docs/팀_테스트_기준.md)과 [API 명세](../../../../docs/API.md)를 따른다. 명세와 구현의 차이가 제품 동작에 영향을 주면 기대 동작을 팀에 확인한다.

## 테스트 수준

- **단위** · 업무 정책은 입력과 상태로 검증한다. 저장소 조회 결과는 스텁으로 설정한다.
- **웹 슬라이스** · HTTP 요청 바인딩·거부와 응답 계약을 확인한다. [컨트롤러 테스트 하네스](../코딩/컨트롤러_테스트_하네스.md)
- **통합** · 단위·슬라이스에서 재현하기 어려운 MySQL 쿼리·제약·잠금, Spring 트랜잭션 같은 경계를 검증한다.
- **백엔드 E2E** · 핵심 흐름에서 실제 HTTP 요청을 이어 보내 앞선 요청의 저장 결과를 확인한다. [댓글 작성·수정·재조회 예시](../../../src/test/java/yeobaek/backend/e2e/CommentE2eTest.java)

## 통합 테스트 DB 격리

- 테스트 데이터 쓰기가 없으면 [IntegrationTest](../../../src/test/java/yeobaek/backend/support/IntegrationTest.java)의 공통 설정만 사용한다.
- 한 트랜잭션으로 검증할 수 있으면 `@Transactional`로 롤백한다. SQL 실행이나 제약 검사가 필요한 시점에 flush한다.
- 실제 커밋이나 별도 트랜잭션이 필요하면 [DatabaseCleaningIntegrationTest](../../../src/test/java/yeobaek/backend/support/DatabaseCleaningIntegrationTest.java)로 종료 후 정리한다. 테스트 수준 `@Transactional`과 함께 사용하지 않는다.

DB 통합·E2E는 Testcontainers의 MySQL을 사용하고, FCM·S3 같은 외부 서비스는 스텁으로 제어한다. 운영·도구 테스트는 문서화된 [로그](../../로깅_가이드.md)·[관측](../../Better_Stack_연동.md)·[OpenAPI](../../../../docs/API.md) 계약을 검증한다.

전체 검증은 [커밋 전 게이트](커밋_전_게이트.md)를 따른다.
