# 지침 라우팅 색인

이 문서는 작업 목적에 맞는 지침을 찾는 중앙 진입점이다. 작업을 시작할 때 공통 지침을 먼저 읽고, 아래에서 현재 작업에 해당하는 지침을 모두 선택해 읽는다. 한 작업이 여러 유형에 걸치면 하나만 고르지 않는다.

## 항상 적용

- 모든 작업: [피드백 루프 하네스](프로세스/피드백_루프_하네스.md)

## 프로세스

- 새 기능이거나 목표·범위·제약·완료 기준 등 중요한 요구사항이 모호한 작업: [deep-interview 활용](프로세스/deep-interview_활용.md)
- 구현 전에 설계 초안의 결정과 경계를 압박 검증하는 작업: [그릴 활용](프로세스/그릴_활용.md)
- 기능의 미시 정책, 경곗값 또는 예외 상황을 구체화하는 작업: [정책 구체화](프로세스/정책_구체화.md)
- 여러 에이전트가 병렬로 작업하는 경우: [병렬 작업 조율](프로세스/병렬_작업_조율.md)

## 설계

- 도메인 객체의 상태와 행위, 책임을 설계하거나 변경하는 작업: [도메인 모델링](설계/도메인_모델링.md)
- 새 코드를 배치하거나 패키지 구조를 설계·변경하는 작업: [패키지 구조](설계/패키지_구조.md)

## 코딩

- JSON `@RestController`의 테스트를 작성하거나 검토하는 작업: [컨트롤러 테스트 하네스](코딩/컨트롤러_테스트_하네스.md)

## 검증

- 작업 단위를 커밋하기 전에 수행하는 검증: [커밋 전 게이트](검증/커밋_전_게이트.md)

## 유지보수 규칙

- 새 지침은 주된 목적에 맞는 하위 디렉터리에 배치한다.
- 지침을 추가·이동·삭제할 때 이 색인의 해당 작업 유형과 링크를 같은 변경에서 갱신한다.
- 여러 목적에 적용되는 지침은 파일을 중복하지 않고 관련 작업 유형에서 같은 문서로 라우팅한다.
- 기존 분류로 목적을 설명할 수 없을 때만 새 목적 디렉터리를 추가하고, 이 색인에 그 적용 조건을 함께 기록한다.
