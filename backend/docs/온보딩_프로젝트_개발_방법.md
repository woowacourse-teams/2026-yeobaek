# 온보딩 — 프로젝트 개발 방법

> **읽는 대상:** 이 팀에 새로 합류한 개발자
> **이 문서의 목적:** 기존 개발자들이 진행하고 있는 개발 방법의 흐름을 학습하고,
> 팀이 **왜** 이런 방법을 채택했는지 이해한다.
>
> 각 단계의 "왜"는 결정 기록(ADR)에, "어떻게"는 `docs/지침/`의 지침 문서에 있다.
> 이 문서는 그 둘을 잇는 지도다.

## 한눈에 보는 흐름

```
① 요구사항 구체화          ② 구현                       ③ 리뷰
팀원과 논의 + /grill-me  →  AI 에이전트가 코드 작성      →  PR 제출 후
로 명세의 구멍을 찾는다      고민 지점은 피드백 루프          백엔드 팀원과 코드리뷰
                            하네스로 개발자가 결정
```

세 단계를 관통하는 원칙은 하나다: **구현 노동은 AI에게 넘기되, 트레이드오프에 대한
고민과 결정은 개발자가 가져간다.** 각 단계는 이 원칙을 서로 다른 지점에서 지탱한다.

## ① 요구사항 구체화 — 팀 논의 + grill-me

새 기능은 설계 초안을 세운 뒤 팀원과 함께 논의해 구체화하고, `/grill-me`
(AI 인터뷰 세션)를 돌려 계획의 구멍을 찾는다.

- **팀원과 함께 논의하는 이유:** 모든 백엔드 팀원이 한 업무에 대해 이해를 맞추기 위해서다.
- **grill-me를 쓰는 이유:** 요구사항을 구체화하는 과정에서 개발자가 놓치는 부분을
  AI가 짚어주기 위해서다.
- 언제 돌리고 언제 생략하는지, 하네스 보강 목적의 그릴은 무엇인지:
  [지침/그릴_활용.md](지침/그릴_활용.md)
- 결정 배경: [ADR/협업_요구사항_구체화를_위해_grill-me_사용.md](ADR/협업_요구사항_구체화를_위해_grill-me_사용.md)

## ② 구현 — AI 에이전트 + 피드백 루프 하네스

실제 코드 구현은 AI 에이전트가 수행한다. 단, 의미 있는 트레이드오프가 존재하는
결정(스키마, 의존성, 구조, 실패 처리 등)은 AI가 임의로 정하지 않는다 — AI는 멈추고
**결정 요청서**를 올리며, 개발자가 선택과 이유를 답글로 남기면 그 답글이 그대로
결정 기록이 된다. 이 규칙 전체를 **피드백 루프 하네스**라 부른다.

- **AI가 구현하는 이유:** 코딩 생산성을 향상해서, 개발자의 자원을 다른 곳에 쓸 수
  있게 만든다.
- **피드백 루프를 만든 이유:**
  1. 개발자 역량 부족으로 놓치고 넘어가는 고민점들을 AI가 짚어주기 위해서.
  2. 개발자가 지속적으로 트레이드오프를 고민하게 만들어서, 개발자 개인의 개발 역량을
     향상하기 위해서.
  3. AI가 전부 해결하는 것보다, 개발 팀원까지 같이 트레이드오프를 고민한 결과물이
     더 좋을 것이기 때문.
- 하네스의 철칙·멈춤 기준·결정 요청서 양식: [지침/피드백_루프_하네스.md](지침/피드백_루프_하네스.md)
- 구현 단계에서 함께 적용되는 지침:
  - 하네스 멈춤 기준에 안 걸리는 미시 정책(글자수 제한 등)의 처리: [지침/정책_구체화.md](지침/정책_구체화.md)
  - 커밋 전 게이트(빌드·테스트·정적 분석)와 커밋 분할: [지침/커밋_전_게이트.md](지침/커밋_전_게이트.md)
  - 패키지 구조 / 도메인 모델링 / 멀티 에이전트 병렬 작업: `지침/` 하위 각 문서
- 결정 배경: [ADR/협업_AI_에이전트_구현과_피드백_루프_하네스.md](ADR/협업_AI_에이전트_구현과_피드백_루프_하네스.md)

## ③ 리뷰 — PR 제출 후 백엔드 팀원과 코드리뷰

구현이 끝나면 PR을 제출하고 백엔드 팀원과 코드리뷰를 수행한다.

- **AI가 아니라 개발자가 직접 리뷰하는 이유:**
  1. 개발자가 작성된 코드의 흐름을 모두 이해하게 강제한다 (블랙박스로 두지 않는다).
  2. 개발자가 코드를 지속적으로 검토하며, 하네스가 부족한 부분을 찾고 개선할 수 있게
     만든다.
  3. 개발자가 "더 나은 코드란 무엇인가"를 계속 고민하게 돕고, '좋은 코드'의 기준을
     말로 정리할 수 있게 만든다.
- 실제로 코드리뷰 지적에서 출발해 만들어진 지침이 이미 있다 —
  [지침/정책_구체화.md](지침/정책_구체화.md)와 [지침/커밋_전_게이트.md](지침/커밋_전_게이트.md)는
  모두 2026-08-05 코드리뷰 지적을 배경으로 작성되었다. 리뷰가 하네스를 개선한다는
  루프가 실제로 동작한 사례다.
- 결정 배경: [ADR/협업_PR_제출_후_백엔드_팀원_코드리뷰.md](ADR/협업_PR_제출_후_백엔드_팀원_코드리뷰.md)
