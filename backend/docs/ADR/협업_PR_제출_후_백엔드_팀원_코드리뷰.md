# ADR: PR 제출 후 백엔드 팀원과 코드리뷰 수행

## 상태

확정 (2026-08-07, 개발자).

## 맥락

실제 코드 구현을 AI 에이전트가 수행하므로
([협업_AI_에이전트_구현과_피드백_루프_하네스.md](협업_AI_에이전트_구현과_피드백_루프_하네스.md)),
그대로 두면 작성된 코드가 개발자에게 블랙박스가 될 수 있다. 코드에 대한 이해를
개발자에게 남기는 장치가 필요했다.

## 결정

구현 완료 후 PR을 제출하고, 백엔드 팀원과 코드리뷰를 수행한다.

## 근거 (2026-08-07 개발자 기록)

AI가 아니라 개발자가 직접 코드리뷰를 하는 이유:

1. 개발자가, 작성된 코드의 흐름을 모두 이해하게 강제한다 (블랙박스로 두지 않는다).
2. 개발자가 코드를 지속적으로 검토하며, 하네스가 부족한 부분을 찾고 개선할 수 있게
   만든다.
3. 개발자가 "더 나은 코드란 무엇인가"를 계속 고민하게 돕고, '좋은 코드'의 기준을
   말로 정리할 수 있게 만든다.

**실증 사례** — 코드리뷰가 하네스를 개선하는 루프는 이미 동작했다.
[../지침/프로세스/정책_구체화.md](../지침/프로세스/정책_구체화.md)("비즈니스 정책이 부실하게 기획되어
있다"는 지적)와 [../지침/검증/커밋_전_게이트.md](../지침/검증/커밋_전_게이트.md)("미사용
파라미터 등 이슈를 커밋 전 검토해야 한다"는 지적)는 모두 2026-08-05 코드리뷰 지적을
배경으로 만들어진 지침이다.
