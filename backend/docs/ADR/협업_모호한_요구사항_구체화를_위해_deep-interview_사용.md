# ADR: 모호한 요구사항 구체화를 위해 deep-interview 사용

## 상태

확정. 운영 지침([../지침/프로세스/deep-interview_활용.md](../지침/프로세스/deep-interview_활용.md))과
프로젝트 스킬 적용 2026-08-18.

## 맥락

기존 [grill-me 결정](협업_요구사항_구체화를_위해_grill-me_사용.md)은 개발자가 설계
방향을 2~3문단으로 설명할 수 있는 상태에서 계획의 구멍을 찾는다. 목표와 범위부터 흐려
설계 초안을 만들 수 없는 요청에는 별도의 입구 게이트가 없었다.

## 결정

모든 요청에 인터뷰를 강제하지 않고, 구현 결과를 바꿀 중요한 미정이 있는 요청에만
개발동생의 `deep-interview`를 작업 착수 전 명확성 게이트로 적용한다. 목표, 범위와 제외
범위, 제약, 완료 기준, 기존 맥락과 영향 범위를 한 번에 한 질문씩 확인한다.

인터뷰가 끝나 개발자가 자기 언어로 설계 방향을 설명할 수 있으면 기존 팀 논의와
`/grill-me`로 넘어간다. 인터뷰와 그릴의 답변은 요구·설계 맥락이며, 정책 질의서와
피드백 루프 하네스의 결정 요청서 승인을 대체하지 않는다.

원문 스킬은 [참고 스냅샷](../참고/deep-interview/SKILL.md)에 보존하고, 하네스 R1~R4에
따른 프로젝트 오버라이드는 [활용 지침](../지침/프로세스/deep-interview_활용.md)에 둔다.

## 근거 (2026-08-18 개발자 원문)

> 우리 백엔드 프로젝트의 하네스를 보면, grill-me 스킬을 이용해 문제를 구체화시키는 과정이 포함되어 있어. 여기에 '개발동생'의 deep-interview라는 스킬도 포함해서, 개발자가 모호한 요구사항을 전달했을 때 그냥 넘어가지 않고 충분히 구체화해서, 개발자의 암묵지가 포함된 의도와 AI의 동작을 일치시키고 싶어.
> 추가적인 의도는 기존의 '피드백_루프_하네스'를 참고해.

## 검토한 대안

- **grill-me만 유지:** 기존 설계 압박 흐름은 유지되지만, 설계 초안을 만들기 전의 모호한
  요청을 AI가 임의로 해석할 수 있는 공백이 남는다.
- **모든 요청에 deep-interview 강제:** 일관된 형식은 얻지만 오타, 명백한 버그, 작은 설정
  변경에도 질문 비용이 생겨 관문이 소음이 된다.
- **모호한 요청에만 조건부 적용(채택):** 중요한 불확실성이 있을 때만 의도를 정렬하고,
  구체적이고 저위험인 요청은 바로 진행한다.

## 결과와 트레이드오프

- 모호한 요청은 계획·구현 전에 목표와 완료 기준까지 구체화된다.
- 질문은 가장 큰 불확실성 하나씩 진행하므로 한 번에 답해야 할 부담을 제한한다.
- deep-interview와 grill-me가 같은 내용을 물을 위험이 있으므로 `요구사항 명확화 결과`를
  다음 단계에 전달하고 이미 확인한 사실을 재질문하지 않는다.
- 외부 스킬의 추천과 종료 요약 형식은 하네스 R2/R3와 충돌할 수 있다. 이 프로젝트에서는
  개발자가 명시적으로 요청한 경우에만 추천하며, 개발자의 이유·구조 설명을 AI가 작성하거나
  요약하지 않는다.
- 인터뷰 답변만으로 정책이나 R1 결정을 구현할 수 없다. 공식 정책 질의서 또는 결정 요청서
  승인까지 추가 관문 비용이 들지만, 승인 기록과 요구 맥락의 경계를 보존한다.
