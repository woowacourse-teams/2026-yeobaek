# ADR: AI 에이전트 PR 작성 자동화

## 상태

확정 (2026-08-26, PR 본문 목적 보완 2026-08-31, 개발자).

## 맥락

백엔드 변경을 구현한 AI 에이전트가 PR 제출까지 이어서 수행할 하네스가 필요했다. 한 저장소에
백엔드와 Android 프로젝트가 함께 있으므로, 백엔드 자동화가 Android 개발 절차에 미치는 영향과
기계적 검증 도입 비용을 함께 검토했다.

초기 자동화는 개발자가 확정한 문장을 PR 본문에 직접 사용하는 데 초점을 맞췄다. 실제 사용에서
선택지 기호나 대화 지시어가 남아 리뷰어가 코드와 대화 기록을 함께 읽어야 선택 이유를 이해할 수
있는 문제가 확인됐다.

## 검토한 선택지

### 선택지 A: 백엔드 에이전트 지침과 백엔드 전용 PR 본문 템플릿

`backend/AGENTS.md`가 백엔드 변경 작업의 종료 절차를 지시하고, `backend/docs/` 안의
템플릿을 PR 본문 파일의 원본으로 사용한다. 저장소 공용 `.github`와 Android 파일은 변경하지
않는다. 에이전트가 지침을 따르는 동안 자동화되지만 별도 프로그램이 형식을 강제하지는 않는다.

### 선택지 B: 저장소 공용 GitHub PR 템플릿

저장소의 `.github` 아래에 PR 템플릿을 두어 GitHub의 PR 작성 화면에서 사용한다. 저장소 공용
설정이므로 Android PR 작성 과정에도 템플릿이 노출될 수 있다.

### 선택지 C: 스크립트 또는 GitHub Actions를 통한 기계적 검증

스크립트나 GitHub Actions가 PR 본문 형식, reviewer, label 같은 규칙을 검사하거나 적용한다.
자동 검증을 구현하고 유지하는 비용이 추가된다.

## 결정

**선택지 A를 사용한다.**

- [백엔드 PR 작성 하네스](../지침/프로세스/백엔드_PR_작성_하네스.md)를 백엔드 쓰기 작업의
  종료 조건으로 연결한다.
- [백엔드 PR 본문 템플릿](../템플릿/백엔드_PR_본문.md)을 채운 임시 파일로 PR을 생성하거나
  갱신한다.
- 저장소 공용 `.github`와 `android/`는 이 자동화를 위해 수정하지 않는다.
- 별도 스크립트나 GitHub Actions 검증은 현재 도입하지 않는다.
- PR 본문은 리뷰어가 코드 확인 전에 변경 사항, 구현 방법과 선택 이유를 이해할 수 있도록
  작성한다. AI는 코드·문서 및 개발자가 확정한 결정 기록을 근거로 자기완결적인 설명을 작성한다.
  승인 답글은 결정 원본으로 유지하며 PR 본문은 이를 대체하지 않는다. AI는 원본에 없는 결정이나
  근거를 추가하지 않는다 (2026-08-31 개발자 결정).

## PR 본문 목적 보완 근거 (2026-08-31 개발자 기록)

> 선택 근거로 여전히 개발자 원문을 제공하는데, 개발자 원문은 "따라서 C안을 선택했다"처럼 PR 리뷰어 입장에서 바로 이해할 수 없는 언어들이 포함되어 있어.
>
> 따라서, PR 본문의 목적은 "리뷰어가 변경 사항, 구현 방법, 그 방법을 선택한 이유"를 코드 읽기 전에 최대한 빠르게 파악하기 위함이니, 개발자 원문이 아닌 AI가 맥락을 파악해 다듬은 글을 제출해야 해.

## 근거 (2026-08-26 개발자 기록)

> 한 프로젝트 안에 안드로이드 프로젝트도 있으니, 안드로이드 개발에는 영향을 미치지 않아야 한다.

> 기계적 검증엔 비용이 추가되니, 일단 기계적 검증 없는 A로 경험해보고, 문제가 있다고 느껴지면 그때 확장을 고려한다.

## 한계·후속 검토

- 규칙 준수는 AI 에이전트가 백엔드 지침을 정확히 실행하는 데 의존한다.
- 실제 사용에서 문제가 확인되면 선택지 B 또는 C로 확장할지 다시 검토한다.
