# ADR: 도서 제공 방식으로 서버 보관 + 부분 서빙 선택

## 상태

확정. 결정 근거 기록 2026-08-07 (개발자).

## 맥락

책 본문 데이터를 클라이언트에 어떻게 제공할지 결정해야 한다. 이 결정은 데이터
저장 위치·저장 단위·전송 방식과 보안 구조를 좌우한다.

## 검토한 선택지 (2026-08-07 개발자 기록)

### 선택지 A: 암호화(DRM) 후 클라이언트 보관

책 데이터에 암호화(DRM)를 적용한 후, 책 데이터를 모두 클라이언트에 보관한다.

- **저장 위치:** 서버와 클라이언트 모두
- **저장 단위:** 책 하나당 하나의 단위로 저장 (ePub)
- **제공 방식:** 요청이 들어온 책 데이터(ePub)를 한번에 모두 전달

### 선택지 B: 서버 보관 + 부분 서빙

책 데이터를 서버에서만 보관하고, 클라이언트가 요청할 때마다 부분적으로만 제공한다.

- **저장 위치:** 서버에만 저장
- **저장 단위:** 하나의 책을 일정 단위로 쪼개서 여러 DB 레코드에 저장
  (일단은 문단 단위로 저장 예정)
- **제공 방식:** 요청이 들어온 부분만큼의 책 데이터만 전달

## 트레이드오프 비교 (2026-08-07 개발자 기록)

### 오프라인 독서 가능 여부

- 암호화 방식(A)을 활용해야, 오프라인 환경에서도 책을 읽을 수 있다.
- 우리 서비스는 '교환독서' 서비스로, 댓글을 남기며 다른 사용자와 교류하는 게 핵심
  가치다. → 도메인을 고려하면, 오프라인 환경을 지원해야 할 필요성이 적다.

### 책 데이터 유출 위험성

- 암호화 방식(A)은 '메모리 덤프', '복호화 키 및 알고리즘 역공학' 등으로 책 내용이
  유출되기 쉽다.
- 부분 서빙 방식(B)은 비교적 안전하다. (유출하는 데 드는 시간과 비용을 극단적으로
  높여서 공격할 가치를 없앨 수 있음)
- 책 데이터 유출을 어렵게 만들어야, 후에 출판사 및 작가를 섭외할 때 유리하다.
  → 보안이 도메인 관점에서 매우 중요.

## 결정

**서버 보관 + 부분 서빙 방식(B)을 사용한다.**

오프라인 지원의 필요성은 도메인상 적은 반면, 데이터 유출 방지는 도메인상 매우
중요하므로 두 비교 축 모두 부분 서빙 방식이 유리하다.

문단 단위 저장·순서 기반 부분 조회는 데이터베이스 선택의 전제이기도 하다
([기술_데이터베이스로_RDBMS_선택.md](기술_데이터베이스로_RDBMS_선택.md)).

## 한계·트레이드오프

- 오프라인 환경에서는 책을 읽을 수 없다.
- 독서 진행에 따라 클라이언트가 서버에 반복 요청해야 하므로, 정렬된 문단 데이터의
  고빈도 조회 부하를 서버가 감당해야 한다.
