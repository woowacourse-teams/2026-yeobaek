# ADR: 도서 표지를 S3 공개 객체로 제공

## 상태

확정. 결정 근거 기록 2026-08-26 (개발자).

관련 이슈: [P-123](https://linear.app/yeobaek/issue/P-123)

관련 계약: 상위 저장소의 [`API.md`](../../../docs/API.md)

## 해결해야 할 문제

관리자가 도서를 생성하거나 기존 도서의 표지를 바꿀 때 이미지 파일을 보관하고, 도서 정보를
반환하는 모든 API에서 표지 이미지 URL을 제공해야 한다. 표지가 없는 기존·신규 도서도 유효하며,
이 경우 서버는 `coverImageUrl: null`을 반환하고 클라이언트가 기본 이미지를 표시한다.

이미지는 서비스 자산이므로 EC2 파일 시스템이나 DB BLOB보다 내구성과 수평 확장성이 높은 객체
스토리지가 필요하다. 현재 서비스는 AWS를 사용하고 비용을 지원받으므로 S3를 선택한다.

## 결정

### 저장 모델과 공개 URL

- `books.cover_image_key`에 nullable S3 객체 키만 저장한다.
- 전체 URL은 저장하지 않고, 애플리케이션 설정의 공개 base URL과 객체 키를 조합한다.
- CDN은 지금 도입하지 않는다. CloudFront를 도입할 때 DB를 바꾸지 않고 base URL만 교체한다.
- 키 형식은 `${storage.s3.prefix}/book-covers/{소문자 UUID}.(jpg|png|webp)`다.
- prefix는 환경변수 `BOOK_COVER_S3_PREFIX`로 변경할 수 있고, 기본값은 `yeobaek`이다. DB의 객체 키
  길이 제한을 지키기 위해 슬래시로 시작하거나 끝나지 않는 1~26자 경로만 허용한다.
- 키는 불변으로 취급한다. 표지 교체는 같은 키를 덮어쓰지 않고 새 키를 연결한다.

### 접근 제어

- 표지는 비회원에게도 보이는 공개 데이터이므로 S3 `GetObject`는 익명 읽기를 허용한다.
- 쓰기와 삭제는 공개하지 않는다. 애플리케이션이 EC2 IAM Role로 Presigned PUT URL을 발급한다.
- 공개 읽기는 URL 발급과 만료 갱신이 필요 없고 브라우저·모바일 이미지 캐시를 안정적으로
  활용할 수 있다. 반면 외부 핫링크와 대량 수집을 URL 자체로 막을 수 없다는 위험을 수용한다.
- 현재 표지 수와 트래픽에서는 핫링크·대량 다운로드 방어보다 운영 단순성과 캐시 이점의
  우선순위가 높다. 트래픽이 실제 문제가 되면 CloudFront, WAF, rate limiting을 재검토한다.

### 관리자 직접 업로드

1. 관리자 화면이 `POST /api/admin/book-covers/upload-url`에 MIME과 바이트 크기를 보낸다.
2. 서버가 UUID 키와 10분 유효 Presigned PUT URL을 발급한다.
3. 브라우저가 서명된 `Content-Type`과 `Cache-Control`로 S3에 직접 PUT한다.
4. PUT 성공 후에만 `coverImageKey`를 도서 생성 또는 표지 교체 API에 전달한다.

허용 형식은 JPEG, PNG, WebP이며 크기는 1바이트 이상 5 MiB 이하다. 확장자는 원본 파일명이
아니라 서버가 검증한 MIME에서 정한다. 관리자 기능이므로 관리자 화면과 URL 발급 API에서만
크기를 검사하며, S3 POST policy의 엄격한 크기 조건은 이번 범위에 넣지 않는다.

불변 키의 캐시 이점을 위해 업로드 객체에는
`Cache-Control: public,max-age=31536000,immutable`을 저장한다. Presigned URL 응답은 브라우저가
정확히 보내야 할 헤더를 함께 반환한다.

### 생성·교체·제거와 정합성

- 도서 생성 요청의 `coverImageKey`는 nullable이다.
- 기존 활성 도서는 새 키로 표지를 교체하거나 키를 `null`로 만들어 표지를 제거할 수 있다.
- 서버는 제출된 키의 형식만 검증하고 S3 `HeadObject`는 호출하지 않는다. 관리자 화면이 PUT
  성공 후에만 키를 제출하므로, DB 트랜잭션에 S3 지연과 장애를 끌어들이지 않는 편을 선택한다.
- S3 PUT이 성공하고 도서 생성·교체가 실패하거나, 표지를 교체·제거하면 연결되지 않은 객체가
  생길 수 있다. 기존 객체를 요청 안에서 삭제하지 않으며 고아 객체 정리는 백로그로 남긴다.
- 삭제된 도서의 표지 교체·제거는 `BOOK_NOT_AVAILABLE`로 거부한다.

### 응답 계약

도서 목록·상세, 모임 생성·참여·목록·상세, 마지막 읽기, 관리자 도서 생성과 관리자 작가별 작품
목록처럼 도서 정보를 포함하는 모든 응답에 nullable `coverImageUrl`을 포함한다. 내부 객체 키는
일반 사용자 응답에 노출하지 않는다.

### 애플리케이션과 인프라 설정

- AWS SDK for Java v2의 BOM과 `s3` 모듈만 사용한다.
- `S3Presigner`는 애플리케이션 단위 빈으로 재사용하고 종료 시 닫는다.
- 운영 자격증명은 EC2 instance profile의 기본 자격증명 체인을 사용하며 access key를 설정 파일에
  저장하지 않는다.
- 설정은 bucket, region, public base URL이며 운영에서는 환경변수로 주입한다.
- 버킷은 ACL을 사용하지 않고, 저장 암호화와 버전 관리를 활성화한다.
- S3 CORS는 관리자 웹 origin의 `PUT`과 실제 서명 헤더만 허용한다.

## 검토한 선택지

### 저장 위치

- S3·BaaS·미디어 CDN
- Imgur API
- EC2 파일 시스템
- DB BLOB

서비스 자산의 내구성, 기존 AWS 생태계와 비용 지원, 운영·확장 경계를 고려해 S3를 선택했다.

### DB 저장값

- 전체 공개 URL
- S3 객체 키

전체 URL은 응답 로직이 단순하지만 버킷·리전·CloudFront 변경이 DB 마이그레이션이 된다. base URL
조합의 작은 애플리케이션 비용으로 배포 경로 변경 가능성을 확보하기 위해 키만 저장한다.

### 읽기 접근

- 공개 객체 URL
- 비공개 객체와 짧은 Presigned GET
- 비공개 객체와 긴 Presigned GET

긴 Presigned URL은 만료·서명·쿼리스트링 캐시 키를 관리하면서도 수명이 길수록 공개 URL과 같은
유출·핫링크 위험을 가진다. 표지는 보호 대상이 아니므로 공개 읽기를 선택한다.

## 영향

- DB와 S3는 하나의 트랜잭션이 아니므로 완전한 원자성을 제공하지 않는다.
- 같은 이미지 내용도 교체 시 URL이 달라져 장기 캐시를 안전하게 사용할 수 있다.
- 공개 base URL을 바꾸면 이후 API 응답부터 새 URL이 즉시 적용된다.
- 버킷 정책은 익명 읽기만 허용하고, 업로드 권한은 지정된 EC2 Role에 한정해야 한다.
- Android는 nullable `coverImageUrl`을 모든 도서 응답 모델에 추가하고 null이면 기본 이미지를
  표시해야 한다. Android 코드 변경은 이 작업에 포함하지 않는다.

## 한계와 후속 작업

- 고아 객체 탐지·정리 정책과 자동화는 백로그다.
- CloudFront 도입은 트래픽, 비용, 지연 시간 데이터가 쌓인 뒤 재검토한다.
- 공개 핫링크·대량 다운로드가 실제 비용 문제로 나타나면 CDN/WAF/요청 제한을 검토한다.
- 이미지 리사이징, 썸네일 파생본, 바이러스 검사와 실제 바이트 signature 검사는 제공하지 않는다.
- 운영 인프라 적용 후 관리자 브라우저에서 CORS와 실제 PUT을 smoke test해야 한다.

## 향후 재검토 신호

- S3 전송 비용이나 원거리 지연이 유의미해진다.
- 외부 핫링크나 대량 수집이 비용·가용성 문제를 만든다.
- 표지를 비공개로 다뤄야 하는 권리·계약 요구가 생긴다.
- 고아 객체의 저장량이 운영상 무시할 수 없는 수준이 된다.
- 원본 외에 여러 해상도·포맷 파생본을 제공해야 한다.
