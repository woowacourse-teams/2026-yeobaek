# ADR: 백엔드 언어로 Java 선택

## 상태

확정. 결정 근거 기록 2026-08-07 (개발자).

## 맥락

백엔드 서버 개발 언어를 선택해야 한다. 프레임워크는 Spring으로 확정된 상태에서
([기술_백엔드_프레임워크로_Spring_선택.md](기술_백엔드_프레임워크로_Spring_선택.md)),
Spring이 공식 지원하는 Java와 Kotlin 중 하나를 선택한다. 언어는 코드베이스 전체와
팀 협업 방식을 결정하는 비가역적 선택이므로, 검토한 선택지와 결정 근거를 기록한다.

## 검토한 선택지 (2026-08-07 개발자 기록)

### 선택지 A: Java

- 모든 백엔드 팀원이 능숙하게 다룰 수 있다 → 코드리뷰 및 장애 발생 시 원인 파악이
  수월하다.
- 별도 설정 없이도 Spring을 바로 사용할 수 있다.
- (Kotlin 대비) Kotlin 숙련도 부족으로 인해, 코드 리뷰를 거치고도 놓치는 버그가
  존재할 수 있다.

### 선택지 B: Kotlin

- Kotlin Multiplatform을 통해, 클라이언트(Kotlin & Jetpack Compose)와 중복 로직을
  공유해서 생산성을 향상할 수 있다.
- 클라이언트와 같은 개발 맥락을 공유할 수 있다.
- 언어가 제공하는 강력한 기능(예: 널 안전성)을 사용할 수 있다.

## 결정

**Java를 사용한다.**

## 근거 (2026-08-07 개발자 기록)

- 빠른 개발이 급선무인 상황에서, Kotlin 사용으로 인한 코드리뷰 및 러닝커브 병목이
  치명적이다. (이점 대비 단점이 크다)

## 한계·트레이드오프

- 클라이언트와의 로직 공유(Kotlin Multiplatform), 널 안전성 등 Kotlin이 제공하는
  이점은 포기한다.
