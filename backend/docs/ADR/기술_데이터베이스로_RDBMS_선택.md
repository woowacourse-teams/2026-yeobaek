# ADR: 데이터베이스로 RDBMS 선택

## 상태

확정. 결정 근거 기록 2026-08-07 (개발자).
단, 파티셔닝/샤딩 도입 vs 광폭 열 NoSQL 전환은 재검토 예정 결정으로 보류.

## 맥락

책 본문 데이터를 순서와 함께 저장하고, 순서를 기반으로 연속된 데이터를 조회하는
기능이 필요하다. 현재 도메인상 정렬된 문단 데이터를 고빈도로 호출할 것으로 예상된다.
이 접근 패턴을 감당할 데이터베이스를 선택해야 한다.

## 결정

**RDBMS를 사용한다.** (프로젝트 기술 스택상 MySQL)

프로토타입에서는 RDBMS에 파티셔닝/샤딩 없이 해결한다.

## 근거 (2026-08-07 개발자 기록)

- 정렬된 문단 데이터의 고빈도 조회는, 복합 PK 클러스터링 시 조회 속도가 가장 빠른
  RDBMS가 유리하다.

## 재검토 예정 (2026-08-07 개발자 기록)

실제 서비스로 발전하는 과정에서 다음을 고민한다:

- **파티셔닝/샤딩을 도입해서 RDBMS 유지** vs **광폭 열 NoSQL로 전환**

## 한계·트레이드오프

- 프로토타입 단계에서는 파티셔닝/샤딩 없이 운영하므로, 데이터 규모가 커지면 위
  재검토 결정을 실제로 내려야 한다.
