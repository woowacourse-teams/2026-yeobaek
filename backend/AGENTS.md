# 백엔드 에이전트 지침

이 파일은 백엔드 작업의 공통 규칙이다. 세부 지침은 작업에 해당할 때만 읽는다.
사용자의 현재 요청을 우선하고, 기존 지침과 충돌하면 충돌한 부분을 짧게 알린다.
ADR은 결정 배경을 확인하는 자료이며 현행 작업 절차는 이 파일과 아래 지침을 따른다.

## 작업 범위

- 기본 수정 범위는 `backend/`다. `android/` 수정은 사용자의 명시적 요청이 필요하다.
- 사용자의 미커밋 변경과 삭제를 보존하고, 요청과 무관한 파일을 복구하거나 정리하지 않는다.
- 작업 브랜치 생성·PR 제출은 [Git Flow 지침](../docs/Git_Flow_지침.md)을 따른다.
  사용자가 선택한 기존 작업 브랜치와 변경을 임의로 전환·재배치하지 않는다. 분기 기준이
  맞지 않으면 푸시·PR 제출 전에 알리고 해결한다.

## 작업 방식

- 코드·문서에서 확인할 수 있는 사실은 직접 조사한다. 구현을 바꿀 중요한 미정만
  [피드백 루프 하네스](docs/지침/프로세스/피드백_루프_하네스.md)에 따라 질문한다.
- [지침 색인](docs/지침/README.md)에서 변경 대상에 해당하는 문서만 읽는다.
- 코드 변경의 검증과 커밋은 [커밋 전 게이트](docs/지침/검증/커밋_전_게이트.md)를 따른다.
- PR 작성·제출을 맡은 작업에서는 [PR 작성 하네스](docs/지침/프로세스/백엔드_PR_작성_하네스.md)를 따른다.

## 설명과 문서

- 현재 동작, 필요한 이유, 검증 결과를 먼저 쓴다. 독자가 이미 아는 배경은 반복하지 않는다.
- 과거 대화 날짜·승인 이력·PR 번호는 변경 경위나 출처 확인에 필요할 때만 언급한다.
- 구현 사실과 추론을 구분하고, 개발자가 말하지 않은 선택 이유를 개발자의 판단으로 쓰지 않는다.
- 지침에는 현재 적용할 규칙과 예외를 남긴다. 변경 이력을 누적하거나 코드·설정 내용을 복제하지 않는다.
- 지침을 추가·이동·삭제하면 색인의 적용 조건과 링크도 함께 갱신한다.
