# 번역 완료본 업로드 지침

전체 번역 요청은 독립 검증된 최종 패키지를 **yeobaek.team 프로필의 Chrome UI**로 관리자와 팀 Google Drive에 업로드하는 단계까지 포함한다. 도서 제작 담당자는 로컬 산출물과 증거를 인계하고, 단일 업로드 담당자가 중복 등록을 방지한다. 사용자가 업로드를 제외하거나 중단하면 그 최신 지시를 따른다. 작업 범위를 늘리거나 새 자동화·채팅을 만드는 권한으로 해석하지 않는다.

- 관리자: https://yeobaek.duckdns.org/admin
- 팀 Drive: https://drive.google.com/drive/folders/1GGynmSzhA2BzogMkyzfJEON24u5G0skN
- 계정: `yeobaek.team@gmail.com`

## 1. 제작 전 서비스 확인

computer-use 스킬을 읽고 팀 Chrome 프로필·실제 로그인 계정을 확인한다. 기존 사용자 탭을 확인해 사용하고, 새 탭을 만들면 현재 연결된 브라우저를 명시한다. 다른 개인 프로필로 전환하지 않는다.

최신 관리자 목록에서 제목·원제·저자/ISNI·판본으로 중복을 확인한다. 같은 ISNI의 서버 한글 저자명을 메타데이터·표지 프롬프트·이미지에 일치시킨다. 동일 작가만으로 시리즈를 추정하지 않는다. 같은 시리즈가 실제 있으면 기존 표지를 직접 확인하고 이미지 생성 전 선정에 반영한다. 서비스 기존 책·저자 표기를 임의 변경하지 않는다.

## 2. 업로드 직전 독립 검증

- 원문 baseline SHA-256, 실제 원문/번역 문단과 운문·재결합, 독립 리뷰와 필요 시 원문 색인·색인 검토 해시를 대조한다.
- 서지·ISNI와 대한민국에서의 공개 권리 근거를 확인한다. 현대 전사자 주·삽입문 등 별도 권리 미해결 부분을 원작의 퍼블릭 도메인 여부로 덮지 않는다.
- `책_소개.txt`를 별도 검토자가 사실성·스포일러·한국어 기준으로 검토하고 `ingest.json.description`과 정확히 대조한다. 운영자가 별도 검수를 요구했거나 불확실성이 남으면 해당 책을 보류하고 확인한다. 운영자의 승인·검수 완료를 자동으로 꾸며 기록하지 않는다.
- 선택 표지의 실제 원본과 전체 프롬프트, 현재 검수 해시를 확인한다. 기존 7종 제품은 기존 전체 검증 계약을 따른다.
- ZIP 전체 CRC와 보관 대상의 현재 바이트를 대조한다. 원문·ingest·표지·번역·색인·검토 기록이 승인 제품과 같아야 한다. 작성과 독립 검증을 분리한다.
- 독립 검증 결과와 현재 원문·ingest·ZIP·선택 표지의 SHA-256을 결속한 기록을 저장한다. 채팅 idle·자체 완료 주장만으로 승인하지 않는다. 검증 후 변경되면 다시 검토한다.

업로드 직전 두 서비스의 최신 목록과 기존 업로드 장부를 다시 확인한다. 장부는 책별 관리자/Drive 상태·고유 ID·제품 해시·증거 경로를 구분한다. 과거 메모만으로 중복 없음이나 업로드 성공을 선언하지 않는다.

## 3. 관리자 등록

1. 자동 입력된 기존 인증으로 목록을 불러온다. 토큰 값을 읽거나 출력·기록하지 않는다. 인증 입력이 필요하면 사용자가 직접 입력하도록 요청하며 채팅으로 토큰을 받지 않는다.
2. 검증한 `ingest.json`과 선택한 PNG 한 개를 UI 파일 선택기로 선택한다. 서비스가 허용하는 실제 파일 형식·크기를 확인한다. 크기나 형식을 맞추기 위해 검증 후 이미지를 몰래 바꾸지 않는다.
3. JSON 로드 완료를 확인하고 등록을 한 번 실행한다. 응답 지연·연결 끊김은 재등록 근거가 아니다. 완료 메시지와 실제 목록을 확인한 뒤 재시도 필요 여부를 판단한다.
4. 실제 행의 bookId·제목·저자·본문 수, 펼친 소개의 정확 일치, 표지 로딩을 확인한다. 즉시 UI 증거와 장부를 저장한다. 성공한 실제 스타일만 시리즈 이력에 기록한다.
5. 실패하거나 결과가 불명확하면 정확한 상태와 근거를 보존한다. 이미 성공한 도서를 다시 등록하지 않는다.

큰 JSON으로 제어가 지연되면 기존 완료 응답·실제 행을 우선 확인한다. 닫힌 탭 핸들을 재사용하지 않는다. 새 탭에서 조회할 때도 제출을 반복하지 않는다.

## 4. Drive 보관

1. 대상 폴더와 계정을 확인하고 ZIP명을 검색하거나 목록의 다음 구간까지 불러와 중복을 확인한다. 첫 50개 등 일부 목록만으로 전체 중복 없음을 주장하지 않는다.
2. 없으면 검증한 정식 ZIP을 UI로 업로드한다. 기존 같은 도서 파일이 구버전이면 정상 `Manage versions → Upload new version`으로 같은 고유 ID를 유지해 현재 제품을 교체한다. 같은 이름의 중복 파일을 추가하지 않는다.
3. 휴지통·이동·접근 오류가 있으면 실제 상태를 확인한다. 소유자가 보관을 요청한 동일 파일 복원 등 권한 범위 안에서 처리하며, 모호한 충돌은 사용자와 해결한다. 구버전을 임의 영구 삭제하지 않는다.
4. UI 업로드 완료와 고유 파일 ID·파일명·표시 크기를 기록하고 로컬 바이트 수와 표시 단위/반올림 범위를 대조한다. 기존 버전 이력과 현재 버전을 구분한다. UI 크기 확인을 원격 바이트 해시 검증으로 표현하지 않는다.
5. 즉시 Drive 증거와 장부를 저장한다. 관리자 성공·Drive 실패는 부분 완료이며 양쪽 성공으로 바꾸지 않는다.

## 5. 브라우저 장애·사용자 중단

정상 새로고침·현재 탭 확인 등 안전한 복구 후에도 연결·파일 선택·인증 문제가 남으면 사용자에게 증상과 필요한 조치를 구체적으로 의논한다. 자동 승인 검토 거절·URL 정책·브라우저 보안 경고를 API/CLI·다른 프로필로 우회하지 않는다. 도구 오류·타임아웃을 성공으로 기록하지 않는다.

사용자가 중단하면 신규 배정·제작·변환·업로드를 멈추고 현재 도구 결과·해시·체크포인트를 보존한다. 승인 대기 상태를 임의 승인하지 않으며 실제 종료까지 확인한다. 재개는 최신 사용자 지시 범위에 한정한다.

## 6. 완료 보고

책별 로컬 검증 상태, 관리자 bookId와 본문·소개·표지 확인, Drive 파일 ID·표시 크기·로컬 크기와 신규/버전 교체 여부, 현재 제품 해시·증거 경로를 보고한다. 로컬 완료·각 서비스 성공·개별 보류를 구분한다. 권리·시리즈 디자인·미승인 패키지 등 보류는 정확한 근거와 필요한 다음 조치를 남긴다. 보류를 업로드 완료로 세지 않는다. 업로드된 패키지와 장부가 정합하며 남은 실행이 없을 때 전체 결과를 보고한다.
