# 책 표지 선정·제작 하네스

번역과 리뷰가 끝난 작품에 가장 어울리는 표지 시안 **한 종을 이미지 생성 전에 선정**하고, 그 표지만 제작·검수한다. A–G는 선택 가능한 디자인 방향이며 일곱 이미지를 모두 만드는 작업 목록이 아니다.

> 브리프 → 실제 서비스 시리즈·저자 표기 확인 → 시안 1종 선정 → 선택 프롬프트 준비 → 이미지 1개 제작 → 독립 검수 → 인제스트·ZIP → 팀 Chrome 업로드

## 0단계 — 입력 확정

1. `번역_하네스.md`, 최종 메타데이터, 공통 가이드, 전체 번역과 리뷰를 읽는다.
2. [업로드 지침](업로드_지침.md)에 따라 팀 Chrome에서 최신 서비스 목록을 확인한다. 같은 ISNI의 기존 한글 저자명과 메타데이터를 맞춘 뒤 프롬프트·이미지를 만든다. 서버 저자나 기존 책은 임의 수정하지 않는다. 연결이 막히면 사용자와 해결하고 미확인을 확인 완료로 기록하지 않는다.
3. 실제 같은 시리즈가 있으면 기존 표지의 색·레이아웃·제목·작가 위치·모티프 표현을 확인한다. 같은 작가라는 이유만으로 시리즈로 간주하지 않으며, 같은 A–G 문자만으로 디자인 일관성을 충족했다고 판단하지 않는다.
4. `표지_브리프.json`을 작성한다. 제목·작가는 메타데이터만 기준으로 하며 브리프에 중복 기록하지 않는다.

```json
{
  "genre": "고전 추리 소설",
  "coreSummary": ["작품 전체를 설명하는 문장.", "중심 갈등과 정서를 설명하는 문장."],
  "keywords": ["주제", "정서", "서사"],
  "visualMotifs": ["원문에 근거한 장소 또는 상징 오브제"],
  "targetAudience": "고전 문학을 현대 한국어 번역으로 읽으려는 성인 독자",
  "avoid": []
}
```

`coreSummary`는 2~5문장, `keywords`는 3~7항목, `visualMotifs`는 하나 이상이다. 원문에 없는 사건을 실제 사건처럼 추가하지 않는다. 시각적 은유는 작품의 주제를 설명하는 표현임을 선정 근거에 구분한다.

## 1단계 — 이미지 생성 전 한 종 선정

- A — 감성적 수채화 일러스트
- B — 현대적 타이포그래피
- C — 직관적인 실사 오브제
- D — 클래식 아카이브
- E — 키치 팝아트
- F — 텍스처 오브제 프레임
- G — 시각적 은유와 그래픽 폼

주제 30·정서 25·장르 20·시대문화 15·모티프 또는 확장 10의 가중치로 디자인 방향을 비교한다. 비교를 위해 이미지를 일곱 장 생성하지 않는다. 실제 같은 시리즈가 있으면 기존 디자인 계약을 우선 적용하고 작품 적합성과 충돌하면 생성 전에 해결한다.

책 폴더의 `표지_선정.md`에 선택 ID, 후보 비교·가중 평가, 선정 이유, 시리즈 조회 근거, 최종 제목·저자명, 브리프 SHA-256을 기록한다. 별도 검토자가 작품 적합성과 시리즈 일관성을 검토한다. 모든 후보가 부적합하면 브리프를 수정하고 다시 선정한다.

## 2단계 — 선택 프롬프트 준비

G를 선정한 예시다. 실제 선정 ID로 바꿔 실행한다.

```powershell
py -3 ..\표지_시안_준비.py prepare --meta .\메타데이터.json --brief .\표지_브리프.json --output-dir .\표지 --style G
```

macOS/Linux는 `python3 ../표지_시안_준비.py`를 쓴다. 시스템 Python이 없으면 Codex workspace dependency Python을 사용한다. 새 책에서는 `--style`을 반드시 명시한다. 미지정 준비는 과거 7종 호환 경로다.

선택한 `프롬프트/G.txt`와 `시안_목록.json`만 준비한다. 파생 프롬프트·목록은 수작업 수정하지 않는다. 입력이나 선택이 바뀌면 prepare를 다시 실행하고 이미지 적합성·검수 해시를 갱신한다.

공통 제작 조건은 실제 앞표지 한 장·세로 2:3, 정확한 제목과 작가명만 한 번씩, 독창적이고 인쇄 가능한 완성도다. 추가 문구·유사문자·가짜 활자·워터마크·로고·목업·책등·뒷표지·바코드·가격표·손·표지 밖 배경은 금지한다. 손 금지는 작은 배경 인물과 태피스트리 속 인물에도 적용한다. 문자 유발 소재의 내부 표면은 비우며 메타데이터 제목·작가명만 예외로 허용한다.

## 3단계 — 이미지 한 개 제작

1. 선택 프롬프트 전문을 내장 이미지 생성 도구에 전달해 한 장만 만든다. 나머지 디자인의 이미지는 생성하지 않는다.
2. 실제 결과를 확인하고 `표지/<선택 ID>.png`로 보관한다. 도구 임시 위치에만 두지 않는다.
3. 실패하면 같은 시안의 결함을 고쳐 다시 제작한다. 이전 결과는 `표지/작업/`에 보존하고 검수한 최신 한 장만 최종 위치에 둔다. 방향을 바꾸려면 선정 근거부터 갱신한다. ID 변경이나 기존 7종에서 1종으로 이관할 때는 기존 `표지/` 전체를 책 폴더의 `작업/표지_이전_<timestamp>/`에 보존한 뒤 새 `표지/`에 prepare를 실행한다. 이전 PNG·프롬프트를 새 출력 폴더에 남겨 검증 실패를 만들거나 임의 삭제하지 않는다.
4. 도구 실패 시 사용자 확인 없이 API·CLI·다른 모델로 전환하지 않는다. 빈 파일·복사본·플레이스홀더·여러 표지를 합친 보드로 대체하지 않는다.

G 선택 시 최종 배치:

```text
표지_브리프.json
표지_선정.md
표지/
  G.png
  시안_목록.json
  표지_검수.json
  프롬프트/G.txt
  작업/                 # 이전 실패본, ZIP 제외
```

최종 이미지·프롬프트는 선택 ID 한 개만 둔다. 기존 7종의 파일을 임의 삭제하거나 덮어쓰지 않는다.

## 4단계 — 구조·독립 시각 검수

```powershell
py -3 ..\표지_시안_준비.py validate --meta .\메타데이터.json --brief .\표지_브리프.json --output-dir .\표지 --structural-only
```

선택 ID 한 개, PNG CRC·zlib·스캔라인 무결성, 1024×1536 이상·정확한 2:3 비율을 검사한다. 제작자와 별도의 검토자가 실제 원본을 직접 열어 전체 프롬프트와 대조한다. 파일 존재·제작자의 완료 주장으로 시각 검수를 대신하지 않는다.

- `textExact`: 최종 제목·작가명이 정확하고 다른 문자·유사문자가 없음
- `frontCoverOnly`: 앞표지 전용이며 손을 포함한 금지 요소가 없음
- `styleMatch`: 선택 스타일과 작품·시리즈 디자인 계약 충족
- `legible`: 구성에 맞는 가독성. F의 보조 활자는 단일 접사 오브제와 여백에 종속되는 극소형 구성인지 판단하며 임의 절대 픽셀 합격선을 만들지 않음
- `publicationReady`: 인쇄 디자인 수준의 균형·디테일·완성도

검수한 실제 PNG·프롬프트의 SHA-256을 기록한다. G 예시:

```json
{
  "schemaVersion": 2,
  "variants": {
    "G": {"textExact": true, "frontCoverOnly": true, "styleMatch": true, "legible": true, "publicationReady": true, "imageSha256": "<현재 PNG SHA-256>", "promptSha256": "<현재 프롬프트 SHA-256>", "notes": "독립 검토 근거"}
  },
  "setChecks": {"noExtraTextAcrossSet": true}
}
```

한 종에는 시안 간 차별성 판정을 요구하지 않는다. 이미지·프롬프트가 바뀌면 직접 다시 열어 검수한다. 판정만 true로 바꿔 통과시키지 않는다.

```powershell
py -3 ..\표지_시안_준비.py validate --meta .\메타데이터.json --brief .\표지_브리프.json --output-dir .\표지
```

## 5단계 — 보관·업로드·보고

전체 검증 후 공식 변환기로 ingest와 ZIP을 생성한다. 선택 PNG·프롬프트·목록·검수 기록·브리프를 보관하며 `표지/작업/`은 제외한다. `표지_선정.md`는 ZIP과 함께 보관하는 근거이며 현재 ZIP에 포함됐는지는 실제 항목으로 확인한다. [업로드 지침](업로드_지침.md)에 따라 같은 검증 제품을 관리자와 Drive에 올린다.

선택 ID·사전 선정 근거, 최종 PNG·프롬프트, 구조·독립 시각 검수와 해시, 생성 경로, ZIP 보관 결과, 실제 업로드 성공 또는 개별 보류를 보고한다.

## 기존 7종 패키지

기존 schemaVersion 1의 A–G 패키지는 기존 전체 7종·중복·차별성·검수 해시 검증을 유지한다. 한 종 통과로 기존 일곱 종의 검증을 대신하지 않는다. 새 절차 적용을 이유로 과거 책을 자동 재제작·재변환·재업로드하지 않는다. 명시적으로 이관할 때만 기존 파일을 보존한 후 선정·준비·독립 검수·공식 변환을 수행한다.
