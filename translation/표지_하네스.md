# 책 표지 시안 생성 하네스

이 문서는 번역과 리뷰가 끝난 책을 바탕으로 실제 출판용 앞표지 시안 7개를 생성하고 검수하는 절차를 정의한다. 특정 도서에 종속되지 않으며, `번역_하네스.md`의 필수 파이프라인에 포함된다.

> 표지 파이프라인: **표지 브리프 작성 → A–G 프롬프트 생성 → 7개 이미지 독립 생성 → 구조 검증 → 시각 검수와 필요한 재생성 → 최종 검증**

기본 실행 환경은 Codex의 내장 이미지 생성 도구다. 각 시안은 서로 다른 프롬프트로 한 번씩 독립 호출한다. 내장 도구가 없거나 실패했다고 해서 API·CLI 또는 다른 모델로 몰래 전환하지 않는다. CLI/API 경로는 사용자가 명시적으로 요청하거나 확인한 경우에만 사용하며, 그 경로에는 로컬 `OPENAI_API_KEY`가 필요하다.

## 완료 조건

- 책 폴더에 `표지_브리프.json`이 있다.
- `표지/프롬프트/A.txt`부터 `G.txt`까지 7개 프롬프트와 `표지/시안_목록.json`이 현재 메타데이터·브리프에서 생성된 최신 상태다.
- `표지/A.png`부터 `표지/G.png`까지 정확히 7개의 독립 이미지가 있다.
- 모든 이미지는 CRC·zlib·스캔라인을 정상 해제할 수 있는 유효한 PNG이고, 너비 1024px 이상, 높이 1536px 이상이며 정확한 세로 2:3 비율이다.
- 7개 파일의 내용이 서로 중복되지 않는다.
- 각 이미지의 제목과 작가명이 `메타데이터.json`에서 정한 표기와 정확히 일치한다.
- 각 시안이 지정 스타일, 앞표지 전용 구성, 가독성, 출판 완성도 검수를 통과한다.
- `표지/표지_검수.json`이 각 최종 이미지·프롬프트의 SHA-256과 시각 검수 결과를 함께 기록하며 전체 검증 명령이 통과한다.

표지 단계가 끝나지 않았다면 번역 파이프라인 전체 완료를 선언하거나 최종 ZIP을 표준 산출물로 안내하지 않는다.

## 책별 파일 배치

```text
<책 폴더>/
├─ 메타데이터.json
├─ 표지_브리프.json
└─ 표지/
   ├─ A.png
   ├─ B.png
   ├─ C.png
   ├─ D.png
   ├─ E.png
   ├─ F.png
   ├─ G.png
   ├─ 시안_목록.json
   ├─ 표지_검수.json
   └─ 프롬프트/
      ├─ A.txt
      ├─ B.txt
      ├─ C.txt
      ├─ D.txt
      ├─ E.txt
      ├─ F.txt
      └─ G.txt
```

`A.png`부터 `G.png`는 현재 최종 시안의 고정 파일명이다. 실패한 생성물이나 폐기한 버전을 이 7개 파일명으로 남기지 않는다. 기존 최종 시안을 다시 만들 때에는 이전 파일을 바로 덮어쓰지 말고 `표지/작업/` 아래로 옮겨 보존한 뒤 새 시안을 검수해 승격한다. `작업/`은 전달용 ZIP에 포함하지 않는다.

`표지/` 루트에는 A–G PNG, `시안_목록.json`, `표지_검수.json`만 둘 수 있고 하위 폴더는 `프롬프트/`와 선택적 `작업/`만 허용한다. JPG·WebP·추가 PNG·임의 폴더는 최종 검증에서 실패하며 ZIP에도 포함하지 않는다.

## 0단계 — 전제 확인과 표지 브리프 작성

1. `번역_하네스.md`, 이 문서, `메타데이터.json`, `번역_공통_가이드.md`, 리뷰가 반영된 전체 번역본과 `리뷰/` 보고서를 읽는다.
2. 제목과 작가 표기가 최종 확정됐는지 확인한다. 표지 제목은 `메타데이터.json.title`, 작가명은 `authors[].name`을 입력 순서대로 ` · `로 연결한 문자열을 그대로 사용한다. 표지 브리프에 제목이나 작가명을 중복 기록하지 않는다.
3. 작품 전체의 내용과 정서를 분석해 책 폴더에 아래 스키마의 `표지_브리프.json`을 작성한다.

```json
{
  "genre": "고전 추리 소설",
  "coreSummary": [
    "작품 전체를 설명하는 첫 번째 문장.",
    "갈등과 정서를 설명하는 두 번째 문장."
  ],
  "keywords": ["키워드1", "키워드2", "키워드3"],
  "visualMotifs": ["주요 인물", "장소", "상징 오브제"],
  "targetAudience": "주요 독자층",
  "avoid": ["피하고 싶은 요소"]
}
```

필수 규칙:

- `coreSummary`: 작품 전체를 요약하는 2~5개 문장
- `keywords`: 주제·정서·서사를 대표하는 3~7개 항목
- `visualMotifs`: 표지에 활용할 주요 인물·장소·오브제 중 하나 이상
- `targetAudience`: 한 문장 또는 짧은 구
- `avoid`: 선택 배열이며 별도 금지 요소가 없으면 `[]`
- 추측성 소재나 원문에 없는 사건을 넣지 않는다.
- 목표 독자층을 별도로 알 수 없으면 `고전 문학을 현대 한국어 번역으로 읽으려는 성인 독자`를 기본값으로 쓴다.

## 1단계 — A–G 프롬프트 생성

책 폴더에서 다음 명령을 실행한다.

```powershell
py -3 ..\표지_시안_준비.py prepare --meta .\메타데이터.json --brief .\표지_브리프.json --output-dir .\표지
```

macOS/Linux 예시:

```bash
python3 ../표지_시안_준비.py prepare --meta ./메타데이터.json --brief ./표지_브리프.json --output-dir ./표지
```

시스템 Python 명령이 없으면 Codex App의 workspace dependency Python을 찾아 같은 스크립트를 실행한다. 스크립트가 생성한 `프롬프트/*.txt`와 `시안_목록.json`은 파생 산출물이므로 AI가 수작업으로 고치지 않는다. 내용 변경이 필요하면 `표지_브리프.json`을 수정하고 `prepare`를 다시 실행한다.

메타데이터나 브리프를 바꾸고 `prepare`를 다시 실행하면 기존 이미지 파일은 보존되지만, 기존 `표지_검수.json`의 프롬프트 해시가 더 이상 맞지 않아 전체 검증이 실패한다. 변경된 입력에 맞춰 필요한 시안을 다시 생성하고 시각 검수를 갱신해야 한다.

프롬프트는 아래 7개 디자인 방향을 서로 독립된 제작 사양으로 만든다.

- A — 감성적 수채화 일러스트
- B — 현대적 타이포그래피
- C — 직관적인 실사 오브제
- D — 클래식 아카이브
- E — 키치 팝아트
- F — 텍스처 오브제 프레임
- G — 시각적 은유와 그래픽 폼

모든 프롬프트에는 다음 공통 조건이 들어간다.

- 실제 출판용 앞표지 한 장, 세로 2:3
- 제목과 작가명만 정확히 한 번씩 표기
- 추가 문구, 의미 없는 문자, 가짜 로고, 워터마크 금지
- 책 목업, 펼친 책, 책등, 뒷표지, 바코드, 가격표, 출판사 로고, 손, 표지 바깥 배경 공간 금지
- 제목·작가명의 높은 가독성과 비주얼에 가리지 않는 대비
- 기존 출간 표지나 특정 작가의 작품을 모방하지 않는 독창적 디자인
- 초안이나 스케치가 아닌 정교한 인쇄 디자인 수준

또한 `표지_시안_준비.py`는 언어별 키워드 목록에 의존하지 않고 A–G 모든 프롬프트에 다음 **조건부 안전 규칙**을 자동으로 추가한다. 따라서 문자 유발 소재가 어떤 언어로 적혀 있거나 합성어로 표현되어도, 실제 디자인에 그 소재를 사용하는 경우 같은 규칙이 적용된다.

- 소재의 형태와 질감만 사용하고 종이·표지·판면 등 모든 내부 표면을 완전히 비운다.
- 메타데이터에서 지정한 제목과 작가명만 예외로 허용한다.
- 그 밖의 필기·서명·활자·숫자·기호·유사 문자·가짜 텍스트를 금지한다.

이 조건은 파생 프롬프트를 손으로 고쳐 넣는 규칙이 아니다. 브리프가 바뀌었다면 `표지_브리프.json`을 수정한 뒤 `prepare`를 다시 실행한다.

## 2단계 — 7개 이미지 독립 생성

1. `표지/프롬프트/A.txt`부터 `G.txt`까지 각각을 내장 이미지 생성 도구에 **별도 호출**로 전달한다. 여러 스타일을 한 프롬프트의 `n`개 변형으로 요청하지 않는다.
2. 각 호출은 새 이미지 생성이다. 시안 사이에 이전 이미지를 스타일 기준으로 넘기지 않는다. A–G가 같은 구도나 렌더링 방식으로 수렴하는 것을 막기 위함이다.
3. 생성 직후 해당 이미지를 시각적으로 확인한다. 문자 유발 소재가 있는 시안은 제목·작가명 외에 읽을 수 없는 낙서, 장식용 가짜 활자, 숫자나 서명처럼 보이는 흔적까지 없는지 확인한다. 합격한 결과만 프로젝트의 `표지/<ID>.png`로 복사하거나 이동한다. 프로젝트가 참조할 최종 이미지를 이미지 도구의 기본 저장 위치에만 남겨 두지 않는다.
4. 동시에 실행할 수 있으면 독립 호출을 병렬화할 수 있지만, 각 결과의 ID와 프롬프트가 뒤섞이지 않게 한다.
5. 7개 중 일부가 이미 있고 현재 프롬프트·검수를 통과한다면 재개 시 해당 파일을 다시 만들지 않고 누락되거나 실패한 ID만 생성한다.

별도 이미지 출력을 지원하는 현재 기본 환경에서는 디자인 보드로 합치지 않는다. 단일 이미지밖에 출력할 수 없는 별도 환경을 사용해야 한다면, A–G가 붙거나 겹치지 않는 동일 크기 패널로 배열하고 라벨은 표지 바깥에만 둔 보드를 만들 수 있다. 이 예외 산출물은 현재 개별 파일 검증 게이트와 ZIP 표준 산출물을 대신하지 않으므로, 사용자가 보드만으로 완료해도 된다고 확인한 경우에만 사용한다.

## 3단계 — 구조 검증과 시각 검수

먼저 파일 구조, 크기, 비율, 중복 여부를 확인한다.

```powershell
py -3 ..\표지_시안_준비.py validate --meta .\메타데이터.json --brief .\표지_브리프.json --output-dir .\표지 --structural-only
```

그다음 A–G 이미지를 각각 원본 해상도로 열어 다음 항목을 확인한다.

- `textExact`: 제목과 작가명이 정확하며 다른 문구가 없음
- `frontCoverOnly`: 앞표지만 있고 목업·책등·뒷표지·바코드·로고·손·바깥 배경이 없음
- `styleMatch`: 해당 A–G 스타일 사양과 작품 내용이 모두 반영됨
- `legible`: 제목과 작가명이 비주얼에 가려지지 않고 축소 화면에서도 읽힘
- `publicationReady`: 스케치가 아닌 실제 출판 표지 수준의 균형·디테일·완성도

각 시안의 `imageSha256`에는 검수한 `표지/<ID>.png`의 SHA-256, `promptSha256`에는 대응하는 `표지/프롬프트/<ID>.txt`의 SHA-256을 기록한다. 검수 뒤 이미지나 프롬프트가 한 바이트라도 바뀌면 전체 검증이 실패하므로 새 파일을 다시 열어 확인하고 해시와 판정을 갱신한다.

세트 전체에서는 다음을 확인한다.

- `visuallyDistinct`: 색상만 바꾼 변형이 아니라 스타일·타이포그래피·색·구도·시점·밀도·분위기·표현 방식이 확실히 다름
- `noExtraTextAcrossSet`: 7개 모두 제목과 작가명 외의 글자가 없음

검수 결과를 `표지/표지_검수.json`에 기록한다.

```json
{
  "schemaVersion": 1,
  "variants": {
    "A": {"textExact": true, "frontCoverOnly": true, "styleMatch": true, "legible": true, "publicationReady": true, "imageSha256": "<A.png SHA-256>", "promptSha256": "<A.txt SHA-256>", "notes": ""},
    "B": {"textExact": true, "frontCoverOnly": true, "styleMatch": true, "legible": true, "publicationReady": true, "imageSha256": "<B.png SHA-256>", "promptSha256": "<B.txt SHA-256>", "notes": ""},
    "C": {"textExact": true, "frontCoverOnly": true, "styleMatch": true, "legible": true, "publicationReady": true, "imageSha256": "<C.png SHA-256>", "promptSha256": "<C.txt SHA-256>", "notes": ""},
    "D": {"textExact": true, "frontCoverOnly": true, "styleMatch": true, "legible": true, "publicationReady": true, "imageSha256": "<D.png SHA-256>", "promptSha256": "<D.txt SHA-256>", "notes": ""},
    "E": {"textExact": true, "frontCoverOnly": true, "styleMatch": true, "legible": true, "publicationReady": true, "imageSha256": "<E.png SHA-256>", "promptSha256": "<E.txt SHA-256>", "notes": ""},
    "F": {"textExact": true, "frontCoverOnly": true, "styleMatch": true, "legible": true, "publicationReady": true, "imageSha256": "<F.png SHA-256>", "promptSha256": "<F.txt SHA-256>", "notes": ""},
    "G": {"textExact": true, "frontCoverOnly": true, "styleMatch": true, "legible": true, "publicationReady": true, "imageSha256": "<G.png SHA-256>", "promptSha256": "<G.txt SHA-256>", "notes": ""}
  },
  "setChecks": {"visuallyDistinct": true, "noExtraTextAcrossSet": true}
}
```

한 항목이라도 실패하면 해당 ID만 다시 생성한다. 재생성 프롬프트에는 원래 프롬프트 전체와 함께 실패한 한 가지 문제를 구체적으로 고치는 지시를 추가하고, 나머지 조건을 반복해 고정한다. 제목·작가 오탈자를 사후에 검수 파일만 `true`로 바꿔 통과시키지 않는다.

수정이 끝나면 전체 검증을 실행한다.

```powershell
py -3 ..\표지_시안_준비.py validate --meta .\메타데이터.json --brief .\표지_브리프.json --output-dir .\표지
```

## 4단계 — 최종 인제스트와 보관

표지 전체 검증을 통과한 뒤에만 `번역_하네스.md`의 최종 변환을 실행한다. `인제스트_변환.py`도 JSON을 쓰기 직전에 표지 전체 검증을 다시 실행하며, 실패하면 `ingest.json`과 ZIP을 만들지 않는다. 제목 기반 ZIP에는 `표지_브리프.json`, A–G 최종 이미지·프롬프트·시안 목록·검수 기록만 포함되고 `표지/작업/`과 허용 목록 밖 파일은 포함하지 않는다.

- 표지 브리프를 어떤 번역·리뷰 근거로 정리했는지
- A–G 7개 생성 여부와 각 파일 경로
- 구조 검증 결과(개수, PNG 디코딩 무결성, 해상도, 2:3 비율, 중복 없음)
- 시각 검수 결과(정확한 텍스트, 스타일 구분, 앞표지 전용, 가독성, 출판 완성도)
- 사용한 생성 경로(기본 내장 이미지 도구 또는 사용자가 확인한 CLI/API 경로)
- 최종 ZIP에 표지 산출물이 포함됐는지

## 금지 사항

- 7개 스타일을 한 프롬프트의 단순 변형으로 생성하는 것
- 색상만 바꾼 결과를 서로 다른 시안으로 승인하는 것
- 제목·작가명 오탈자 또는 추가 문구가 있는 이미지를 승인하는 것
- 이미지 생성 실패를 빈 파일, 복사본, 플레이스홀더, 디자인 보드로 위장하는 것
- 기존 출간 표지나 특정 작가의 작품을 모방하도록 지시하는 것
- 내장 이미지 도구 실패 시 사용자 확인 없이 CLI/API/다른 모델로 전환하는 것
- 검수 기록 없이 7개 파일의 존재만으로 완료를 선언하는 것
