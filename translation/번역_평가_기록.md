# 번역 평가 기록

[번역 평가 기준](번역_평가_기준.md) `1.0`으로 판정한 최종 번역의 기록을 양식 버전 `1`로 보존한다. 기준에 따라 원문 질문과 평가 근거를 만들고, 이 문서에 따라 집계할 필드를 작성한다.

## 평가 입력과 실행 기록

1. 비교에 사용할 질문을 원문만 보고 미리 정한다. 사실·문학 특성 질문을 각각 하나 이상 만들고, 같은 질문 묶음에는 후보 간 동일한 `question_set_id`를 부여한다. 문항과 범위를 바꾸면 새 ID를 부여한다.
2. 최종 평가를 시작할 때 원문·번역 파일·공통 가이드의 SHA-256과 실제로 적용한 원문 파싱 규칙을 고정한다. 원문 색인을 사용하면 색인의 SHA-256을 기록하고, 장 제목 정규식으로 나누면 실제 정규식 문자열을 기록한다. 번역 파일 경로는 최종 변환 CLI와 같은 장 순서로 나열한다. 해시는 실제 파일 바이트를 기준으로 구한다. Windows에서는 `Get-FileHash -Algorithm SHA256`, macOS/Linux에서는 `shasum -a 256`을 사용할 수 있다.
3. 평가자 두 명에게 같은 원문·번역·문맥·질문·문체 방침을 제공하고 서로의 판정과 번역 모델명을 가린다. 재검토자는 두 결과의 대응 위치·인용·문맥과 이견을 확인해 최종 판정을 작성한다. 결함을 수정하면 영향을 받은 항목과 구조를 다시 검사하고, 새 버전의 파일을 평가 입력에 연결한다. 최신 파일 해시만 채워서 이전 판정을 재사용하지 않는다.
4. 각 번역·수정·평가·재검토 실행이 끝날 때 실제 모델 식별자, 역할, 장·문단 범위, 사용 방식, 확인 근거를 인계한다. 실행 도구 응답, 실제 실행 설정 또는 해당 실행에서 확인한 표시를 근거로 삼는다. 역할명이나 상위 작업의 기본 모델로 추정하지 않는다. 확인할 수 없으면 식별자는 `null`로 남기고 사유를 쓴다. 혼합 모델 작업은 각 실행과 담당 범위를 기록한다. 인증 정보나 비공개 로그 원문은 보고서에 담지 않는다.

## 최종 평가 JSON 작성

평가 내용을 책 폴더의 `작업/번역_평가.json`에 UTF-8 JSON으로 작성한다. 다음 표의 필드는 보고서 생성기의 입력 계약이다.

| 필드 | 값과 작성 규칙 |
|---|---|
| `schema_version`, `rubric_version` | 각각 숫자 `1`, 문자열 `"1.0"` |
| `evaluation_id`, `evaluated_at` | 평가를 식별하는 문자열, 시간대가 포함된 ISO 8601 평가 시각 |
| `book_title`, `source_language`, `source_edition` | 도서 제목, 원문 언어 태그, 사용한 판본·출처 |
| `translation_method` | 직접 번역의 수행 방식. 장·청크 병렬 또는 순차, 수정 방식 등 실제 조건을 기록한다. |
| `scope` | `kind`는 `full` 또는 `sample`. `evaluated_paragraphs`는 실제 평가한 문단 수, `total_paragraphs`는 최종 변환 대상 전체 문단 수다. `description`에 장·문단 범위와 제외 범위를 적는다. 전권 평가이면 두 수가 같다. |
| `inputs` | `source`, `translations`, `style_guide`와 파싱에 사용한 `source_index` 또는 `chapter_pattern`을 기록한다. |
| `question_set_id`, `questions` | 고정 질문 묶음 식별자와 최종 문항 기록 배열 |
| `defects` | 최종 확정 결함 배열. 결함이 없으면 빈 배열이다. |
| `runs` | 모델과 실행 조건을 기록한 배열 |
| `revisions`, `limitations` | 반영한 수정과 범위·판정의 한계를 각각 문자열 배열로 기록한다. 해당 사항이 없으면 빈 배열이다. |

**입력 파일**은 `{"path": "번역본/01_제목.md", "sha256": "..."}` 형태다. `path`는 책 폴더 기준 상대 경로이며 슬래시 `/`를 사용한다. `sha256`은 파일 바이트의 소문자 64자리 16진수 해시다. PowerShell의 해시 출력은 소문자로 바꿔 기록한다. `source`는 실제 `--original` 입력을 가리키며 `../` 경로를 허용한다. `translations`는 `번역본/` 안에 있는 장별 Markdown 전부를 변환 CLI에 넘길 순서대로 기록한 배열이다. `style_guide`의 경로는 `번역_공통_가이드.md`다.

**원문 파싱 규칙**은 실제 평가에서 사용한 방식에 맞춰 기록한다. `--source-index`를 사용하면 `source_index`에 색인 파일 경로와 해시를 기록하고 `chapter_pattern`을 생략한다. 정규식으로 장을 나누면 `chapter_pattern`에 실제 `--chapter-re` 값을 기록하고 `source_index`를 생략한다. 기본 정규식은 `^[IVXLCDM]+\.\s+\S`다. JSON 문자열 안에서는 역슬래시를 이스케이프하므로 기본값은 `"^[IVXLCDM]+\\.\\s+\\S"`로 쓴다. 최종 변환에는 평가와 동일한 규칙을 사용한다.

**문항**은 `id`, `kind`, `criterion`, `status`, `prompt`, `reason`, `location`, `source_quote`, `translation_quote`, `defect_ids`를 가진다. `kind`는 공통 `common`, 작품별 사실 `fact`, 작품별 문학 특성 `literary` 중 하나다. 공통 기준을 25개 코드별로 하나씩 기록하고, `fact`와 `literary` 문항을 각각 하나 이상 둔다. `id`는 중복될 수 없다. `criterion`은 A1~G2의 실제 기준 코드 중 하나이며 `status`는 `P/E/U/NA/NO` 중 하나다. `prompt`에 확인할 조건, `reason`에 최종 근거와 필요한 경우 허용 변이·핵심 효과를 적는다. P/E는 대응 위치와 인용을 남긴다. E의 번역 인용이 비어 있는 누락은 그 위치·주변 근거를 기록한다. U/NA/NO는 가능한 근거와 사유를 남기고 해당하지 않는 인용 필드는 빈 문자열로 기록할 수 있다. E의 `defect_ids`는 실제 결함 ID를 하나 이상 참조하고 다른 상태는 빈 배열을 사용한다.

**공통 문항**의 상태는 평가 범위에서 해당 코드의 최종 상태를 뜻한다. 같은 주코드의 확정 결함이 하나라도 있으면 공통 문항을 E로 기록하고 그 코드의 모든 고유 결함 ID를 연결한다. 작품별 `fact`·`literary` 문항은 각각의 관찰 조건을 판단하므로 같은 코드의 공통 상태가 E여도 해당 조건을 보존했다면 P로 기록할 수 있다. `scope.kind`가 `sample`이면 전권 일관성인 G2 공통 문항은 NO로 기록한다.

**결함**은 `id`, `criterion`, `severity`, `description`, `source_quote`, `translation_quote`, `locations`를 가진다. `severity`는 `major`, `minor`, `unresolved` 중 하나다. 위치 목록과 원문·번역 인용을 기록하고, 누락이면 번역 인용을 비워 두고 대응 위치를 남긴다. 여러 질문이 같은 결함을 가리켜도 한 ID로 기록한다. 고정 질문 밖에서 발견한 결함도 기록할 수 있다. 수정하여 사라진 결함은 `revisions`에서 설명한다.

**실행**은 `run_id`, `role`, `scope`, `method`, `model_id`, `model_evidence`, `unknown_reason`을 가진다. 역할은 번역 `translate`, 수정 `revise`, 평가 `evaluate`, 최종 재검토 `adjudicate` 중 하나다. 번역과 재검토 각 한 번 이상, 서로 독립된 평가 두 번 이상을 서로 다른 `run_id`로 기록한다. `scope`에 책·장·문단 범위를, `method`에 실제 번역 또는 평가 방식을 적는다. 모델을 확인했으면 `model_id`와 `model_evidence`를 적고 `unknown_reason`은 `null`로 둔다. 미확인 모델에는 `model_id: null`, `unknown_reason`에 사유를 기록한다. 이 경우 `model_evidence`는 빈 문자열을 허용한다.

## 보고서 생성·보존

책 폴더에서 실행한다. Windows에서는 `py -3 ..\번역_평가_보고서.py`를 사용한다.

```bash
python3 ../번역_평가_보고서.py 작업/번역_평가.json --output 번역_평가_결과.md
```

생성기는 입력 JSON에서 사람이 읽는 결과와 집계용 JSON 블록을 함께 만든다. `--output`으로 저장 위치를 지정할 수 있으며 파일명은 `번역_평가_결과.md`로 고정한다. 입력과 출력 경로가 충돌하면 생성을 중단한다. 변환기는 생성된 본문과 집계용 데이터의 일치를 검사하므로 보고서를 직접 편집하지 않는다. 별도의 총점이나 집계 필드를 적지 않고, 수정할 내용이 있으면 평가 기록을 정정해 보고서를 재생성한다. 새 최종 변환은 이 보고서를 검증하고 ZIP 루트에 동일한 바이트로 넣는다. 이후 통계에는 ZIP의 `번역_평가_결과.md` 안에 있는 JSON 블록을 사용한다.

## 집계와 완료 보고

- 공통 항목과 작품별 사실·문학 특성 질문의 P/E/U/NA/NO 개수를 구분한다. 확정 결함은 주코드와 중대·경미·심각도 유보별로 고유 ID를 한 번씩 집계한다.
- 작품별 고정 질문의 적용 분모는 `T=P+E+U+NO`다. `T>0`이고 `NO=0`일 때만 위반 질문 비율을 `E/T`에서 `(E+U)/T`까지로 제시한다. 실제 전체 번역 오류율이나 통계적 신뢰구간으로 해석하지 않는다.
- 모델이나 번역 방식을 비교할 때 동일한 원문·문맥·범위·질문 묶음·기준 버전을 사용하고 평가 전 후보의 모델명을 가린다. NA는 원문 특성의 유무에 따라 후보를 보기 전에 결정하고 모든 후보에 동일하게 적용한다. 평가 범위가 좁거나 미평가가 있으면 그대로 표시한다. 혼합 작업의 전권 지표를 한 모델에 귀속하지 않는다.

사용자에게 **평가 기준 버전과 평가 범위·전체 대비 문단 수**, **공통 및 작품별 질문 상태와 최종 고유 결함 수**, **대표 개선·보존 사례와 남은 유보·미평가**, **번역 방식과 역할별 실제 모델 또는 미확인**, **최종 Markdown·ZIP 경로와 보존 검증**을 보고한다. 같은 보고서에서 수치를 읽어 옮기고, 초안에서 수정한 결함은 최종 결함에서 뺀다. 완료가 보류되면 판단 근거와 필요한 후속 조치를 함께 제시한다.
