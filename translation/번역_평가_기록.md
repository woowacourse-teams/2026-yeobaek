# 번역 평가 기록

## 평가 입력 수집

[최종 품질 평가](번역_리뷰_지침.md#최종-품질-측정)에 들어가기 전에 책 폴더에서 실행한다. Windows에서는 `py -3 ..\번역_평가_보고서.py`를 사용한다.

```bash
python3 ../번역_평가_보고서.py 작업/번역_평가.json --capture-inputs --original 원문.txt --translations 번역본/01_제목.md
```

최종 변환에 사용할 원문과 번역 파일을 지정한다. 번역 파일이 여러 개면 최종 변환과 같은 장 순서로 모두 나열한다. 별도 원문 색인이나 장 구분 규칙을 사용하면 최종 변환과 같은 `--source-index` 또는 `--chapter-re`를 지정한다.

도구는 원문·번역·공통 가이드의 경로와 해시, 번역 파일 순서, 장 구분 규칙 또는 색인 경로와 해시를 `inputs`에 기록한다. 기존 기록이 있으면 덮어쓰지 않는다. 입력이 바뀌면 새 기록 파일에 수집하고 영향 범위를 다시 평가한다. 해시만 갱신해 이전 판정을 재사용하지 않는다.

## 평가 결과 작성

수집한 JSON에 평가 결과를 채운다. 작품별 사실과 문학 질문은 [평가 기준](번역_평가_기준.md#평가-준비)에 따라 원문만 보고 각각 하나 이상 준비한다. 질문 묶음과 범위가 같으면 비교 대상에 같은 `question_set_id`를 쓴다.

| 필드 | 기록할 내용 |
|---|---|
| `schema_version`, `rubric_version` | 숫자 `1`, 문자열 `"1.0"` |
| `evaluation_id`, `evaluated_at` | 평가 식별자와 시간대가 포함된 ISO 8601 시각 |
| `book_title`, `source_language`, `source_edition` | 도서 제목, 원문 언어 태그, 판본·출처 |
| `translation_method` | 장·청크 병렬 또는 순차, 수정 방식 등 실제 번역 방식 |
| `scope` | `kind`는 전권 `full` 또는 발췌 `sample`. `evaluated_paragraphs`와 `total_paragraphs`에 평가·전체 문단 수를 적고 `description`에 평가·제외 범위를 적는다. 전권 평가면 두 수가 같다. |
| `inputs` | 평가 시작 시 도구로 수집한 값 |
| `question_set_id`, `questions` | 질문 묶음 식별자와 아래 판정 목록 |
| `defects`, `runs` | 아래 결함 목록과 실행 모델 기록 |
| `revisions`, `limitations` | 반영한 수정과 평가 한계의 목록. 해당 사항이 없으면 빈 배열. |

- **공통 판정**은 25개 기준별로 `id`, `kind: "common"`, `criterion`, `status`를 하나씩 기록한다. 예를 들어 `{"id":"A1","kind":"common","criterion":"A1","status":"P"}`로 보존을 표시한다. U/NA/NO는 `reason`에 사유를 적는다. 확정 결함이 있는 주코드는 E로 표시하고 `defect_ids`에 그 코드의 결함 ID를 모두 연결한다. 발췌 평가에서 G2는 NO다.
- **작품별 질문**은 `kind`를 사실 `fact` 또는 문학 특성 `literary`로 지정하고 `id`, `criterion`, `status`, `prompt`, `reason`을 적는다. P이면 `location`, `source_quote`, `translation_quote`로 근거를 남긴다. E이면 `defect_ids`로 결함을 연결한다. 공통 판정과 작품별 질문의 ID는 서로 달라야 한다.
- **결함**은 같은 원인마다 한 건으로 묶고 `id`, 주코드 `criterion`, `severity`(중대 `major`, 경미 `minor`, 심각도 유보 `unresolved`), `description`, `locations`, `source_quote`, `translation_quote`를 적는다. 위치와 인용은 여기 한 번만 적고 각 E 판정에서 ID로 연결한다. 누락이면 번역 인용을 비우고 대응 위치를 적는다. 수정해서 사라진 결함은 `revisions`에 남긴다. 최종 결함이 없으면 `defects`를 빈 배열로 둔다.

## 실행 모델 기록

작업을 인계할 때 실행별 `run_id`, 역할 `role`, 담당 범위 `scope`, 실제 방식 `method`를 적는다. 번역(`translate`)과 평가(`evaluate`)는 각각 한 번 이상 기록한다. 수정(`revise`)과 별도 판정 재검토(`adjudicate`)는 수행한 경우 기록한다.

도구 응답이나 실제 실행 설정 등에서 확인한 모델을 `model_id`, 확인 근거를 `model_evidence`에 적고 `unknown_reason`은 `null`로 둔다. 확인할 수 없으면 `model_id`를 `null`, `model_evidence`를 빈 문자열로 두고 `unknown_reason`에 이유를 적는다. 기록에는 역할이나 기본 설정에서 추정한 모델과 인증 정보를 넣지 않는다.

## 보고서 생성과 ZIP 보존

```bash
python3 ../번역_평가_보고서.py 작업/번역_평가.json --output 번역_평가_결과.md
```

보고서는 사람이 읽는 판정과 집계용 JSON을 담는다. 내용이 바뀌면 평가 JSON을 고쳐 보고서를 다시 생성한다. 최종 변환기는 보고서와 현재 평가 입력의 일치를 확인하고, 중대 결함이 남아 있으면 변환을 중단한다. 검증된 보고서는 ZIP 루트에 넣는다. 부분 검증과 구형 인제스트 정규화에는 보고서가 필요 없다.

새 최종 ZIP에서 보고서가 로컬 보고서와 바이트 단위로 같은지, 원문·번역·공통 가이드·사용한 원문 색인의 해시가 보고서의 값과 같은지 대조한다. 평가 입력이 달라졌으면 영향 범위를 재평가한 뒤 보고서와 ZIP을 재생성한다.

## 집계와 완료 보고

사용자에게 기준 버전, 평가 범위와 전체 대비 문단 수, 공통·작품별 P/E/U/NA/NO 집계와 심각도별 고유 결함 수, 대표 개선·보존 사례와 남은 유보·미평가를 보고한다. 번역 방식과 역할별 실제 모델 또는 미확인 여부, 평가 보고서·ZIP 경로와 보존 검증 결과를 함께 제시한다. 보류하면 사유와 필요한 다음 조치를 적는다.

통계에는 보고서의 JSON을 사용한다. 작품별 적용 질문 수는 `T=P+E+U+NO`다. `T>0`이고 `NO=0`일 때만 위반 비율을 `E/T`부터 `(E+U)/T`까지 표시한다. 전체 번역 오류율이나 통계적 신뢰구간으로 해석하지 않는다.

모델·번역 방식을 비교할 때는 원문·문맥·범위·질문 묶음·기준 버전을 맞추고 평가자에게 번역 모델명을 가린다. NA는 후보를 보기 전에 원문을 기준으로 정한다. 한 결과에 여러 모델이 참여했으면 각 모델의 역할과 범위를 함께 해석한다. 판정 이견을 비교 분석에 반영해야 할 때는 독립 평가를 두 차례 진행하고 별도로 근거를 대조할 수 있다.
