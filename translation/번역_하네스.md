# 번역·인제스트 하네스

이 문서는 AI가 『The Memoirs of Sherlock Holmes』를 번역하여 서버 인제스트용 JSON을 생성하는 전체 절차를 정의한다. 이 하네스를 받은 AI는 아래 절차를 **순서대로, 검증 게이트를 통과하면서** 수행한다.

> 파이프라인: **번역 → 번역본 텍스트 생성(장 단위 .md) → 스크립트 파싱/검증 → ingest.json 생성**
> 파싱과 JSON 생성은 반드시 `인제스트_변환.py`가 수행한다. AI가 직접 JSON을 작성하지 않는다.

## 파일 배치

| 파일 | 역할 |
|---|---|
| `The Memoirs of Sherlock Holmes.txt` | 영문 원문 (Project Gutenberg #834) |
| `번역 지침.md` | 번역 스타일·구조 보존 규칙 — **번역 수행 시 이 지침 전체를 따른다** |
| `번역 리뷰 지침.md` | (선택) 번역 품질 리뷰 기준 |
| `메타데이터.json` | 도서 메타데이터 (title/publisher/publishedYear/authors) |
| `인제스트_변환.py` | 번역본 → JSON 변환 + 원문 문단 수 대조 검증 |
| `번역본/` | 장별 번역 결과물 저장 폴더 (`NN_제목.md`, 없으면 생성) |
| `ingest.json` | 최종 산출물 |

## 작업 절차

### 0단계 — 준비 및 재개 확인

1. `번역 지침.md`를 읽는다. 특히 `[4. 구조 보존 규칙]`은 인제스트 성패를 좌우하므로 반드시 준수한다.
2. `번역본/` 폴더를 확인한다.
   - 폴더가 없으면 생성하고 1번 장부터 시작한다.
   - 기존 파일이 있으면 부분 검증을 실행해 진행 상태를 파악한다:
     ```powershell
     py -3 .\인제스트_변환.py (Get-ChildItem .\번역본\*.md | Sort-Object Name).FullName --partial
     ```
   - 마지막 장의 문단 수가 표의 기대치보다 적으면 그 장이 중단된 것이다. 파일의 마지막 문단이 원문의 몇 번째 문단인지 대조해 확인하고, 다음 문단부터 이어서 번역한다.

### 1단계 — 장 단위 번역 루프 (장마다 반복)

1. 위 표의 라인 범위로 해당 장의 원문만 읽는다.
2. `번역 지침.md`에 따라 번역한다. 핵심 제약:
   - 원문에서 빈 줄로 구분된 문단 1개 = 번역문 문단 1개 (병합·분할 금지)
   - 문단 사이는 빈 줄 하나, 문단 내부는 줄바꿈 없이 이어 쓴다
   - 요약·생략·부연 금지, 사족(인트로/아웃트로) 금지
3. **긴 장은 나눠서 작업한다.** 한 번에 60~80문단씩 번역해 파일에 이어 붙인다(Write 후 이어서 추가). 몇 번째 문단까지 진행했는지 반드시 추적한다. 특히 11장(377문단)은 5~6회에 나눠 작업한다.
4. 장 하나가 끝날 때마다 부분 검증을 실행한다:
   ```powershell
   py -3 .\인제스트_변환.py (Get-ChildItem .\번역본\*.md | Sort-Object Name).FullName --partial
   ```
   - **통과** → 다음 장으로 진행한다.
   - **불일치** → 원문과 번역본을 대조해 빠졌거나 합쳐진 문단을 찾아 그 부분만 고친다. 장 전체를 다시 번역하지 않는다. 수정 후 재검증한다.

### 2단계 — (선택) 품질 리뷰

전체 번역 완료 후, 요청이 있는 경우에만 수행한다. `번역 리뷰 지침.md`에 따라 장별로 리뷰하고, 수정할 때도 문단 구조(1:1, 빈 줄 구분)는 그대로 유지한다. 수정 후 반드시 부분 검증을 다시 통과시킨다.

### 3단계 — 최종 변환 (JSON 생성)

12개 장이 모두 완료되면:

1. `메타데이터.json`의 값(제목·출판연도·작가·ISNI)이 채워져 있는지 확인한다. 미비하면 사용자에게 보고한다.
2. `--partial` 없이 실행해 `ingest.json`을 생성한다:
   ```powershell
   py -3 .\인제스트_변환.py (Get-ChildItem .\번역본\*.md | Sort-Object Name).FullName
   ```
3. 검증에 실패하면 지적된 항목을 고치고 재실행한다. **`--force`는 사용하지 않는다.**

### 4단계 — 완료 보고

다음을 보고한다: 장별 문단 수 검증 결과 요약, `ingest.json` 경로, 남은 수동 확인 사항(메타데이터, `/admin` 업로드는 사람이 수행 — `인제스트_지침.md` 5장 참고).

## 금지 사항

- AI가 ingest JSON을 직접 작성·수정하는 것 (반드시 스크립트 산출물 사용)
- `--force`, `--no-verify`로 검증을 우회하는 것
- 문단 수를 맞추기 위해 빈 문단이나 더미 텍스트를 넣는 것 (불일치는 반드시 번역 누락/병합을 찾아 해결)
- 원문 요약·축약 번역 (문단 수가 맞아도 내용이 줄었으면 실패다)
- `## 제목` 외의 마크다운 문법 사용
