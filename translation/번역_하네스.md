# 번역·표지·인제스트 하네스

이 문서는 AI가 원문 언어와 국가에 관계없이 저작권이 만료된 고전 문학을 한국어로 직접 번역하고 사전에 선정한 표지 한 종과 서버 인제스트용 JSON·ZIP을 만들고 팀 Chrome으로 업로드하는 전체 절차를 정의한다. 특정 도서나 언어에 종속되지 않으며, 책마다 이 하네스를 그대로 재사용한다. 이 하네스를 받은 AI는 사용자가 단순히 "지침에 따라 번역해줘"라고만 요청해도 아래 절차를 **필수 파이프라인**으로 해석하고, 검증 게이트를 통과하면서 수행한다.

> 파이프라인: **장 정보 파악 → 공통 번역 계약 수립 → 병렬 번역 → 장별 병합/구조 검증 → 필수 리뷰/수정 → 책 소개 초안 작성·검토 → 문장 분리·재결합 검증 → 표지 1종 사전 선정·제작·검수 → ingest.json 생성 → 보관용 ZIP 검증 → 팀 Chrome 관리자·Drive 업로드**
> 파싱과 JSON 생성은 반드시 `인제스트_변환.py`가 수행한다. AI가 직접 JSON을 작성하지 않는다.

## 파일 배치

공통 파일은 `translation/` 루트에, 책별 파일은 `translation/<책 폴더>/` 아래에 둔다.

**공통 (`translation/`)**

| 파일 | 역할 |
|---|---|
| `AGENTS.md` | 이 디렉터리에서 AI 에이전트를 열었을 때 자동 적용되는 작업 규칙 |
| `번역_하네스.md` | 이 문서 — 전체 작업 절차 |
| `번역_지침.md` | 번역 스타일·구조 보존 규칙 — **번역 수행 시 이 지침 전체를 따른다** |
| `번역_리뷰_지침.md` | 필수 번역 품질 리뷰 기준 |
| `책_소개_지침.md` | 번역 리뷰 후 소개 초안 작성·검토와 운영자 인계 기준 |
| `업로드_지침.md` | 검증 완료본의 팀 Chrome 관리자·Drive 업로드와 증거·중복·장애 처리 |
| `표지_하네스.md` | 리뷰 완료 후 표지 브리프·1종 사전 선정·이미지 제작·검수 절차 |
| `표지_시안_준비.py` | 표지 브리프 검증 + 선택 시안 프롬프트 준비 + 최종 이미지 검증 |
| `인제스트_변환.py` | 원문 장 정보 출력 + 번역 문단의 문장 분리 + `passages[].sentences[].content` JSON 변환 + 문단 수·문장 재결합 검증 + 보관용 ZIP 생성 |

**책별 (`translation/<책 폴더>/`)** — 예: `translation/셜록_홈즈의_회상록/`

| 파일 | 역할 |
|---|---|
| `원문.txt` | 번역 대상 언어의 원문 (Project Gutenberg 텍스트 등). 파일명은 자유 |
| `메타데이터.json` | 도서 메타데이터 (title/publisher/publishedYear/authors[].name/isni) |
| `장_정보.md` | 0단계에서 생성하는 장별 작업 계획표 |
| `번역_공통_가이드.md` | 병렬 번역자가 공유하는 언어 공통 코어와 원문 언어별 번역 프로필 |
| `번역본/` | 장별 번역 결과물 저장 폴더 (`NN_제목.md`) |
| `책_소개.txt` | 번역 리뷰 후 AI가 작성하는 소개 초안. 최종 JSON에 반영하고 독립 검토 후 팀 Chrome으로 등록 |
| `리뷰/` | 장별 리뷰 보고서 저장 폴더 (`NN_제목_리뷰.md`) |
| `작업/` | 긴 장을 문단 범위로 쪼갠 임시 청크, 병합 전 작업물 |
| `표지_브리프.json` | 전체 작품을 분석한 장르·요약·키워드·시각 소재·독자층·금지 요소 |
| `표지/` | 선택한 1종 이미지·프롬프트, 시안 목록, 시각 검수 기록 |
| `ingest.json` | 최종 산출물 |
| `책이름.zip` | 원문·번역·리뷰·표지·인제스트 보관용 표준 산출물 묶음. 예: `오만과_편견.zip` |

아래 명령은 모두 **책 폴더에서 실행**하는 기준으로 적는다. (macOS/Linux는 `python3 ../인제스트_변환.py`, Windows는 `py -3 ..\인제스트_변환.py`)

## 작업 절차

### 0단계 — 책 준비 및 장 정보 파악

1. `번역_지침.md`를 읽는다. 특히 `[4. 구조 보존 규칙]`은 인제스트 성패를 좌우하므로 반드시 준수한다.
2. 책 폴더에 원문 `.txt`가 있는지 확인한다. 없으면 사용자에게 요청한다.
3. 출처 메타데이터가 선언한 언어와 실제 원문을 대조해 원문 언어를 식별한다.
   - `장_정보.md`와 `번역_공통_가이드.md`에 BCP 47 태그와 한국어 언어명을 함께 기록한다. 예: `fr — 프랑스어`, `de — 독일어`, `zh-Hant — 중국어(번체)`.
   - 출처의 선언값과 실제 텍스트의 식별 결과가 일치하면 그대로 진행한다. 둘이 다를 때만 판본이나 파일 선택이 맞는지 확인한다.
   - 특정 언어의 허용 목록을 만들거나 비영어 원문을 차단하지 않는다. 식별된 모든 언어는 해당 원문에서 한국어로 직접 번역하며, 사용자가 별도로 요청하지 않는 한 영어 중간 번역본을 만들거나 영어를 거치지 않는다.
4. 원문의 장 제목·라인 범위·문단·문자·추정 토큰 수와 권장 청크를 스크립트로 파악한다:
   ```bash
   python3 ../인제스트_변환.py --list-chapters --original 원문.txt
   ```
   - 스크립트의 기본 장 제목 패턴은 열 0에서 시작하는 로마숫자 형식(`I. 제목`)이다. 출력된 장 수·제목이 실제 목차와 다르면, 원문에서 장 제목이 어떤 형식인지 확인하고 `--chapter-re`로 패턴을 지정한다. 예: 영어 `--chapter-re '^CHAPTER [IVXLCDM]+'`, 프랑스어 `--chapter-re '^CHAPITRE [IVXLCDM]+'`, 독일어 `--chapter-re '^KAPITEL [0-9IVXLCDM]+'`. 언어별 패턴은 파싱 규칙일 뿐 지원 여부를 판정하는 게이트가 아니다.
   - **`--chapter-re`를 지정했다면 이후 모든 검증·변환 명령에도 동일한 패턴을 붙인다.**
   - 기본 권장 청크는 150문단, 24,000자, 추정 8,000토큰 중 먼저 한도에 닿는 **문단 경계**에서 나눈다. 단일 문단만으로 한도를 넘으면 그 문단 하나를 독립 청크로 둔다. 문단 내부를 분할하지 않는다.
   - 책의 문체·문자 체계·작업 환경에 맞춰 한도를 조정할 때는 다음 옵션을 사용한다:
     ```bash
     python3 ../인제스트_변환.py --list-chapters --original 원문.txt \
       --max-chunk-paragraphs 120 \
       --max-chunk-characters 20000 \
       --max-chunk-estimated-tokens 7000
     ```
5. 출력 결과를 바탕으로 `장_정보.md`를 작성한다. 형식:
   ```markdown
   # 장 정보 — <도서 제목>

   원문: 원문.txt
   원문 언어: fr — 프랑스어
   언어 확인: 출처 선언 fr / 실제 텍스트 식별 fr / 일치
   장 제목 패턴: (기본 | --chapter-re '...')
   청크 한도: 150문단 / 24,000자 / 추정 8,000토큰

   | # | 원제 | 원문 라인 | 문단 수 | 문자 수 | 추정 토큰 | 권장 청크 | 파일명 |
   |---|---|---|---:|---:|---:|---|---|
   | 1 | I. Un cœur simple | 64–1226 | 231 | 31,420 | 7,980 | p001–p150, p151–p231 | `번역본/01_순박한 마음.md` |
   | ... |
   ```
   - 파일명의 한국어 제목은 AI가 번역해 정하되, `NN_` 접두사는 반드시 붙인다(병합 순서를 결정한다). 번역 과정에서 더 나은 제목이 생기면 바꿔도 된다.
   - 파일 첫 줄의 `## 제목`은 **원문의 장 번호 표기(로마숫자 등)를 유지**한 한국어 제목으로 쓴다. 예: `## I. 실버 블레이즈`, `## 제1장 토끼 굴 속으로`
6. `번역_공통_가이드.md`를 작성한다. 병렬 번역자는 이 파일을 읽기 전에는 번역을 시작하지 않는다. 모든 언어에 적용하는 **공통 코어**와 이 책의 **원문 언어별 프로필**을 분리하며, 최소한 다음 항목을 포함한다.
   - 원문 언어: BCP 47 태그, 한국어 언어명, 출처 선언값과 실제 텍스트 식별 결과
   - 공통 코어: 서술자 문체와 전체 톤앤매너, 등장인물 한국어 표기와 존대/반말 관계, 반복 용어, 장 제목 원칙, 대화체 예시, 금지 표현, 미정 항목과 결정권자
   - 언어별 프로필: 원문 언어의 문법, 호칭 체계, 시제·상, 문장부호, 고유명사 표기, 방언·시대어를 한국어로 옮기는 원칙
   - 직접 번역 원칙: 해당 원문 언어에서 한국어로 바로 번역하며 영어 피벗을 사용하지 않음
   최종 변환기가 확인할 수 있도록 다음 표기와 절 제목을 그대로 사용한다.
   ```markdown
   # 번역 공통 가이드 — <도서 제목>

   원문 언어: fr — 프랑스어
   번역 경로: fr 원문 → 한국어 직접 번역

   ## 공통 코어

   ...

   ## 원문 언어별 프로필

   ...
   ```
   병렬 작업 중 충돌이 발견되면 각 작업자가 임의로 고치지 않고 코디네이터에게 보고한다. 코디네이터는 `번역_공통_가이드.md`를 갱신한 뒤 영향받는 장을 일괄 정리한다.
7. `메타데이터.json`이 없으면 아래 형식으로 생성한다. `authors[].isni`는 서비스에서 작가를 식별하는 필수값이다:
   ```json
   {"title": "", "publisher": "", "publishedYear": 0, "authors": [{"name": "", "isni": ""}]}
   ```
   메타데이터가 파일·사용자 메시지에 없으면 다음 순서로 처리한다.
   - 원문 표지·저자 표기, Project Gutenberg 등 원문 출처와 도서관/서지 데이터를 조회해 제목·작가·출판연도·출판사 후보를 추론한다.
   - **ISNI는 가능한 한 국립중앙도서관 ISNI-KOREA(<https://www.nl.go.kr/isni/>)에서 가장 먼저 검색·검증한다.** 검색 결과의 인물 상세 화면에서 이름뿐 아니라 생몰년, 다른 이름, 직업·활동 분야, 외부 권위 식별자를 원문의 저자 정보와 대조한다. 확인한 상세 화면 URL(예: `https://www.nl.go.kr/isni/0000000121441305`)을 출처로 기록한다.
   - ISNI-KOREA에 레코드가 없거나 동명이인·중복 식별자 때문에 판별할 수 없을 때에만 ISNI 국제기구, 국가도서관 권위 레코드, VIAF·LC 등 다른 신뢰할 수 있는 출처로 보완한다. 이 경우 ISNI-KOREA를 우선 사용할 수 없었던 이유와 보완 출처를 함께 기록한다.
   - 이름, 생몰년, 다른 이름, 직업·활동 분야, 연결된 외부 권위 식별자가 원문의 저자 정보와 일치해 한 인물로 유일하게 식별되면 별도의 사용자 확인 없이 해당 이름과 ISNI를 `메타데이터.json`에 확정한다.
   - 서로 다른 권위 출처가 복수 ISNI를 제시하면 임의로 하나를 선택하지 않는다. 각 후보의 연결 근거와 불확실성을 정리하고 추가 권위 출처로 교차 검증한다. 동명이인·복수 저자·번역자/편집자 구분을 포함해 끝내 한 인물로 유일하게 식별할 수 없으면 ISNI를 비워 둔 채 최종 변환하지 않고, 조사한 후보·출처·불확실성을 차단 사유로 보고한다. ISNI는 작가명만으로 임의 생성하거나 추측해서는 안 된다.
   - 완료 보고를 위해 메타데이터 조사 내역을 정리한다. 제목·출판사·출판연도·작가명·ISNI 각 필드의 최종값, 출처명과 URL, 값을 확정한 대조 근거를 기록하고, ISNI-KOREA를 우선 사용할 수 없었다면 그 이유와 보완 출처를 함께 기록한다. 사용자가 제공한 값은 `사용자 제공`으로 구분해 조사로 확정한 값과 섞지 않는다.
8. **재개 확인:** `번역본/` 폴더를 확인한다.
   - 폴더가 없으면 생성하고 1번 장부터 시작한다.
   - 기존 파일이 있으면 부분 검증을 실행해 진행 상태를 파악한다:
     ```bash
     python3 ../인제스트_변환.py 번역본/*.md --original 원문.txt --partial
     ```
     ```powershell
     py -3 ..\인제스트_변환.py (Get-ChildItem .\번역본\*.md | Sort-Object Name).FullName --original 원문.txt --partial
     ```
   - 마지막 장의 문단 수가 `장_정보.md`의 기대치보다 적으면 그 장이 중단된 것이다. 파일의 마지막 문단이 원문의 몇 번째 문단인지 대조해 확인하고, 다음 문단부터 이어서 번역한다.

### 복잡한 원문 구조 — 명시적 원문 색인

목차와 본문 표제가 같거나, 장 표제가 여러 줄이거나, 부·서문·헌시·후면부의
범위를 정규식 하나로 표현할 수 없으면 `--source-index 원문_색인.json`을 사용한다.
기본 정규식 파싱은 그대로 유지된다. 기존 책별 작업 색인은 자동으로 신뢰하거나
가져오지 않는다. 원문을 고치지 않고 아래 공통 형식으로 대응 범위를 작성한다.
이는 번역 인제스트 JSON 수작업 작성이나 문단 검증 우회가 아니다.

```json
{
  "version": 1,
  "sourceSha256": "원문 파일의 원본 바이트 SHA256 소문자 64자리",
  "chapters": [
    {"title": "I. 원문 표제와 부제", "paragraphs": [
      {"start": 8, "end": 9, "kind": "prose"},
      {"start": 11, "end": 12, "kind": "verse"}
    ]}
  ],
  "exclusions": [
    {"start": 1, "end": 2, "category": "toc", "reason": "본문과 중복된 목차"},
    {"start": 4, "end": 6, "category": "heading", "reason": "장 번호와 두 줄 표제"}
  ]
}
```

예시 행 번호는 형식 설명용이며 실제 파일 전체를 대조해 지정한다.
범위는 BOM을 제외하고 `splitlines()`로 센 원문 물리행의 **1-based 양끝 포함**이다.
원문 전체의 모든 비공백 행은 문단 또는 제외 구간에 정확히 한 번 포함되어야 한다.
범위 중복·순서 역전·누락·경계 초과·원문 해시 불일치는 실패한다. 장과 문단 배열,
제외 배열은 각각 원문 순서로 정렬한다. 문단 범위에 빈 줄을 넣거나 원문의 한
문단을 임의로 나눌 수 없다. 표제 등 바로 붙은 제외 행이 있는 경우만 명시적으로
제외한 뒤 남은 문단 범위를 지정한다. 문단 수·문자 수·토큰 추정은 항상 원문에서
다시 계산한다. `title`은 표제 메타데이터이며 본문 문단을 대신하지 않는다.

허용된 제외 분류는 `metadata`, `toc`, `heading`, `gutenberg`, `editorial`,
`end-marker`이며 각각 구체적 `reason`을 적는다. Gutenberg 표지 밖도 전체 원본의
일부이므로 분류한다. 헌사·헌시·작가 서문·삽입 운문 등 원작 부속본문을 편의상
제외하지 않는다. 번역할 부속본문은 별도 장 단위와 문단으로 포함한다.
산문은 `kind: prose`(생략 가능), 시행 보존이 필요한 문단은 `kind: verse`로 선언한다.
운문은 번역 문단 수뿐 아니라 원문과 번역의 행 수도 같아야 한다. 들여쓰기만으로
운문을 자동 판정하지 않으며 산문과 운문 구분·제외 타당성은 독립 원문 검토 대상이다.
한 문단 안에 운문과 산문이 함께 있으면 문단을 분할하지 않고 다음처럼 명시한다.

```json
{"start": 11005, "end": 11010, "kind": "mixed", "verseSpans": [
  {"start": 11005, "end": 11006, "translationStart": 1, "translationEnd": 2}
]}
```

`verseSpans`의 원문 범위는 절대 물리행, 번역 범위는 해당 번역 문단 안의 물리행이며
모두 1-based 양끝 포함이다. 각 운문 구간의 원문·번역 행 수는 같아야 하고 구간은
각각 문단 안에서 순서대로 겹치지 않아야 한다. 번역 구간은 실제 존재하는 비공백
행이어야 한다. `mixed`에는 비어 있지 않은 `verseSpans`와 운문 이외의 원문·번역 행이
각각 적어도 하나 필요하다. `prose`·`verse`에는 `verseSpans`를 넣지 않는다.
이 대응은 자동 추론하지 않으며 독립 검토자가 각 구간의 의미 대응을 확인한다.
혼합 문단을 `prose`로 선언해 운문 검증을 통과했다고 보고하지 않는다. 안전한 명시적
대응을 확정할 수 없으면 해당 형식 검증과 최종 패키징은 미해결로 남긴다.

목록·부분 검증·최종 변환 모두 같은 색인을 지정한다.

```bash
python3 ../인제스트_변환.py --list-chapters --original 원문.txt --source-index 원문_색인.json
python3 ../인제스트_변환.py 번역본/*.md --original 원문.txt --source-index 원문_색인.json --partial
python3 ../인제스트_변환.py 번역본/*.md --original 원문.txt --source-index 원문_색인.json --source-index-review 원문_색인_검토.json --meta 메타데이터.json
```

최종 변환에는 색인 작성자와 다른 검토자의 전수 대조 기록이 필요하다.
검토자는 원작 누락 여부, 표제·목차·편집물 구분, 문단 경계, 운문 선언을 확인하고
다음 기록에 실제 검토자와 근거 보고서 경로·검토 내용을 적는다.

```json
{
  "version": 1,
  "sourceSha256": "원문 원본 바이트 SHA256",
  "sourceIndexSha256": "검토한 색인 파일 원본 바이트 SHA256",
  "status": "pass",
  "reviewer": "독립 검토자 식별명",
  "evidence": "독립 전수검토 보고서 경로와 확인 내용"
}
```

변환기는 판정·해시·필수 기록 존재를 검증하며, 문자열만으로 검토자의 신원이나
독립성을 인증하지 않는다. 독립 검토 절차를 실제로 수행해야 한다. 색인 바이트가
바뀌면 다시 검토해야 한다. 목록·부분 검증에는 이 최종 검토 기록이 필요하지 않다.
색인 모드에서는 `--force`와 `--no-verify`를 사용할 수 없다. 최종 ZIP에 원문과 함께
사용한 색인·검토 기록을 `원문_검증/원문_색인.json`, `원문_검증/원문_색인_검토.json`으로
원본 바이트 그대로 보관한다. 색인 없이 기존 정규식 경로로 생성한 결과를 이 검증의
통과 결과로 보고하지 않는다.

### 1단계 — 병렬 번역 및 장별 구조 검증

기본값은 병렬 번역이다. 남은 장이 2개 이상이거나 긴 장을 여러 청크로 나눌 수 있으면, 사용 가능한 서브에이전트/작업 스레드를 활용해 독립 단위를 병렬로 진행한다. 단일 에이전트 순차 번역은 병렬 실행 수단이 없거나 사용자가 명시적으로 금지한 경우에만 허용한다.

1. 모든 번역 작업자는 `번역_지침.md`, `장_정보.md`, `번역_공통_가이드.md`를 읽고 자신에게 배정된 범위만 번역한다.
2. 분담 단위:
   - 장 단위 병렬화: 서로 다른 장은 각각 `번역본/NN_제목.md`에 작성한다.
   - 장 내부 청크 병렬화: `--list-chapters`가 제안한 범위에 따라 `작업/청크/NN_p001-p080.md`처럼 문단 범위를 명시한 임시 파일로 나눠 번역한 뒤, 코디네이터가 `번역본/NN_제목.md` 하나로 병합한다.
   - 청크는 기본 150문단, 24,000자, 추정 8,000토큰 중 먼저 한도에 닿는 문단 경계에서 끝낸다. 한 문단만으로 한도를 넘으면 그 문단을 독립 청크로 배정한다. CLI로 한도를 바꿨다면 `장_정보.md`에 실제 사용값을 기록한다.
   - 한 작업자에게 여러 개의 짧은 장이나 청크를 묶어 배정할 때도 `장_정보.md`의 문단·문자·추정 토큰 수를 합산하고, 합계가 같은 한도를 넘기 전에 다음 작업자 배정으로 끊는다. 문단 수가 적다는 이유만으로 긴 장 여러 개를 한 작업에 몰아주지 않는다.
3. 원문을 통째로 읽지 말고, `장_정보.md`의 라인 범위 또는 배정된 문단 범위로 필요한 원문만 읽는다.
4. `번역_지침.md`와 `번역_공통_가이드.md`에 따라 번역한다. 핵심 제약:
   - 원문에서 빈 줄로 구분된 문단 1개 = 번역문 문단 1개 (병합·분할 금지)
   - 문단 사이는 빈 줄 하나, 문단 내부는 줄바꿈 없이 이어 쓴다
   - 의미상 문장 끝에는 문맥에 맞는 종결부호를 사용하고, 문장 분리용 임의 표식·번호는 넣지 않는다
   - 요약·생략·부연 금지, 사족(인트로/아웃트로) 금지
5. 병렬 작업자가 호칭·고유명사·말투 충돌을 발견하면 번역 파일 안에서 독자적으로 새 규칙을 만들지 않는다. 코디네이터에게 충돌을 보고하고, 확정된 결정은 `번역_공통_가이드.md`에 반영한다.
6. 장 하나가 끝나거나 긴 장 청크가 병합될 때마다 부분 검증을 실행한다:
   ```bash
   python3 ../인제스트_변환.py 번역본/*.md --original 원문.txt --partial
   ```
   - 스크립트는 문단 수뿐 아니라 `passages[].sentences[]` 구조, 문장별 공백 여부·UTF-8 바이트 제한, 문장 재결합 불변식을 함께 검사한다. 문장 사이 공백과 개행은 앞 문장 `content` 끝에 보존되며, 배열을 순서대로 이으면 분리 전 문단과 완전히 같아야 한다.
   - 원문 언어에서 유래한 약어·축약·문장부호 때문에 한국어 문장 경계를 확정할 수 없다는 오류가 나오면 문맥에 맞는 한국어 또는 풀어 쓴 표현으로 바꾸거나 문장을 다시 표현한다. 임의 구분자나 번호를 삽입해 우회하지 않는다. 영어의 `p.m.`, `U.S.`, `Jr.`는 이 일반 원칙의 예시일 뿐이다.
   - **통과** → 다음 장으로 진행한다.
   - **불일치** → 원문과 번역본을 대조해 빠졌거나 합쳐진 문단을 찾아 그 부분만 고친다. 장 전체를 다시 번역하지 않는다. 수정 후 재검증한다.

### 2단계 — 필수 품질 리뷰 및 수정

전체 번역 완료 후 반드시 수행한다. 사용자가 리뷰를 별도로 요청하지 않아도 생략하지 않는다.

1. `리뷰/` 폴더를 만들고, `번역_리뷰_지침.md`와 `번역_공통_가이드.md`를 기준으로 장별 리뷰를 수행한다.
2. 리뷰도 병렬화할 수 있다. 단, 리뷰어는 번역자와 동일한 장을 셀프 승인하지 않으며, 원문과 번역문을 대조해 정확성·자연스러움·호칭·톤앤매너를 확인한다.
3. 리뷰 보고서는 `리뷰/NN_제목_리뷰.md`로 저장한다.
4. 지적 사항은 `번역본/`의 장 파일에 반영하되, 문단 구조(1:1, 빈 줄 구분)는 그대로 유지한다.
5. 리뷰어는 실제 문장 끝의 종결부호가 빠지지 않았는지, 원문 언어별 인용부호·괄호가 대응 문장에 포함되는지, 약어·축약·소수점·줄임표가 잘못된 한국어 문장 경계를 만들지 않는지 확인한다. 모호한 표현은 문맥에 맞는 한국어로 풀어 쓰거나 문장을 다시 표현해 변환 오류를 해소한다.
6. 수정 후 반드시 부분 검증을 다시 통과시킨다. 리뷰 과정에서 공통 호칭·용어 결정이 바뀌면 `번역_공통_가이드.md`를 갱신하고 영향받는 장을 다시 훑는다.

### 2-1단계 — 책 소개 초안 작성·검토

번역 리뷰와 수정을 마친 뒤 [책 소개 지침](책_소개_지침.md)에 따라 AI가 책 폴더의
`책_소개.txt`를 작성한다. 작품의 구체적인 내용과 읽을 매력을 담고 스포일러를 검토한다.
2~3문장은 작성 가이드이며 변환기가 정확한 문장 수를 강제하지 않는다. 본문 파일이나
`메타데이터.json`에는 초안을 따로 복사하지 않는다. 최종 변환기가 `책_소개.txt`의 내용을
`ingest.json.description`에 반영하며 소개 파일도 별도로 보존한다.

소개는 별도 검토자가 사실성·스포일러·한국어를 검토하고, 업로드 담당자가 JSON과 정확히 대조한다. 운영자 별도 검수 지시나 해결되지 않은 불확실성이 있으면 업로드를 보류한다. 운영자 검수 완료를 자동 기록하지 않는다.
수정이 필요하면 소개 파일을 고친 뒤 최종 변환을 다시 실행한다. 관리자 업로드는 JSON의 `description`만 사용한다. 승인 플래그나 자동 승인 기록은 만들지 않는다.

### 3단계 — 표지 1종 사전 선정·제작·검수

전체 번역의 리뷰 수정과 문단 재검증을 마친 뒤 `표지_하네스.md`의 전체 절차를 수행한다.

1. 최종 메타데이터, 번역본, 리뷰 보고서를 근거로 `표지_브리프.json`을 작성한다.
2. 팀 Chrome의 실제 저자 표기·시리즈 디자인을 확인하고, 작품 적합성을 비교해 A–G 중 한 방향을 이미지 생성 전에 선정한다. `표지_선정.md`에 근거를 남기고 별도 검토자가 확인한다.
3. `표지_시안_준비.py prepare --style <선정 ID>`로 선택 프롬프트만 준비하고 내장 이미지 생성 도구로 해당 PNG 한 개만 만든다. 실패 시 같은 시안을 교정하며 다른 여섯 이미지는 만들지 않는다.
4. 구조 검증 후 제작자와 별도의 검토자가 선택 원본 이미지와 프롬프트 전문을 직접 대조하고 `표지/표지_검수.json`에 현재 해시와 판정을 기록한다.
5. `표지_시안_준비.py validate` 전체 검증을 통과시킨다.

이미지 생성 도구를 사용할 수 없는 환경에서는 번역·리뷰 결과를 보존하고 표지 단계를 명시적 차단 사유로 보고한다. 사용자의 확인 없이 API·CLI 또는 다른 모델로 전환하거나, 빈 이미지·복사본·플레이스홀더를 만들어 통과시키지 않는다.

### 4단계 — 최종 변환 (JSON 생성)

모든 장과 선택 표지 한 종의 제작·독립 검수가 완료되면:

1. `메타데이터.json`의 값(제목·출판사·출판연도·작가명·각 작가의 ISNI)이 출처와 함께 채워져 있고, 각 작가의 이름과 ISNI가 한 인물로 유일하게 식별된 근거가 있는지 확인한다. ISNI가 없거나 해결되지 않은 후보 충돌·불확실성이 남아 있으면 최종 변환을 실행하지 말고, 조사한 후보·출처·불확실성을 차단 사유로 보고한다. 별도의 사용자 확인 여부는 최종 변환 조건으로 삼지 않는다. 변환기는 `장_정보.md`와 `번역_공통_가이드.md`가 존재하고 두 파일의 BCP 47 태그가 일치하는지, 언어 확인·공통 코어·원문 언어별 프로필·직접 번역 경로 기록이 있는지도 검증한다.
2. 책 폴더의 `책_소개.txt`가 비어 있지 않은 UTF-8 초안인지 확인한다. 새 최종 변환은 소개를 요구하며 소개 누락·공백·인코딩 오류·원문/메타데이터/출력 경로 충돌·책 폴더 밖을 가리키는 링크가 있으면 기존 JSON과 ZIP을 덮어쓰지 않는다. `--partial`과 `--normalize-legacy-ingest`에는 소개 파일이 필요 없다.
3. `표지_시안_준비.py validate`를 다시 실행해 최종 표지 파일과 검수 기록이 모두 현재 메타데이터·브리프에 대응하는지 확인한다. `인제스트_변환.py`도 JSON을 쓰기 직전에 같은 전체 검증을 자동으로 다시 실행하며, 실패하면 `ingest.json`과 ZIP을 만들지 않는다.
4. `--partial` 없이 실행해 `ingest.json`을 생성한다. 각 문단은 `{"sentences": [{"content": "..."}]}` 형태이며, 순서는 배열 등장 순서로 서버가 부여하므로 JSON에 `sequence`를 넣지 않는다:
   ```bash
   python3 ../인제스트_변환.py 번역본/*.md --original 원문.txt --meta 메타데이터.json
   ```
   ```powershell
   py -3 ..\인제스트_변환.py (Get-ChildItem .\번역본\*.md | Sort-Object Name).FullName --original 원문.txt --meta 메타데이터.json
   ```
5. 출력된 장·문단·문장 수와 문장 재결합 검증 결과를 확인한다. 문장 배열을 이어 붙인 값은 번역본의 해당 문단과 완전히 같아야 한다.
6. 검증에 실패하면 지적된 항목을 고치고 재실행한다. **`--force`는 사용하지 않는다.**
7. 스크립트는 `메타데이터.json`의 `title` 값을 파일명으로 바꿔 `책이름.zip`을 생성한다. 공백은 `_`로 바꾼다. 예: `"오만과 편견"` → `오만과_편견.zip`.
   - ZIP에는 **`--original`로 지정한 원문 파일**, `ingest.json`, `책_소개.txt`, 메타데이터, 장 정보, 공통 가이드, 번역본, 리뷰, 표지 브리프와 `표지/` 최종 산출물이 포함된다. `표지/작업/`은 제외된다.
   - 원문은 책 폴더 안팎의 위치와 관계없이 ZIP 내부 `원문/<원본 파일명>`에 저장한다. 예: `--original 원문.txt` → `원문/원문.txt`, `--original ../자료/pg123.txt` → `원문/pg123.txt`. 폴더의 다른 `.txt` 파일을 원문으로 추측하거나 추가하지 않는다.
   - 원문은 인코딩·BOM·줄바꿈을 변환하지 않고 파일 바이트 그대로 보존한다. 최종 변환에는 원문 파일이 필수이며, 파일이 없으면 원문이 빠진 ZIP을 만들지 않는다. ZIP 내부 경로가 다른 산출물과 충돌하면 덮어쓰지 않고 실패한다.
   - 완료 전에 ZIP의 원문 항목을 읽어 입력 원문과 바이트가 동일한지 확인한다.
8. 최종 보관 대상은 `책이름.zip`이다. 개별 파일도 남기되, 사용자에게는 ZIP을 표준 보관 파일로 안내한다. 제목과 다른 파일명이 필요할 때만 `--zip-output 원하는_파일명.zip`을 명시한다.

최종 변환은 `책_소개.txt`를 기준으로 `ingest.json.description`을 채운다. 앞뒤 공백은 제거하고
내부 개행은 유지하며 메타데이터의 소개보다 우선한다. ZIP에는 이 JSON과 원래 소개 파일을 함께 넣는다.
부분 검증과 구형 인제스트 정규화에서는 기존처럼 소개를 선택값으로 취급한다. 소개가 있다고 검수 완료로 간주하지 않는다.

### 5단계 — 독립 최종 검증과 팀 Chrome 업로드

원문 baseline·현재 ingest·ZIP·선택 표지 해시와 독립 검토 결과를 결속한다. ZIP 전체 CRC와 원문·번역·색인·검토 기록의 바이트 보존, 문단·운문·재결합, 소개 정확 일치, 서지·ISNI·대한민국 권리 근거를 대조한다. 실패한 제품은 업로드하지 않는다.

[업로드 지침](업로드_지침.md)의 전 절차를 수행한다. `yeobaek.team` 프로필 Chrome의 `yeobaek.team@gmail.com` 계정에서 관리자 https://yeobaek.duckdns.org/admin 에 ingest JSON과 선택 표지를 등록하고, 팀 Drive https://drive.google.com/drive/folders/1GGynmSzhA2BzogMkyzfJEON24u5G0skN 에 같은 검증 제품의 정식 ZIP을 보관한다. 한 업로드 담당자가 최신 서비스 목록과 장부로 중복을 방지한다. 브라우저 문제가 해결되지 않으면 사용자와 의논한다.

### 6단계 — 완료 보고

원문 언어·직접 번역 경로, 병렬 분담·장/문단/문장 수·재결합, 독립 리뷰·수정, 서지 각 필드의 최종값·출처 URL·대조 근거와 ISNI·권리 검증을 보고한다. 선택 표지 ID·사전 선정 이유·이미지/프롬프트·독립 검수와 현재 해시, 소개 경로·검토와 JSON 정확 일치, ingest·정식 ZIP·원문 바이트 보존 결과를 기록한다.

관리자 bookId·본문 수·소개·표지 확인, Drive 파일 ID·표시 크기와 로컬 크기·신규/버전 교체, 증거·장부 경로를 보고한다. 로컬 완료와 양쪽 업로드 완료를 구분하며 보류는 완료로 세지 않는다. 미해결 항목은 책별 사유·근거·필요 조치를 명시한다. 원격 파일 해시를 UI 확인만으로 검증했다고 주장하지 않는다.

소개 없는 과거 ZIP의 ingest JSON은 서버에 그대로 등록할 수 있다. 과거 작업을 새 변환기로 다시 생성할 때는 `책_소개.txt`를 보완한다. 최종 ZIP 생성은 운영자 검수 완료를 의미하지 않는다.

원문을 포함하지 않는 기존 ZIP은 자동으로 갱신되지 않는다. 해당 책의 검증에 사용한 원문을 `--original`로 지정해 4단계 최종 변환을 다시 실행하고, 원문 포함 여부를 확인한 새 ZIP을 보관한다.

## 기존 책 재검증 마이그레이션

이 언어 공통 계약과 조건부 무문자 프롬프트가 도입되기 전에 만든 책을 다시 변환할 때는 다음을 먼저 수행한다.

1. `장_정보.md`에 `원문 언어:`와 `언어 확인:` 줄을 추가한다.
2. `번역_공통_가이드.md`에 같은 원문 언어 태그, `번역 경로: <태그> 원문 → 한국어 직접 번역`, `## 공통 코어`, `## 원문 언어별 프로필`을 추가한다.
3. 기존 7종 제품의 재검증은 기존 계약을 보존한다. 새 1종으로 명시적으로 이관할 때만 선정 근거를 작성하고 `prepare --style <ID>`를 실행한다. 기존 파일은 보존하며 준비 명령이 입력을 바꾸면 기존 프롬프트 검수 해시는 만료된다.
4. 기존 7종 계약을 유지하면 A–G 전체를, 명시적 1종 이관이면 선택한 원본만 현재 프롬프트와 직접 대조한다. 이미지가 조건을 충족하면 유지하고 검수 해시·판정을 갱신하며 실패한 대상만 재생성한다.
5. 전체 표지 검증과 `인제스트_변환.py` 최종 변환을 다시 통과시킨다.

## 금지 사항

- AI가 ingest JSON을 직접 작성·수정하는 것 (반드시 스크립트 산출물 사용)
- 구형 `passages[].content` 형식으로 JSON을 생성하거나, 문장 배열에 `sequence`를 직접 넣는 것
- `--force`, `--no-verify`로 검증을 우회하는 것
- 문단 수를 맞추기 위해 빈 문단이나 더미 텍스트를 넣는 것 (불일치는 반드시 번역 누락/병합을 찾아 해결)
- 원문 요약·축약 번역 (문단 수가 맞아도 내용이 줄었으면 실패다)
- `## 제목` 외의 마크다운 문법 사용
- `장_정보.md` 없이 감으로 라인 범위를 추정해 번역을 시작하는 것
- `번역_공통_가이드.md` 없이 병렬 번역을 시작하는 것
- 리뷰 보고서 없이 최종 완료를 선언하는 것
- `표지_하네스.md`의 사전 선정·선택 표지 구조 검증·독립 시각 검수를 생략하는 것
- 표지 제목·작가 오탈자, 추가 문구, 목업, 중복 시안 또는 플레이스홀더를 승인하는 것
- `책이름.zip` 없이 여러 개별 파일만 최종 산출물로 안내하는 것
