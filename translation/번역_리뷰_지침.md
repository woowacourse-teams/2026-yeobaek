# 번역 리뷰 지침

장별 번역 작업과 독립된 리뷰어가 원문 언어에서 한국어 번역을 직접 대조한다. 배정된 원문과 앞뒤 문맥, 번역본, 공통 가이드, 작품별 질문을 준비한다.

## 장별 품질 리뷰와 수정

1. [번역 평가 기준](번역_평가_기준.md)의 25개 항목과 작품별 질문으로 해당 장을 검토한다. 원문의 관찰 조건과 핵심 효과를 확인한 다음 사실·의미, 문학적 기능, 한국어 표현을 대조한다. 작품별 문체 방침의 근거와 실제 번역의 적용을 각각 살핀다.
2. `리뷰/NN_제목_리뷰.md`에 평가 범위, 보존 사례, 확정 결함과 수정안, 유보·비해당·미평가와 그 사유를 기록한다. 결함은 위치, 원문·번역 인용, 위반 조건, 코드·심각도, 영향을 포함한다. 같은 원인으로 반복된 결함은 위치를 모은다. 중요한 결함이나 남은 불확실성을 사례 수 제한으로 생략하지 않는다.
3. 중대 결함이 확인되면 해당 구간과 영향을 받은 문맥을 원문에서 다시 번역한다. 경미한 결함은 해당 표현을 고친다. 공통 호칭·문체 변경이 여러 장에 영향을 주면 가이드를 먼저 갱신하고 해당 장에도 반영한다.
4. 수정한 범위와 주변 문맥을 해당 품질 기준으로 다시 평가하고 아래 구조 검증을 통과시킨다. 수정 내역은 이력으로 남긴다. 중대 결함이 남으면 최종 JSON·ZIP 생성과 업로드를 보류하고 필요한 조치를 보고한다.
5. 리뷰·수정 과정의 실제 사용 모델과 작업 범위는 [평가 기록 지침](번역_평가_기록.md#실행-모델-기록)에 따라 인계한다.

## 구조와 인제스트 검증

문학 품질 판정과 구별해 다음을 확인한다.

- 원문과 번역의 문단이 1:1로 대응하는지 확인한다. 문단을 합치거나 나누거나 누락하지 않는다.
- 실제 문장 끝에 종결부호를 두고, 약어·축약·소수점·줄임표·인용부호가 모호한 문장 경계를 만들지 않는지 확인한다. 변환기 오류가 나면 문맥에 맞게 풀어 쓴다.
- 닫는 따옴표·괄호와 문장 사이의 공백·개행이 보존되고, 각 문단의 `sentences[].content`를 순서대로 이었을 때 분리 전 문단과 같은지 검사한다.
- 장 제목의 `## 제목` 외에 마크다운 문법이나 AI 사족을 넣지 않는다. `인제스트_변환.py --partial`로 구조를 검증한다.

## 최종 품질 측정

장별 리뷰와 수정을 마치면 [현재 평가 입력을 기록](번역_평가_기록.md#평가-입력-수집)하고, 번역·수정 작업과 독립된 AI가 최종본을 한 차례 평가한다. 앞선 리뷰와 판정이 다르거나 판단 유보가 결과에 영향을 주면 해당 부분의 원문과 문맥을 독립적으로 추가 검토한다. 검토 후에도 근거가 부족하면 확인한 내용과 사유를 적고 유보한다.

최종 평가에서 결함이 발견되면 위 수정·재평가 절차를 적용한다. 평가 입력을 바꾼 경우 새 입력을 수집하고 영향 범위를 재평가한 뒤 [평가 보고서](번역_평가_기록.md#보고서-생성과-zip-보존)를 생성한다.
