# 장르·해시태그 작성 지침

책을 웹소설처럼 친근하게 소개해 독자가 읽어볼 책을 고르고, 읽으며 떠오른 반응을 편하게 나누도록 돕는다.
번역 리뷰 후 작품을 근거로 작성하고, **완성된 태그 묶음이 독자에게 자연스럽게 읽히는지** 별도 검토한다.

## 산출물과 규격

- 장르는 자유롭게 작성해 `메타데이터.json.genres` 문자열 배열에 넣는다. 새 산출물에는 1개 이상 필요하며, 작품을 설명하는 데 필요한 장르만 고른다. 예: 로맨스, 비극. 공통 목록이나 임의의 개수 상한은 두지 않는다.
- 해시태그는 같은 파일의 `hashtags` 문자열 배열에 **1~5개, 문구당 최대 10자**로 넣는다. 글자 수는 Unicode 코드 포인트 기준이다.
- `#` 없이 문구만 쓴다. 자동 공백 제거·중복 제거·정렬에 기대지 않고, 작성자가 최종 문구와 순서를 정한다.
- 새 최종 변환에는 두 필드가 모두 필요하다. 공식 변환기는 메타데이터의 값을 그대로 `ingest.json`에 반영하며 메타데이터와 JSON을 ZIP에 보관한다. 업로드에는 기존처럼 JSON 하나와 표지 한 개만 사용한다.

```json
{
  "genres": ["로맨스", "풍자"],
  "hashtags": ["첫인상은함정", "혐관맛집", "말싸움장인"]
}
```

## 표현 기준

- 인물 관계·갈등·소재·분위기·공감 포인트 중 작품을 구별하는 특징을 고른다. 비슷한 뜻만 바꿔 채우거나 최대 개수를 맞추기 위해 태그를 늘리지 않는다.
- 감상·밈·구어체를 적극 활용한다. 다만 읽을 내용을 예상할 수 있어야 하며, 유행어를 붙이는 것 자체를 목표로 삼지 않는다.
- 전체 분위기는 암시할 수 있지만 핵심 반전, 구체적인 결말과 인물의 최종 운명은 드러내지 않는다.
- 고전의 갈등을 현대적인 말로 표현하되 작품에 없는 회귀·빙의·능력·관계·전개를 만들어내지 않는다. 성격이나 관계를 단정하는 표현은 실제 장면으로 뒷받침한다.
- 읽는 데 낯선 은어가 겹치거나, 붙여 쓴 문장이 이해되지 않거나, 해설문을 짧게 잘라 붙인 느낌이면 다시 쓴다. 긴 설명이 필요한 태그는 더 분명한 표현으로 바꾼다.

### 참고한 실제 서비스

- [리디 키워드 검색](https://ridibooks.com/keyword-finder/romance)은 소재·관계·인물·분위기를 구분한다. 실제 키워드의 예는 ‘첫사랑’, ‘라이벌/앙숙’, ‘성장물’이다.
- [노벨피아 작품 상세](https://novelpia.com/novel/233097)에서는 ‘일상’, ‘대학교’, ‘사업’처럼 짧은 특징을 함께 표시한다. [작품 목록](https://novelpia.com/plus/subscription)에서도 소재와 전개를 조합한 태그를 확인할 수 있다.

이는 표현 관행의 참고 자료다. 문장형 밈이 모든 서비스에서 보편적이라는 뜻이나, 우리 태그를 위 목록으로 제한한다는 뜻은 아니다. 참고 페이지의 실제 태그와 아래의 우리 서비스용 예시를 혼동하지 않는다.

### 우리 서비스용 작성 예시

아래는 플랫폼에서 가져온 태그가 아니라 작품 내용을 바탕으로 작성한 예다. 개별 번역본에 적용할 때도 실제 내용과 대조한다.

- **『오만과 편견』:** `첫인상은함정`, `혐관맛집`, `말싸움장인`. 첫인상에서 시작되는 오해와 두 인물의 신경전을 가볍게 전달한다.
- **『변신』:** `벌레가된아침`, `출근이문제가아님`, `가족눈치`. 첫 장의 설정과 일·가족의 긴장을 드러내며 이후 운명을 밝히지 않는다.
- **어색한 예:** `인간존재론적성찰`처럼 해설 제목만 옮기면 책의 구체적인 매력이 잘 드러나지 않는다. `명작`, `필독서`만 나열하면 어떤 경험을 할지 알기 어렵다.
- **내용과 다른 예:** 『변신』에 `먼치킨성장물`을 붙이면 실제 전개와 다른 기대를 준다. 어울리지 않는 인기 키워드를 가져오지 않는다.

## 독립 검토와 업로드

작성자와 다른 검토자가 원문·번역·리뷰를 대조해 다음을 확인하고, 선정 근거와 수정 내역을 리뷰 보고서에 남긴다.

1. 장르 목록이 이 책을 소개하는 데 적절하고, 근거 없는 분류가 섞이지 않았는가?
2. 태그마다 근거가 있고, 태그 묶음이 같은 말의 반복 없이 책의 특징을 전달하는가?
3. 밈·구어체를 포함한 문구를 독자가 그대로 보아도 어색하지 않은가? 혼자 웃기는 표현만 있고 내용 정보가 사라지지 않았는가?
4. 핵심 반전·결말을 공개하거나 작품에 없는 설정을 약속하지 않는가?
5. `#` 없는 1~5개 문구이며 각 10자 이내인가? 순서까지 최종본으로 검토했는가?

수정은 `메타데이터.json`에서 하고 공식 변환을 다시 실행한다. 업로드 담당자는 검토된 메타데이터와 `ingest.json.genres/hashtags`, ZIP 내부 값을 정확히 대조한다. 변환기의 형식 검증 통과를 자연스러움·사실성 검토 완료로 간주하지 않는다.

과거 인제스트와 부분 검증·구형 정규화에서는 두 필드를 선택 값으로 유지한다. 기존 도서의 일괄 생성·보강은 하지 않으며 필요한 책만 관리자에서 개별 수정한다. 관리자 API는 `#`를 검사하거나 자동 보정하지 않는다.
