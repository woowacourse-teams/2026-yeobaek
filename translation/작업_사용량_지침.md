# 작업 사용량 기록

일반 번역·재개 요청에 기본 적용한다. 아래 명령의 실행 주체는 AI다. 사용자가 별도 명령을 입력하거나 개발자 지시를 덧붙일 필요가 없다. 번역이 중단된 상태에서는 계측 준비만으로 번역을 재개하지 않는다. 새 반복 스케줄러는 만들지 않는다.

## 시작과 단계 배정

1. 책 준비·재개 때 `작업_사용량.py init`으로 책과 실행을 등록한다. 동일 작업 재개는 기존 `run_id`를 사용하고, 완성 후 별도 품질 측정은 새 `run_id`로 분리한다. 책의 여러 단계를 조율하는 부모는 `book_control`, 여러 책의 후보 선정·공통 평가기 점검은 `shared`로 배정한다. 공통 비용을 책별 토큰 비율로 나누지 않는다.
2. 단계별 새 세션을 생성하고 실제 로그의 세션 메타데이터와 첫 턴 ID를 확인한 뒤 즉시 `bind --turn-id <확인한첫턴ID>`로 책·실행·단계를 연결한다. 세 단계는 `translation`, `normalization`, `upload`다. 한 세션의 책·단계·실행 배정은 불변이므로 단계마다 별도 실행 세션을 사용한다. 부모에서 상속된 환경 변수의 세션 ID나 추측한 턴 ID로 자식을 등록하지 않는다. 세션 메타데이터와 배정이 확인되지 않으면 미수집 상태와 사유를 남긴다.
3. 한 원실행 세션·턴을 여러 책이나 단계로 다시 귀속하지 않는다. 다른 호스트로 복제한 로그도 원래 식별자를 유지한다. 과거 혼합 턴을 임의로 분할하지 않는다.

아래 예시는 `translation/`에서 실행한다. `<...>`는 AI가 실제 확인한 값으로 바꾼다. Windows에서는 `python3` 대신 `py -3` 또는 확인한 workspace dependency Python을 사용한다. 개인 PC의 Python 절대 경로를 저장소에 고정하지 않는다.

```bash
python3 작업_사용량.py init --book <책폴더> --stage book_control --session-id <실제부모ID> --run-id <실행ID>
python3 작업_사용량.py bind --book <책폴더> --stage translation --session-id <실제자식ID> --turn-id <확인한첫턴ID> --run-id <실행ID> --purpose draft
python3 작업_사용량.py reconcile
python3 작업_사용량.py report --book <책폴더> --run-id <실행ID>
python3 작업_사용량.py probe
```

`--purpose`는 초벌 `draft`, 리뷰 `review`, 교정 `correction`, 준비 `prepare`(기본값), 비교 `comparison`으로 배정 의도를 기록한다. 완료·승인을 증명하는 값은 아니다. `--state-dir`로 원장 위치, `reconcile --logs-root`로 로그 검색 위치를 지정할 수 있다. 기본 원장은 스크립트 옆 `.omc/state/measurement/usage.sqlite3`이며 책별 수집기가 같은 원장을 사용한다. 원장 없이 각각 수집한 합계를 합쳐 전역 중복 제거가 됐다고 주장하지 않는다.

`init`·`bind`는 배정 시각 `bound_at`을 저장한다. `--turn-id`가 없으면 배정 시각보다 먼저 시작한 턴은 제외하므로 기존 긴 세션의 과거 비용을 새 책에 귀속하지 않는다. 새 자식이 이미 첫 턴을 시작했다면 실제 로그에서 확인한 그 턴을 시작 경계로 지정해야 첫 턴이 포함된다. 시작 턴이 확인되지 않으면 추측해 소급하지 않고 누락 사유를 보고한다. 기존 부모의 진행 중 턴도 해당 책 전용 작업임이 확인된 경우에만 실제 턴 ID를 지정한다. `report --run-id`는 해당 실행의 비용·배정 분량·수집 상태를 함께 제한하며 생략하면 같은 책의 모든 실행을 합친다.

## 단계와 수집 시점

- `translation`: 준비, 초벌 번역, 독립 리뷰, 수정·재검증, 최종 결함 평가와 출간본 비교. 실패·중단·폐기·재시도에 사용한 실행도 남긴다.
- `normalization`: 책 소개·장르·해시태그, 표지, 인제스트 변환과 최종 패키지 검증.
- `upload`: 관리자·Drive 업로드, 재시도, 실제 결과 확인과 증거·장부 기록.
- `book_control`: 특정 책의 여러 단계를 조율하는 비용. 세 단계와 별도로 표시하되 책 전체 합계에 포함한다.
- `shared`: 책에 직접 귀속할 수 없는 공통 작업. 책 전체 합계에 분배하지 않는다.

프로젝트 hook은 `SessionStart`, `UserPromptSubmit`, `SubagentStart`, `SubagentStop`, `Stop`, `SessionEnd`에 연결한다. 지원 호스트에서는 입력 이벤트로 로그를 읽고 대조한다. CLI 0.147.0에 없는 `Interrupt` 이벤트는 등록하지 않으며 중단은 실제 `turn_aborted` 기록과 다음 대조로 복구한다. hook 설정 파일의 존재만으로 실제 자동 연결을 검증했다고 하지 않는다. 현재 호스트에서 hook이 동작하지 않으면 AI가 시작·단계 전환·보류·종료·보고 때 같은 `reconcile`과 `report`를 직접 실행한다. 이 경로는 AI 하네스 호출로 표시하며 검증된 hook 실행과 구분한다. 사용자에게 수동 계측을 맡기지 않는다.

CLI 0.147.0의 linked worktree에서는 주 체크아웃의 대응 hook 설정을 읽으므로 새 worktree에만 만든 설정이 로드된다고 가정하지 않는다. 주 체크아웃 또는 일반 체크아웃에서 실제 로드 상태를 확인한다. 같은 설정을 명시한 `hooks/list`에서 6종 선언을 인식하고 Windows 실행 스모크를 통과해도 프로젝트 신뢰·hook 신뢰에 따른 실제 자동 활성화까지 입증한 것은 아니다. 이 호스트의 기본 자동 활성화는 미검증이며 신뢰 설정을 우회하지 않는다. 미활성 상태에서는 위 AI 호출 경로로 수집·대조·보고를 계속한다.

종료 이벤트보다 사용량 기록이 늦으면 pending으로 남기고 다음 이벤트·재개·보고 시 다시 대조한다. 강제 중단은 마지막 관측까지만 보고한다. 과거 자료의 일부 턴만 확인돼도 확인한 비용을 보존하고 누락을 0으로 바꾸지 않는다. 수집 실패가 원문·번역·제품 검증을 우회하는 근거는 아니다.

## 토큰·시간·원문 분량 해석

토큰은 입력, 캐시 입력, 캐시 쓰기, 출력, 추론 출력, 총량과 실제 모델·근거를 구분한다. 캐시 입력은 입력의 일부, 추론 출력은 출력의 일부인 원천에서는 다시 더하지 않는다. 원천에 없는 항목은 미수집과 사유로 남긴다. 모든 턴에서 미수집인 항목은 `null`이며 일부만 관측됐으면 관측한 값의 합계와 `tokenMeasuredTurns`를 함께 확인한다. 역할의 기본 모델명을 실제 실행 모델로 대체하지 않는다.

시간은 실행 구간을 더한 `summedDurationMs`(작업자 누적), 겹친 구간을 한 번만 센 `intervalUnionMs`(활성 경과), 관측한 완료·중단 실행의 첫 시작부터 마지막 종료까지인 `calendarDurationMs`(달력 경과)를 함께 해석한다. 달력 값은 그 관측 구간 사이의 대기를 포함하지만 책 전체 착수 전·마지막 관측 후 대기는 포함하지 않는다. 병렬 작업의 누적 시간과 달력 시간을 혼동하지 않는다. 턴 사이 대기는 활성 시간에 넣지 않는다. 부분 로그로 계산한 시간은 부분 실측이다.

현재 수집기의 원문 범위는 **배정 범위**다. `bind`에 `--original <원문> --source-index <공식색인>`을 주면 변환기의 `parse_source_index`로 원문 바이트 해시와 색인을 검증한다. `--range-start N --range-end N`은 공식 색인과 같은 원문 물리행의 **1-based 양끝 포함**이며 둘 다 생략하면 색인의 전체 본문을 배정한다. 원문 해시별 본문 범위의 합집합으로 중복을 제거한다. 교정·재검수에 새 초벌 배정 범위를 추가하지 않는다.

`sourceVolume.scope=assigned_indexed_body`와 `characters`, `declaredDraftCharacters`, `indexedBodyCharacters`, `coveredLines`는 번역 완료량이나 승인량이 아니다. 문자 수는 모든 유니코드 공백을 제외한다. `declaredDraftCharacters`는 `purpose=draft`의 배정 합집합이다. 공식 색인이 없는 작업의 분량을 추정값으로 채우지 않는다. 현재 수집기는 파일 작성 완료·폐기 여부를 의미적으로 검증하거나 신규 초벌·교정·승인 분량을 자동 구별하지 않는다. 해당 근거를 별도 작업 기록에 남기며, 배정 분량으로 1만 자당 완성 비용·전권 예상·주간 처리량을 확정하지 않는다.

## 출간본 비교와 모델 제공자

책별 탐색·이용조건 확인·구간 대응·익명화·순서 교환 평가·집계를 `translation`에 배정한다. 작업 기록에는 유형, 평가 ID, 실행 ID와 유효·폐기·실패·재시도를 연결한다. 현재 수집기의 턴 종료 상태만으로 판정 유효성이나 폐기 사유까지 자동 분류됐다고 하지 않는다. 공통 평가기 최초 점검·재점검은 `shared`로 분리한다.

익명 평가자에게 책 ID·배정 원장·역자·후보 모델·파일명·대응표·출처를 전달하지 않는다. 배정은 평가 입력 밖에서 실제 실행 ID와 연결하고 hook은 메타데이터를 모델에게 주입하지 않는다. 원장 접근·대화 상속·검색 차단은 실제 환경에서 별도로 검증한다. 수집기가 격리를 제공한다고 가정하지 않는다. 격리가 안 되면 [비교 지침](출간본_비교_지침.md)대로 유보하고 발생 비용은 남긴다.

다른 제공자 사용량은 제공자·계정 범위·실제 모델·단위를 명시한 별도 관측 자료로 남긴다. 현재 Codex 로그 수집으로 다른 제공자까지 자동 수집됐다고 하지 않는다. 토큰·크레딧·주간 한도 단위를 합치지 않는다.

## 주간 한도 UI 관측과 현재 한계

Desktop 26.1111.2228.0 / CLI 0.169.0-alpha.11.1에서 설정 → 사용량 → 분석의 ‘상위 채팅’ 표를 네이티브 접근성(CUA)으로 읽는 경로를 확인했다. 정확한 열 제목은 `주간 한도의 %`이며 `도서 번역 컨트롤러 V2` 행의 표시값은 `35.32%`였다. 이 대화는 여러 책을 조율하므로 이 값을 개별 책에 귀속하지 않는다. UI 관측 경로 확인과 전권 한도 소모 검증은 구분한다.

AI 실행 하네스는 책 시작·체크포인트·종료 때 기존 책 전용 대화의 실제 세션 ID와 정확한 고유 제목을 확인하고 `quota-bind`로 책·실행에 결속한 뒤 CUA로 UI 접근성 텍스트를 수집한다. 새 사용자 소유 대화 생성(`create_thread`)을 필수 절차로 삼지 않는다. 새 대화 생성은 사용자의 명시적 요청이 있을 때만 한다. 부모·자식의 행을 각각 관측해도 합산하지 않는다.

```bash
python3 작업_사용량.py quota-bind --book <책폴더> --run-id <실행ID> --session-id <실제대화ID> --chat-title "<정확한고유대화제목>"
python3 작업_사용량.py quota-import --book <같은책폴더> --run-id <같은실행ID> --session-id <같은대화ID> --snapshot <임시JSON경로>
python3 작업_사용량.py report --book <책폴더> --run-id <실행ID>
```

스냅샷 JSON은 `source: "codex_desktop_accessibility"`, CUA가 실제 반환한 `accessibilityText`, 시간대가 포함된 ISO 시각 `observedAt`을 담으며 `appVersion`은 선택값이다. 숫자를 직접 작성한 자료나 화면의 값을 추측한 자료를 가져오지 않는다. 원시 접근성 텍스트에는 다른 대화 정보가 포함될 수 있으므로 ignored 임시 상태 경로에만 두고 추적 파일·ZIP·완료 보고에 복사하지 않는다. `작업_한도.py`는 결속된 정확한 행과 필요한 관측 메타데이터만 정제해 같은 SQLite 원장에 보존한다.

이 수집은 AI가 CUA로 관측한 뒤 명령으로 가져오는 **AI 실행** 경로다. 프로젝트 hook이 CUA를 직접 호출한다고 가정하지 않는다. hook은 수집된 관측과 로그를 반영한 보고서를 갱신한다. 사용자가 별도 계측 명령을 입력하거나 개발자에게 수집을 요청할 필요는 없다. UI 접근 불가·행 누락·동명 행 등 모호한 경우에는 해당 시도 실패와 구체적 사유를 별도로 보고하고 표시값을 만들어 내지 않는다. 잘못된 스냅샷은 수집기가 거부한다. 유효한 과거 관측이 없으면 `unavailable`이며, 과거 관측이 있으면 원래 관측 시각과 최신성 미확인 상태를 유지한다. 새 수집 실패를 이전 관측의 삭제나 현재값 확인으로 표현하지 않는다.

유효한 관측이 있으면 `status=observed_ui`, `displayedWeeklyPercent`에 UI 표시값을 기록하되, 검증된 책별 소모량인 `percentPoints`는 `null`, 수집 범위는 `incomplete`로 유지한다. 행의 집계 기간·기준 시각, 갱신 지연, 자식 실행 포함 여부와 초기화 간격은 아직 검증되지 않았다. 관측 시각을 집계 기준 시각으로 대체하지 않는다. Desktop 스키마의 `account/usage/read({threadId})`는 실제 부모·자식 모두 `threadUsage:null`이었으며 이는 0이 아니다. 내부 관측·수집 개수는 AI 실행의 계측 자료 수이며 사람의 보고 횟수가 아니다.

계정 사용률 차이·토큰 점유율·부모와 자식의 합계로 책별 소모율을 추정하지 않는다. 표시상 0% 변화도 실소비 0을 뜻하지 않는다. 전권의 귀속·집계 범위를 실제로 검증할 때까지 **책별 주간 한도 자동화 목표는 미충족**이며 PR #366은 Draft로 유지한다. 이 계측 확장은 중단된 번역이나 자동화를 재개하는 지시가 아니다.

## 보고와 보관

완료·보류·중단 보고 전에 AI가 `reconcile` 다음 `report`를 실행해 책별 단계·조율 합계, 모델, 토큰 상세, 세 종류 시간, 배정 원문 범위와 수집 상태·누락 사유를 확인한다. `report` 자체는 새 로그를 대조하지 않는다. `production`은 세 단계 합계, `bookTotal`은 여기에 `book_control`을 더한 책 전체 합계이며 `shared`는 별도다. `tokensByModel`로 실제 모델별 토큰을 확인한다. 측정 기간·실행·평가 범위가 다른 비용 표본을 동일 조건의 권당 평균으로 섞지 않는다.

등록·대조와 배정된 hook 실행은 원장 옆 `reports/<책절대경로SHA256앞16자리>/report.json`·`report.md`를 원자적으로 갱신한다. 기본 위치는 `.omc/state/measurement/reports/`이며 자동 파일은 책의 모든 실행을 합한 요약이다. `report --run-id`의 실행별 JSON은 표준 출력으로 내보내므로 AI가 필요하면 ZIP 밖의 `.omc/artifacts/measurement/` 등에 별도로 보관한다. 요약 경로와 실행 범위를 함께 보고한다. 원시 대화 로그·인증 정보·계정 자료·화면 증거를 ZIP에 넣지 않는다. 업로드 종료 후 최종 사용량을 갱신하며, 이 비용을 ZIP에 넣으려고 다시 압축·업로드하는 순환을 만들지 않는다. 기존 ZIP의 사용량 스냅샷이 있다면 생성 시점의 값임을 명시한다. 업로드 완료와 사용량 수집 범위·미충족 목표를 구분해 보고한다.
